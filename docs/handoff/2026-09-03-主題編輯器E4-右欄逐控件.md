## ② 為什麼這樣改

- 使用者裁定 D79（UI＋功能百分百複製）；100 §3 給右欄結構逐字與 15 型形態；官方 input-settings 頁給各型 default 規則逐字。
- `visible_if` 放前端純函式：66 §A.4——設定一改就要重算可見性，且作用域必含全域 settings（漏了的症狀＝少數欄位永遠不顯示）；
  求值順序照官方 Liquid（由右往左）而非 JS 優先序，V3 兩格鎖住差異。
- 控件庫與面板殼拆檔（`SettingControls.tsx`／`SettingsPanel.tsx`）：佈景設定手風琴與 section／block 面板共用；頁面只提供
  資料與 ops。
- 被推翻的假設：①「checkbox 測試自帶 default 就能殺 M26」——殺不到，改單元測試；②「`label for` 指到按鈕時可及名稱是
  按鈕文字」——實際是 label 文字（ED8 的 image_picker 斷言改用 name=圖片）；③「theme settings 引用用 `\bsettings\.` 即可」
  ——`section.settings.x` 也會命中，改負向後顧；④「一行 python heredoc 可寫 `\b`」——被吃成退格字元（E16 首跑回空），改
  raw 字串／檔案腳本。
- 未採方向：把資源 picker 一併做進本包（E4b／E5：兩欄 popover 形態同 section picker，另包）。
