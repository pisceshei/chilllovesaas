## ② 為什麼這樣改（含被推翻的假設）

### 「換成 HK$」是錯的解法

第一直覺是把 211 處 `NT$` 換成 `HK$`。**這是錯的**，56 號 §513 已經寫過：換成 HK$ 只是把同一個錯誤搬到另一個國家。我們要做全球市場，硬編任何符號都是同一個 bug。

所以 `r_hardcoded_currency` 抓的是**符號字面量本身**，不分幣別。唯一豁免是 `/* CURRENCY-TABLE */`，而且**每檔只准一份**——允許多個等於允許把逃生口撒得到處都是。

最值得記住的形態：**有集中式 formatter 卻仍硬編**。`const NT=n=>'NT$'+…` 看起來已經抽象化了，函式在，但符號長在函式裡。這種最容易在 code review 時被放過。

### 「原型對、契約錯」——方向與以往相反

48 號寫成之後我們才做了 47 號的精確量測，三份原型全部跟上了，契約沒有。契約失真比原型失真更危險：**照契約寫程式的人不會知道自己錯了，因為契約看起來很權威**。

執行者留了一句話值得抄在這裡：47 號的量測散在 §1–§6.5 與 §A–§I，而 §A–§I **不在 §8 修正清單裡**——48 號上一次失真就是只讀了 §8。

### 稅率常數在 HK 下本身就是錯的，不是「顯示 0」的問題

53 號把 P0-17 記成「稅額顯示 0 是錯的資訊」。實際更嚴重：`draftTotals()` 裡有 `Math.round((sub-dsc)*0.05)`——**基準法域是香港，香港沒有銷售稅，這個常數的存在本身就是錯的**，跟空不空車無關。

### lint 規則自己有五個缺陷，是兩位執行者各自獨立回報的

我先寫規則再派工，兩個 agent 在不同檔案上**各自獨立**踩到同一組問題。這種收斂訊號比任何單一回報都可信，所以全部照修並加了自檢：

| 缺陷 | 後果 |
|---|---|
| `data-pack="tw"` 用 `.*?</\1>` 非貪婪 | 遇巢狀同名標籤只吃一半——**三種標記法裡宣稱可用的那一種，對真實 markup 幾乎都失效** |
| `RM` 無詞界 | 誤判 `FORM 2`／`ROOM 3` |
| `統編` 不是 `統一編號` 的子字串 | 寫「統一編號」意思一樣卻完全繞過 |
| 註釋未排除 | 註釋裡引用法規值是**正確且必要的溯源**，卻被逼改寫成「台幣兩萬元」——規則在誘導後人刪掉出處 |
| 只抓前綴串接、只抓 symbol+數字 | 漏後綴 `n+'HK$'`、樣板 `` `HK$${n}` ``、`placeholder="NT$ 最低"` |

還有一個**我自己**踩的：`/* CURRENCY-TABLE */` 標記本身是 JS 區塊註釋，被 `_strip_comments()` 先抹掉，豁免永遠不生效。順序在這裡是語義的一部分。

### 兩處「規格描述本身有誤」

- **53 號 P0-18 的 repro 立不住**（缺口本身是真的）：`lpage()` 第一參數是清單引擎 key 不是路由名；且 `m-customers` 只有 7 筆、per=8，**根本沒有第 2 頁**。全檔唯一多頁的清單是 `m-reports`。
- **N-04 說 16 條假可點列，實際 17 條**（另有 `financePage` 工具卡）＋ 死碼 2 條。

### Chromium UA 對 `:disabled` 套 `opacity:.7`

正是 47 §E 禁止的做法，站內原本沒有覆寫，**lint 只掃我方 CSS 所以掃不到**。這類「瀏覽器預設樣式違反我方規範」的缺口，靜態掃描結構上抓不到，只能靠實跑量測。

## ③ 還有什麼沒解決

### 本輪新產生的（我自己造成的，優先）

- **48 號現在反過來領先原型**：契約已改成「secondary 按鈕靠填色深淺、無邊框」，三份原型仍是白底＋邊框。這是**刻意的**（47 §D 說我們方向不對），但原型還沒跟上。**下一輪不處理的話，下下輪的稽核會把它記成新缺口。**
- **HKD 顯示兩位小數**（`HK$101,930.00`），與 CLAUDE.md 鐵律 10 的示例 `HK$1,480` 不一致。`limits.yml` 已預留這個決策（`hk.currency_format` 註明示例不代表 exponent 為 0）。執行者刻意沒實作 hide-zero-decimals，因為那會讓 HKD 看起來跟 TWD/JPY 一樣、把 exponent 差異藏起來。**需要裁決**：要的話加一個 `hide_zero_minor` 設定即可。

## ④ 下一個人要注意什麼

1. **`python3 scripts/lint-prototype.py` 現在有 14 條規則，ERROR 必須為 0。** 新增的兩條有自檢案例，改規則前先跑一遍：規則自己出錯（誤報／漏報）比沒有規則更糟，因為它會產生虛假的安全感。

2. **要在 pack 標記區外寫幣別符號，答案永遠是「不要」。** 全檔唯一的來源是 `/* CURRENCY-TABLE */`。如果你覺得某處非寫不可，先問「換基準法域時這裡會不會漏改」——`anaCurLabel` 那個「暫時的」`HK$` 就是這樣混進 markup 的。

3. **「移到 pack」不等於「在本 pack 關閉」**（這條從 57 號 H-6 延續，本輪再次驗證有效）。每次搬移，兩邊都要寫。同理，**旗標寫進 `limits.yml` 不代表生效**——一定要回去確認呼叫端真的讀了它。

4. **agent 回報「已完成」要看證據不看宣稱。** 本輪四個 agent 全部附了 headless Chromium 實跑證據，我另外獨立 grep 驗證了每一項關鍵宣稱。53 號抓到過 9 條「宣稱做了但實測不成立」，其中 3 條是主導者自己的。

5. **量焦點環要等 transition 收斂（≥150ms）。** `.btn` 有 `transition:box-shadow`，聚焦後立刻讀 computed style 會拿到動畫 t=0 的透明值——看起來就像「沒有焦點環」。53 號 X-05 的「兩顆按鈕實跑沒有焦點環」**有可能是這個假象**（本輪複測 X-01／N-02／N-03 三條其實都已修好）。

6. **DOCS 不得超前實作。** X-07 的形態在本輪的 P0-07 上再次確認：`service_tier` 只存在於 DOCS 字串、UI 側 0 命中。寫 DOCS 之前先確認控件真的做出來了。

7. **不確定的事實要標「未查證」，不要編。** 本輪 storefront 的 HK 化涉及大量香港事實，執行者把七條假設明確列出來而不是寫得像事實——這是對的做法。有一份待查證登記簿（V-01～V-36）專門收這種項目。

8. **權威順序不變**：官方開發文檔（46a/46b）> 官方商家文檔（46c）> 實測（44/47）> 我方既有規格。衝突一律改我方並留 `<!-- 依 …:行號 修正，原文：… -->`。已修正處加 🔴 防回退註記。
