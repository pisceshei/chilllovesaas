## ② 為什麼這樣改（含被推翻的假設）

- 被推翻：`Get-Service` 沒有結果就代表 MySQL 未啟動。這套環境由手動 launcher 啟動，process、
  listener、ping 與 SQL 才是本次狀態證據。
- 被推翻：原生客戶端的 `-h127.0.0.1` 在 PowerShell 一定原樣傳入。實際錯誤把 host 顯示為
  `127`；改用 `--host=127.0.0.1`／`--port=3306` 後成功，第一次輸出不納入結論。
- 未採：看到受限層的 Zeitwerk／SSPI 失敗就修改 gem 或 `config/database.yml`。`91` §3.5 已有
  同型 A/B 證據；這次本機外層的 Rails Active Record 實連成功，再次證明該失敗不是本輪產品碼
  缺陷。依 17.2 只重驗，不擴修。
