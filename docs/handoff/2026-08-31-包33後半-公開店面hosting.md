# Handoff — 包 33 後半：公開店面 hosting（2026-08-31）

## ① 我改了什麼

六步方案**步 2**：租戶 host 上的公開店面整條——storefront 路由區塊（根 302／前綴查表
／404 判準／robots Disallow／theme-assets）、頁級快取（63 §D.3 key＋§D.5 volatile TTL）、
cart vehicle A1 收口（匿名可用＋限流）＋A2 設定欄＋A3 purge job。消費了包 32 的全部
介面（domains host 解析脈絡、Markets::PrefixIndex、UrlPrefix）。驗證輸出與突變矩陣＝
配對 worklog `docs/worklog/2026-08-31-包33後半-公開店面hosting.md`。specs 全量 1426/0。

## ② 為什麼這樣改

- storefront 不繼承 admin controller 鏈：買家面沒有 staff session／Pundit／瀏覽器門檻，
  塞同一條鏈會把 admin 的閘門語義滲進匿名面（M2 身分閘的教訓反向）。
- 頁快取渲染一律 cart_json=nil：14 §F1-4「個人化不進頁快取」——帶 cart 渲染＝每買家
  一份 HTML，快取即個資外洩窗。買家 cart 態由 /cart.js＋bundled sections 取（不經快取）。
- admin 本來就跑在租戶 host（ApplicationController `return unless Current.shop`）⇒
  A1 只需摘 staff 閘，不需雙載體解析器——被推翻的假設：「cart 需要 staff/host 雙模式」。
- 兩個開發中抓到的真缺陷（GREATEST-NULL 舊快取；主題根內逃逸）見 worklog Done 末節；
  後者連 staff 預覽端點一起封（同 producer 矩陣，17.2）。
