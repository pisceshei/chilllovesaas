## 三、雲端沙箱環境注意 🔴

- **出站可能受 proxy／白名單限制**（2026-08-12 的容器正是這樣：403 CONNECT、`gem install` 不通）。**先實測再排計畫**，不要假設能裝任意依賴。
- **測試以 GitHub Actions CI 為準**：`.github/workflows/ci.yml` 有 MySQL 8.4 service＋RSpec＋前端全套＋schema 漂移檢查。雲端沙箱裡**不必也不要**嘗試自建 MySQL——開 PR 讓 CI 跑。
- 原型 lint：`python scripts/lint-prototype.py`（沙箱一般有 python3，則 `python3` 亦可）——ERROR 必須 0，WARN 基線 13 不得新增。
- 每個 session 是獨立 clone、**做完就 push**（分支＋PR，不直接推 main）——「commit 躺在容器裡」正是本專案發生過的最大事故形態，雲端尤其如此。

## 四、與本地並用的規約

- 兩邊共用同一個 GitHub repo，**以分支隔離**：雲端 session 各開自己的 `m{N}/{功能}` 分支，不與本地在同一分支上交錯 push。
- 上下文同步靠 repo 內的 worklog／handoff（本專案的交接紀律本來就是為「多個接手者」設計的）——不要依賴任何單一機器的本地記憶。
