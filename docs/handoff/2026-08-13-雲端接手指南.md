## 三、雲端沙箱環境注意 🔴

<!-- 依 2026-08-13 官方文檔查證修正（code.claude.com/docs/en/sandbox-environments、cloud-environments），
     原文：「雲端沙箱裡不必也不要嘗試自建 MySQL——開 PR 讓 CI 跑」——成文於查證前的保守假設，已被官方文檔推翻。 -->
- **網路**：Default 環境預設 `Trusted` 等級——**套件庫（rubygems/npm）與 Docker Hub 可通**，其他任意域名擋掉。所以 `bundle install`／`pnpm install` 可以直接跑；要抓別的網站先確認白名單。（2026-08-12 舊容器的 403 經驗＝撞到白名單外的域名，不是全網不通。）
- **測試可以在沙箱裡跑**：Docker 可用 ⇒ `docker run mysql:8.4` 起 DB 後 `bundle exec rspec` 可全綠。**環境加速**：在 claude.ai/code 的環境設定把 setup script 設為 `bash scripts/cloud-setup.sh`（bundle＋pnpm＋docker mysql＋test DB 一次備好，成功後有快取；上限 5 分鐘，腳本是 best-effort 不會擋 session 建立）。
- **合併判準仍是 GitHub Actions CI**（`.github/workflows/ci.yml`：MySQL 8.4 service＋RSpec＋前端＋schema 漂移檢查）——沙箱測試是開發迴圈，CI 綠才算數。
- ⚠ **CLAUDE.md 只在 session 啟動時自動載入，context compaction 後不會重載**（官方已知問題）——長 session 察覺規則變模糊時，主動重讀 CLAUDE.md 與本檔。
- 原型 lint：`python scripts/lint-prototype.py`（沙箱一般有 python3，則 `python3` 亦可）——ERROR 必須 0，WARN 基線 13 不得新增。
- 每個 session 是獨立 clone、**做完就 push**（分支＋PR，不直接推 main）——「commit 躺在容器裡」正是本專案發生過的最大事故形態，雲端尤其如此。

## 四、與本地並用的規約
