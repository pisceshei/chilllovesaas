## ② 為什麼這樣改（含被推翻的假設）

**量測基準錯了兩次，第三次才對。** 先判定是「瀏覽器縮放 150%」，用探針元素驗證後推翻——實際是 Chrome 預設字型設為 24px，**只放大 rem 不放大 px**。這導致第一輪把邊框也除以 1.5，量出 `0.67px` 這種不存在的值。請使用者改回 16px 後才拿到真值。
→ **教訓**：量測前先注入探針（`width:100px; height:1rem; border-top:1px solid`）判定基準，別假設。

**「focus 不是用 outline 畫的」這個結論是錯的。** 那只對 `<s-choice-list>` 一個元件成立；掃全部 437 條 focus 規則後發現系統是 outline(98) 與 box-shadow(96) **並用**。單一元件的觀察不能外推成系統結論。

**Shopify 已改用封閉 shadow DOM**（`s-` 前綴 web components），按鈕與徽章的內部樣式 JS 完全讀不到。改用「CSS transform 放大該元素 + 高倍率截圖」才判讀出 badge 是 ⊘ 斜線圓（48 號原本寫「半圓」是錯的）。

**斷點用 `em` 不是 `px`** —— 這是無障礙設計（使用者調大字型時版面提早切換），也正是量測初期「1024px 視窗卻拿到極窄版」的原因。三份原型已跟進。

**法務邊界的處理方式**：量測數值事實（間距、時長、緩動、狀態轉移）等同拿尺量畫面，可用；Shopify/Polaris 的 CSS 原始碼、變數表、class 名不抄。語意色只取**結構與明度公式**（5 族×5 層×3 態、surface L≈94–97%、hover −2~3、active −4~7），色相用我方自有。唯一例外是 focus 環 `#005bd3`，經使用者裁定採用，理由是它本質為無障礙功能參數（WCAG 只要求 3:1 對比），且**收斂成單一 token 隨時可換**；storefront 維持品牌色。

**降級了一條登記簿條目**：「逾期請款 1.75% 附加費」——官方事實成立但**我方缺口不成立**。1.75% 是 Shopify Payments 作為收單機構的定價；我方依電支條例不代收代付、非收單機構，既不收也無權加收。照抄等於憑空發明收費。

**推翻了七日鑑賞期的處方**：登記簿要求「硬性下限 ≥7 天」，但這會讓合理例外情事商品（易腐敗/客製化/已拆封影音）無法設定，且七日解約權是**獨立於商家規則的法定權利**。改為軟 guard + 法定管道恆存在，明寫 `enforcement: warn` 不得改成 block。

## ④ 下一個人要注意什麼

1. **改原型後一定跑 `python3 scripts/lint-prototype.py`，ERROR 必須為 0。** 最重要的是「同檔頂層函式不得重名」——那次事故（`billingPage` 被覆蓋）造成財務·帳單發票頁整頁消失且形成點擊死循環，**沒有任何錯誤訊息**，是靠稽核才發現的。

2. **agent 回報「已完成」不等於真的完成。** 53 號抓到 9 條「宣稱做了但沒做到」，其中三條是我自己的：focus 環色被同規則內的重複宣告蓋掉、save bar 按鈕的 `box-shadow:none` 特異性壓過 `:focus-visible`、以及上述重名。**驗收要看實跑或 grep 證據，不要看宣稱。**

3. **稽核本身也會量錯。** 49 號說「`sr-only` 三份原型 0 命中」是錯的（storefront 有 `.vh` 與真 skip link）；51 號說 `.card-stack` 已實作也是錯的（5 次全在 `<style>`）。**遇到「宣稱有問題」的條目，先自己驗證一次再動手。**

4. **權威順序**：官方開發文檔(46a/46b) > 官方商家文檔(46c) > 實測(44/47) > 我方既有規格。我方與官方衝突時一律改我方，並留 `<!-- 依 …:行號 修正，原文：… -->` 追溯註釋。**已修正處另留「🔴 任何人翻舊版都不要改回去」防回退註記**——這不是多餘，52 號就發現有條 DOCS 把修正方向寫反（聲稱「四模式是舊文件的錯誤」，實際四模式才是官方值）。

5. **台灣法遵部分沒有 Shopify 出處。** Shopify 不開立台灣統一發票，凡 `TW-*` 與 `einvoice` 區塊都是**我方依台灣法規自訂**，`limits.yml` 內已明寫「46a/46b/46c 不可能是本區塊的來源」。不要去官方文檔找依據，找不到。

6. **上限值一律進 `config/limits.yml` 引鍵名，規格檔不寫死數字。** 原型的 DOCS 實作欄也照此辦理。

7. **量測 Shopify 前先確認基準**：注入探針元素判定根字級與縮放；`elementFromPoint` 要傳 CSS px 而截圖座標是截圖 px（比例 = `innerWidth / 截圖寬度`）；遇 `s-` 前綴元件是封閉 shadow，改用 transform 放大 + 截圖判讀。

8. **PR #11（Codex M0，157 檔 +10,434 行）仍為 Draft**，使用者當時指示「先不管這個」。M0 是否涵蓋本輪新增的規格改動需要重新確認——本輪動了 `11/13/15/16/17/22/28/06/29/38` 十個規格檔。
