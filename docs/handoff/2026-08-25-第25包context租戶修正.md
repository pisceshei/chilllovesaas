# Handoff：第 25 包 context 租戶修正（2026-08-25）

## ① 我改了什麼

PR #125 合併部署後，線上六幕驗收第一幕即 `NoMethodError: undefined method 'id' for nil`
——`Storage::SignedUpload.issue(shop: Current.shop)` 的 `Current.shop` 在 rails runner
下為 nil。改兩支 mutation 用 `context.fetch(:current_shop)`＋新增回歸 spec 兩例。
base＝main `67c55d5`。配對 worklog＝`docs/worklog/2026-08-25-第25包context租戶修正.md`。

## ② 為什麼這樣改

- 倉庫慣例：其餘 9 處 GraphQL 用點全走 `context.fetch(:current_shop)`（product_set、
  collection_set、inventory_*、query_type、schema 的 object_from_id）。`Current` 是
  controller middleware 設的 thread-local——GraphQL 層依賴它等於把「誰呼叫我」寫死成
  「一定是 HTTP controller」。
- 靜態掃描例比行為例更有效：行為例只能覆蓋被想到的呼叫路徑，掃描例覆蓋整個目錄。

## ③ 還有什麼沒解決

- 無。修正範圍恰為兩行＋兩例；#125 其餘部分未動。

## ④ 下一個人要注意什麼

- 新增 mutation／resolver 一律 `context.fetch(:current_shop)`；CI 會擋 `Current.shop`。
- 線上驗收（rails runner 直呼 schema）與 request spec 是**兩條不同路徑**，
  兩邊都要跑——這次就是只有前者能發現。
