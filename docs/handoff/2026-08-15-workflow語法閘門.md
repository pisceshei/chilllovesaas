## ② 為什麼這樣改（含被推翻的假設）

**被推翻的假設：「CI 這麼多道檢查，workflow 本身應該也有人守」。**

實查：**一步都沒有**。而最需要被守的偏偏是 `.github/workflows/claude-review.yml`——
它有一支 240+ 行的閉環 shell，且**動它的 PR 拿不到 Claude 驗收**（反竄改機制）。
該檔註釋自己記載被同型語法錯誤咬過兩次（block scalar 續行、heredoc），
兩次都是「改的時候看起來沒問題，推上去才發現」。

🔴 **保護最少的地方，剛好是風險最高的地方**——而且本輪前面幾個 PR 又往它加了約 50 行 shell。

**一個實作決定值得記**：`wf_clean` 這份反向 fixture **刻意含 `${{ }}` 與 heredoc**。
理由是這兩者都是「檢查器最容易誤報」的形態：`${{` 直接送 bash 是 bad substitution，
heredoc 在 YAML block scalar 裡合法但長得很像縮排錯誤。
⇒ 那一條同時是反向斷言與誤報防護。**反向 fixture 不該只是「一份乾淨的檔」，
它應該是「一份乾淨但最容易被誤判的檔」**——否則它只證明了檢查器不會亂咬簡單的東西。

**另一個決定：誠實聲明寫得比功能還長。**
這不是 actionlint，它抓不到「未知 input 被 GitHub 靜默忽略」那一類——
而那個坑就記載在同一份 workflow 的註釋裡（`with: model:` 在 action v1 無效）。
如果不把這條寫清楚，下一個人會以為「workflow 有 CI 守著」而放心，那比沒有這道閘門更糟。

## ③ 還有什麼沒解決

1. 🔴 **不是 actionlint**：抓不到 action inputs、`${{ }}` 語義、執行期行為。
   要補得引入 `rhysd/actionlint`——新增外部依賴要先討論（鐵律 1），本輪沒做。
2. ⚠️ **`bash -n` 只看語法**。本輪前面抓到的 workflow bug（`core.quotePath`、零掃描、
   jq 濾鏡）**沒有一個**是語法錯誤 ⇒ 這道閘門守的是另一類，不能取代那些檢查。
3. ⚠️ **沒做突變測試**（同 `check-exec-bits.sh` 那輪的缺口）。
   四條 case 是照已知事故設計的，不是打出來的。
4. ⚠️ **同批驗收剩 Y7／Y8**（`claude-review.yml` fallback 的假歸因與 null 垃圾）。

## ④ 下一個人要注意什麼

- 🔴 **改 `.github/workflows/claude-review.yml` 之前，先在本機跑
  `ruby scripts/check-workflow-syntax.rb`。** 那個檔的 PR **拿不到 Claude 驗收**，
  本機這一步是它上線前唯一的機械檢查。`bin/ci` 也會跑它。
- 🔴 **不要把這道閘門當成「workflow 有人守了」**。它只驗語法。
  action input 打錯、`${{ }}` 寫錯、`if:` 條件寫反——全部照樣過。
- **寫反向 fixture 時，讓它「乾淨但最容易被誤判」**，不要只放一份最簡單的檔。
  `wf_clean` 帶 `${{ }}` 與 heredoc 就是這個用意。
