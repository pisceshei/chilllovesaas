## ② 為什麼這樣改

- 把 section 形的 `path: nil` 改成請求路徑，而不是只在 FormTag 補路徑：官方 "render a section in the context of any page" ＋ 實測主選單 current 跟請求頁，
  `linklists`／`request.path`／paginate／tag 連結都是同一個脈絡，補一處就會漏其他三處。
- `return_to` 的 `&` 不轉義是本尊逐字（`value="…&section_id=…&page=2"`），HTML 語義相同但鐵律 22 要逐位元組；只對**預設值**放行、主題明給值照舊 `h()`，
  因為後者本尊形未取得。
- 整頁快取分支不餵原始 query：整頁 HTML 必須是快取鍵的純函數，否則 `?utm_…` 會經 `return_to` 洩進別的請求；Ella 整頁不渲染該表單 ⇒ 本尊整頁形不可觀測，
  登記 V 而非猜。
- `safe_return_to` 改 URI 解析而非放寬成「同站絕對 URL 才收」：本尊對外站 host 也是丟 host 只留路徑（`https://evil.example/x` ⇒ `/x`），open redirect
  防線靠「永遠只用路徑」＋`allow_other_host: false`，比 host 白名單少一個要維護的清單。
- 被推翻的假設：「D80 的 `/localization` 已在 bt3 驗過」——D80 用的是不帶 `_method` 的 curl，真表單（自帶 `_method=put`）從 D80 部署起就 404；
  「Ella JS 不改寫 return_to」——`localization-form.js:170` 改寫成 `window.location.href`。
