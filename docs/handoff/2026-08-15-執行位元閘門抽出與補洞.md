## ② 為什麼這樣改（含被推翻的假設）

**被推翻的假設一：「`-F'\t'` 已經把檔名問題修好了」。**

PR #35 修的是**含空白的檔名**，當時註釋寫「用 TAB 當分隔符才拿得到完整路徑」。
那句話**不完整**：`core.quotePath` 預設 true，含非 ASCII 的路徑會被**加引號並跳脫**成
`"scripts/\346\252\242\346\237\245.rb"`，`-F'\t'` 拿到的仍是那串跳脫字串 ⇒ `head` 開不了
⇒ 靜默漏掉，而閘門照樣印 OK。實測確認舊寫法對 `scripts/檢查.rb`（測試用的假想檔名，僅在該次實測中臨時建立）**零反應**。

⇒ 教訓：**修好一種形態不等於修好那一類**。「路徑取得對不對」有至少兩種破法，
而第一次只解決了看得見的那一種。正解是 `-z`（NUL 分隔、原始未跳脫），
它對**任何**檔名都對——一次解決整類，而不是逐個補。

**被推翻的假設二：「把指令在文件與 CI 兩邊寫成逐字一致，就等於同步了」。**

PR #35 的做法是在 `AGENTS.md` 貼一份與 inline shell 逐字一致的指令。
但 inline shell 有**兩份複製**（test 與 quality job）⇒ 同一段邏輯散在**三處**。
「三處逐字一致」在寫下的當天成立，之後每一次改動都是一次考試。

⇒ **真正的修法是讓它只有一份實作**，其他地方只呼叫。
抽出之後「同步」這個問題本身消失了——不需要任何人記得任何事。
這比本專案先前幾次的處置（寫更醒目的註釋、加一條「必須同步」的規則）都可靠，
因為那些仍然把正確性押在人的記憶上。

**順帶關掉一個我自己登記的缺口。** `scripts/check-ci-parity.rb`（PR #39）的誠實聲明寫著：
「不檢查 inline shell 步驟⋯**這是已知缺口，不是已解決**。要補的話正解是把它抽成
`scripts/check-exec-bits.sh`，那樣它就自動落入規則 1。」
本輪就是照那句做的——**登記缺口時順手寫下正解，下一輪就不用重新想**。

## ④ 下一個人要注意什麼

- 🔴 **不要把判準抄回 `AGENTS.md` 或 `ci.yml`。** 那節現在刻意**不貼指令**，
  只指向 `scripts/check-exec-bits.sh`。抄一份回去就等於把「三處同步」的問題再造出來一次。
- 🔴 **要讀 git 追蹤的路徑，用 `git ls-files -z` ＋ `read -r -d ''`。**
  非 `-z` 的輸出對非 ASCII 路徑會加引號跳脫，任何拿它去開檔的程式碼都會靜默失敗。
  本倉庫目前沒有非 ASCII 的 `bin/`／`scripts/` 檔，所以這個洞從來沒有造成實際損害——
  **但它會在第一個中文檔名出現時發作，而且不會有任何跡象**。
- **改判準時只要改一支腳本**，`ci.yml` 兩個 job 與 `config/ci.rb` 都只是呼叫它。
  改完記得跑 `bash scripts/test-exec-bits-rules.sh`。
- **在 Windows 上 `chmod +x` 不會改到 git mode**，一定要 `git update-index --chmod=+x`。
  這條已寫進 `AGENTS.md`。
