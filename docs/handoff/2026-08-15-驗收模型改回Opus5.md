## ② 為什麼這樣改（含被推翻的假設）

**模型本身**：使用者裁定，不需要理由。我做的是把它記清楚——
這一行在同一天內被改了四次（預設→opus alias→釘完整名→fable-5→opus-5），
只留最後一次的理由會讓下一個人看不出「為什麼會來回改」，於是再繞一圈。
所以四次全列，並明寫 **③（改用 Fable 5）的理由沒有被推翻**——
Fable 5 仍是官方標示的 most capable widely released model，本次是選擇不是糾錯。

**🔴 本輪真正該記的是這個：一個「看起來完全吻合」的解釋差點被我當成原因。**

`claude-review.yml` 裡本來就有一段預言：
「若某天這一行開始報『模型不存在／無權限』…先確認訂閱有沒有 Fable 5，
再考慮回退 `claude-opus-5`。」

而驗收機器人這天確實連續失敗，簽名是 `num_turns:1`、`total_cost_usd:0`、次秒級——
**第一個 API 請求就被拒，零花費**。這與「沒有該模型權限」的預期表現吻合得幾乎完美，
而且使用者剛好要求換模型 ⇒ 很容易寫成「換 Opus 5 順便修好了那個 bug」。

查證後**證偽**：

```
git log -S "claude-fable-5" -- .github/workflows/claude-review.yml
  9fadba9 08-15 00:14 驗收模型改用 claude-fable-5
```

模型自 **00:14** 起就是 fable-5，而 PR #33 的驗收在 **01:41 與 01:54 兩次成功**貼出結論，
失敗是 **01:55 之後**才開始。
⇒ **這只證偽了一條：「從一開始就沒有 Fable 5 權限」。**

     曾經成功只能證明**當時**具備權限，不能證明 01:55 之後 entitlement／OAuth token／
     帳號狀態沒有改變。寫成「不可能是權限」會把下一個人的排障導向錯誤方向。
     🔴 handoff 是 CLAUDE.md 指定「接手先讀」的入口，這裡的斷言比 workflow 註釋更醒目。 -->
⚠️ **01:55 之後才發生的權限或帳號狀態變更，仍然在候選內。**

⇒ 換模型**可能**繞過（不同模型或許不同額度池），但沒有證據保證。已寫進註釋與 worklog。

這與本輪前面幾個教訓是同一件事，只是換了個面孔：
- y/n：把規格當成行為
- §K.7「逐字」：把轉述當成原文
- max-turns 假歸因：把寫死的猜測當成診斷
- **本次：把「吻合的解釋」當成原因**

共同點都是**沒有去查那一步**。查證成本都很低（一行 grep、一行 git log），
而不查的代價是把錯的結論寫進會被別人照做的地方。

## ③ 還有什麼沒解決

1. 🔴 **驗收機器人為什麼失敗，仍然不知道**。已排除：**從一開始就沒有** Fable 5 權限（上面；
   ⚠️ **不包含「01:55 之後才變更的權限／token／帳號狀態」，那一類沒有被排除**）、
   反竄改跳過（PR #33 的 workflow 與 main 逐字相同且 Claude Code 確實 init 了）、
   暫時性抖動（連續兩次 attempt 逐字相同）。剩下最可能是**額度／配額**，
   但 annotation 與 execution log 都只給到 `is_error: true`，沒有錯誤字串。
2. **換模型能否修好，未知**。若換完仍是同一簽名 ⇒ 往帳號側查，不要再換模型。
3. **本 PR 自己不會被驗收**（反竄改機制）⇒ 驗證機會是合併後開的第一個 PR。
4. **Opus 5 有 CLI 版本下限**（v2.1.219+）。我方釘完整名不用 alias ⇒ 不會靜默降級，
   版本過舊會報錯（失效會叫）。action 內建 CLI 版號無從得知，只能等第一次跑。

## ④ 下一個人要注意什麼

- 🔴 **合併後開的第一個 PR 是三件事的共同驗證點**：①本次換的 Opus 5 有沒有跑起來、
  ②PR #36 的失敗診斷會不會貼出真實 result payload、③反竄改機制是否如記載般運作。
  那一輪請特別看 Actions 的 run 時長（正常 3–4 分鐘；十幾秒＝被跳過）。
- 🔴 **驗收失敗時，先看留言裡的 result payload 再歸因。**
  `num_turns:1`＋零花費＝第一個請求被拒；但那**分不出**是暫時性還是持續性，
  判準是「重跑一次」：重跑就過＝暫時；逐字相同＝持續，那時才往帳號側查。
- **想再換模型之前**：先讀那段四次沿革，確認不是又要繞一圈。
  ③的理由（Fable 5 ＝ 官方標示 most capable）至今沒有被推翻。
