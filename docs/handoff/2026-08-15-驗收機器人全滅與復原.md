## ④ 下一個人要注意什麼

🔴 **一、main 的 `claude-review.yml` 一改，所有既有分支立刻失去驗收。**
反竄改比對的是「**PR 分支自己那份** workflow」與**當前預設分支**是否逐字相同。
今天實測到兩次。症狀是 run 只跑 17–24 秒、job 顯示 **success**（不是 failure），
log 裡是 `Skipping action due to workflow validation`。
⇒ **處置：把 main 併進該分支再 push。** 而且動 `claude-review.yml` 的 PR
**永遠無法在自己身上驗證**，要規劃成「先合它、再一次同步所有分支」。

🔴 **二、看到留言寫「零實跑證據 ＋ This command requires approval」就先查 allowlist 語法。**
`Bash(x:*)` **等同** `Bash(x *)`——空格會強制 word boundary。
以 `/` 結尾（停在 token 中間）的前綴**永遠不匹配**，要寫成無空格的 `Bash(ruby scripts/*)`。

🔴 **三、本專案的判準是「破壞那一步本身也要有斷言」，而它今天連續咬了好幾次：**
- 我的 `iconv -c` fallback 寫錯（它回傳 1 ⇒ `||` 把髒資料又接回去），靠斷言才抓到；
- `check-workflow-syntax.rb` 的 canary 第一版放錯位置，**是回歸測試自己抓到的**；
- `check-exec-bits.sh` 的 fixture 在 Windows 全綠、Linux 會紅（`core.filemode`），
  **是驗收抓到的**——而那正是這支閘門存在的理由本身。
⇒ **新增或改動檢查腳本時，一定要故意違反它一次。**

⚠️ **四、數檔案、比路徑一律用 `-z`。** `core.quotePath` 會把含中文的路徑加引號成 `"docs/…`，
`grep '^docs/'` 會漏掉。我在**複驗別人的數字時**又踩了一次。

⚠️ **五、GitHub 的 blob 檢視是虛擬捲動**，只渲染前約 150 行。
「頁面上搜不到」是渲染結果不是事實——要用 `raw.githubusercontent.com` 或 code search。
（差點據此寫下「v1 沒有 `show_full_output` 這個 input」，而它在第 156 行。）

⚠️ **六、合併順序是 `#40 → #39 → #42 → #41`，#38 最後。**
#39／#41／#42 三者**兩兩衝突**（`config/ci.rb`、`ci.yml`），但各自對 main 都乾淨
⇒ GitHub 每個都顯示可自動合併，**先合的沒事、後合的必炸**。衝突全部是 add/add，解法是「兩邊都留」。
🔴 **#39 必須第一**：它的 `check-ci-parity.rb` 會驗證後兩次的衝突解法；
合完每一步要對硬數字（parity 腳本數 10→12→14、run 區塊 25→28→29、exec 掃描檔 25），
**不要只看綠燈**——從 `ci.yml` 單邊掉一步時對等性檢查是抓不到的。
