## ② 為什麼這樣改（含被推翻的假設）

- 使用者裁定：來源語言＝英文、handle 預設英文可自訂、後台先五語、商品先做標題/說明/SEO 三組、形態參考 SHOPLINE 內嵌、語言可自行增刪、C6 語言包由我方翻譯（不接外部機翻）。
- **被推翻 1**：以為多語言要從規格寫起——67 號已有 1,649 行裁定且與新指令幾乎逐條吻合，只需修訂「建立態可否填多語」一條（C1）。**教訓：新需求先 grep 規格再設計。**
- **被推翻 2（線上抓到的真缺口）**：ML-2 的 spec 全綠，但線上改英文標題後其他語言**沒標過期**。成因：admin SPA 宣告式**恆送全樹**（含未編輯的既有譯文），原實作無條件重寫 digest。**教訓：宣告式 API 的測試必須照前端真實 payload 出題**，只測最小輸入會漏掉最常見的組合。
- **被推翻 3**：ML-0 首次 CI 紅——測試庫走 schema load 不跑 migration，種子只在 migration 裡 ⇒ CI 上 `platform_locales` 是空的。改成 `PlatformLocale.seed!` 由 migration／db:seed／spec before(:suite) 三處共用。
