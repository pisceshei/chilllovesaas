## ② 為什麼這樣改

- **排序不塞進 productSet**：工作卡說「排序進 SaveProduct 同 transaction」，
  但媒體的增刪是即時動作（上傳完要立刻看到、刪除有確認框）。若把 media 全量塞進
  productSet 的宣告式輸入，「沒載入 media 就存檔＝清空」的坑會重演
  （collection productIds 的先例）。落法＝拖曳結果進 `values.mediaOrder`，
  儲存時緊接著發一次 `productReorderMedia`——使用者感知是「一起存」，
  語義上是兩個明確的操作。
- **alt 就地編輯（onBlur）而非進 SaveBar**：alt 是媒體的屬性不是商品的；
  而且 alt 權威在 `media` 那一列（同檔掛不同商品可有不同 alt，包 26 已定）。
- **`originalSource`／`fileId` 二選一**：官方契約只有前者，但我方 files 是共用
  檔案庫（包 28 要能挑既有檔）——一次把兩條路開好，28 包只接 UI 不改契約。
