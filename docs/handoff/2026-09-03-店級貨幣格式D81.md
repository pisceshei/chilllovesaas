## ① 我改了什麼

- 目標：使用者裁定 D81「貨幣顯示格式跟隨 shopify 本尊」——前台與 live preview 的金額顯示改由店級
  `shops.money_format`／`money_with_currency_format` 決定（本尊 Settings › General › Change currency formatting），
  移除三處硬編 `HK$` 符號表。輸入 ref：main `3ba1083f`（E9 合併後）；分支 `money/d81-money-format`。
- 做了：migration 兩欄＋回填；`Shop::MoneyFormatDefaults` 種子表（HKD＝真店四欄實讀值）；`ThemeEngine::MoneyFormat` 格式引擎；
  money 族過濾器、Runtime／Notifications registers、ShopDrop 兩欄直出與 `permanent_domain` 改 base_host；鏡像店快照與對齊；
  MF1–MF10 規格；文檔（dev doc、external-facts §G15、91 §3.77、e8 §3／§4、DECISIONS D81 落地註）。
- 遇到的問題：①migration 第一次跑在 `execute` 被 strong_migrations 擋下，但 `add_column` 已生效（MySQL DDL 非交易）⇒ 第二次撞
  Duplicate column；改逐欄 `column_exists?` 守衛＋`safety_assured`。②`unit_price_with_measurement` 仍呼叫已移除的
  `format_money`（LG6 轉紅）⇒ 改走 `money`。③本尊編輯器分頁在背景時側欄停在骨架，Custom Liquid 探針未能執行（見③）。
- 驗證：本機 mirror vs hoko.vip 首頁 18/21 段位元組相同（E8 收尾 17）；餘三段差異片段皆為顧客帳戶 URL／JSON-LD 主機與前綴。
  閘門與突變輸出見 worklog「閘門」段。

## ② 為什麼這樣改

- 證據鏈：官方 help 八佔位符與例值 → 引擎 STYLES 表；filters/money 族官方例 → MF3；真店 admin 四欄實讀 → HKD 種子與 MF4；
  hoko 前台 `$19.99`／`HK$0.00 HKD`／`og:price:amount` 印證三支過濾器在真店格式下的輸出。
- 選案：格式字串原樣存欄、渲染時替換佔位符（不預先格式化）——因 Ella JS 直接吃 `shop.money_format` 字串做前端 formatMoney，
  兩欄必須是本尊形；整數算術避免 float（鐵律 3）。
- 被推翻的假設：E8 時以為 hoko 只有 `money_format = "${{amount}}"` 一個值，實讀 admin 後發現 HTML with currency 是
  `HK${{amount}} HKD`（購物車抽屜 `HK$0.00 HKD` 即此）——兩欄不是「money_format＋幣別碼」的推導關係，必須各自存欄。
- 未採：改 `Money::Display`（admin／PSP 邊界那層）——admin 顯示走 locale 格式器，與前台店級格式是兩件事，不混用。
