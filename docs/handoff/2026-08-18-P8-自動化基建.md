## ② 為什麼這樣改（含被推翻的假設）

- **被推翻的假設①**：「label 不存在時 `--add-label` 會自動建立它」（舊契約註釋）——
  2026-08-18 實測為假：`review:需人工裁定` 從未存在於 repo，add-label 歷輪失敗被
  `|| true` 吞掉，熔斷從未生效（PR #58 的 ⛔ 留言與照常驗收並存即實跡）。教訓：
  這裡的 `|| true` 該吞的只有一種失敗——`gh label create` 在 label 已存在時的報錯；
  `--add-label` 的失敗不在該範圍內（複驗現值：`grep -n '|| true' .github/workflows/claude-review.yml`）。
- **被推翻的假設②**：「`--depth=1` fetch 夠用」——它是為單點 ref 比對設計的，
  套到三點 diff（doc-claims R4/R5）就斷根且**靜默**（warning 後 exit 0）。修法把
  「沒生效」升為結構上可見（exit 3＋fail-loud fetch），並用 G3 釘住。
- **C1 用代理判準而非直讀**：Codex inline thread resolved 狀態 API 拿不到（權限），
  硬讀會做成永假或永真；代理判準（head 錨定＋無建議句）方向 fail-closed——寧可
  多等人工，不誤合併。誠實限制寫進留言文案與 docs/dev §2.2。
