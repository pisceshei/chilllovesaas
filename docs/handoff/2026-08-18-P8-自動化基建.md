### ② 為什麼這樣改（含被推翻的假設）

**被推翻的假設一：「`#` 寫在 YAML 裡就是註釋」。** `claude_args: |` 是**字面塊純量**，
塊內的 `#` 是**字串內容**。這個錯誤在第三、四輪各加了一次，共 22 行，
而它沒出事**純粹因為上游有 `stripShellComments()`**——那是上游對 issue #802 的 bug 修法，
不是 `claude_args` 的輸入契約，而我們把 action 釘在**浮動 tag `@v1`**。
🔴 教訓：**「現在沒出事」與「不會出事」是兩件事，中間隔著一個別人可以隨時改的實作細節。**

**被推翻的假設二：「`set -uo pipefail` 表示這一步沒有 `-e`」。** 這句話寫在檔案裡當作
多處 fail-closed 推理的前提，而它是錯的——GitHub Actions 未指定 `shell:` 時預設 `bash -e`，
`set -uo pipefail` 關不掉已經開著的 `-e`（實測 `$-` ＝ `ehuB`）。
更值得注意的是**同一份檔另一處的註釋是對的**（「避免 && 短路在 set -e 下把整個 job 打死」）
⇒ **兩種互相矛盾的心智模型並存於同一份檔**，而只有錯的那一個被寫成了推理前提。

**被推翻的假設三：「網域白名單照直覺寫就好」。** 差一點寫成 `domain:gnu.org`——
官方明文那**不匹配** `www.gnu.org`（`*.gnu.org` 含子網域但不含 apex）。
而且查證時**實測**到 `docs.anthropic.com` 回 301 → `platform.claude.com`，
偏偏跨 host 重導向**不跟隨** ⇒ 只寫舊網域的話，Anthropic 官方文檔一頁都拿不到。

**被推翻的假設四：「調高 timeout 就能拿到判詞」。** 調高 N 讓 job 不被砍，但**沒有**修好
「真的撞到 N 時 PR 上零留言」——`!cancelled()` 在被取消時求值為假、步驟被跳過。
諷刺的是官方在 `always()` 的 WARNING 裡**推薦**用 `!cancelled()` 取代它，
而本檔正是照官方推薦寫的 ⇒ **不是 workflow 寫錯，是設計假設錯**（以為 timeout 屬 failure）。

### ③ 還有什麼沒解決

- **本 PR 結構上拿不到 Claude 判詞**（改 `claude-review.yml` ⇒ 伺服器端反竄改在換 token 時擋下）。
  已量化：改該檔的 run 全部 3–5 秒收工、拿得到判詞的 3–28 分鐘，雙峰無例外。
- **「被砍時零留言」未修**（見假設四）。方向是給該 step 加 step 級 `timeout-minutes`，
  但「step timeout ⇒ step failure」官方無逐字文檔，採用前必須先實測。
- **內建預核准文檔網域清單官方未公布** ⇒ 白名單外究竟還抓得到什麼，目前無法精確界定。
- **`fetch_state` 單次呼叫仍不受預算約束**（第四輪採契約降級而非實作收緊）。
- **`docs/dev` 沒有新工具能力的條目**、**PR 描述的假設清單與最終註釋不同步**——
  替代審查登記為觀察、未列為缺陷，本輪依鐵律 17.2 未動。

### ④ 下一個人要注意什麼

1. 🔴 **改 `claude_args:` 前先確認你在字面塊裡面還是外面。** 複驗一行就夠：
   用 YAML 解析出該值，**不得出現任何 `#` 開頭的行**。
2. 🔴 **不要在這個 job 裡寫裸的失敗可能命令。** 它是 `bash -e`。留言、API 呼叫這類
   「失敗了也要繼續」的動作一律加 `|| true`；賦值＋`||` 後備則本來就豁免。
3. 🔴 **外部語法先查再寫。** 這一輪如果照直覺寫網域白名單，會得到一個
   **看起來有限制、實際上連自己要用的站都抓不到**的清單。
4. **白名單／閘門類的東西，要同時寫「它擋不住什麼」。** 本輪把兩個缺口
   （內建預核准網域、`--allowedTools` 是免詢問而非限制）明文寫進註釋——
   不寫的話，下一個人會以為封死了。
5. **替代審查不是判詞。** 它由被審的那一方做，不具獨立性；它的價值在留痕與早期發現，
   **不得**用來滿足雙清。這一輪它抓到的三條都是真的，但那不改變它的性質。
