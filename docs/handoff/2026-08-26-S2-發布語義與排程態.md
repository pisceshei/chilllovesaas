## ② 為什麼這樣改

**為什麼只實作 V2 投影**：V1 帶兩個已知誤用源（`isPublished=true` 涵蓋排程態、
`publishDate` 用 epoch 哨兵且型別 `DateTime!` 不可為 null），兩者都是「在非排程態下
100% 測綠」的形態。而 `resourcePublicationsV2` **有** `onlyPublished`（default true）
**和** `catalogType` ⇒ V2 是 V1 的功能超集，只出 V2 沒有缺口。

⚠️ **不得寫「官方建議改用 V2」或「V1 是 legacy」**——官方**沒有這句**。
兩者在 latest 皆無 deprecation 標記，並存逾六年。可以說的只有「官方指南只教 V2」。

**為什麼排程態是強制測試維度**：兩個投影的語義分歧**只在「已排程未到點」這一格顯現**
——已發布時兩邊都 true，完全未發布時 V1 是 false 而 V2 根本沒有這一列。
⇒ 沒有排程 fixture 的測試矩陣會 100% 全綠而實作可以完全做錯。
與鐵律 3 的 zero-decimal 陷阱同型。

**為什麼「到點生效」不做 job**：`published_at <= :at` 已經是查詢時動態判定，
到點那一刻資料庫不需要任何寫入。加一支「掃描 due 的列並 UPDATE」的 job ＝
第二個事實來源 ＝ 鐵律 7 違反。Saleor 走同一條路；Medusa 走反例（cron 翻 status），
缺點正是我方要避開的。

**被推翻的假設**：

| 假設 | 怎麼被推翻 |
|---|---|
| S1 的 `publishedResourceCount` 是對的 | 它完全不看 `published_at`，排程一存在就把排程中算成已發布 |
| 「admin UI 只曝露 active／archived 兩個 catalog 狀態」（S0 寫的） | `82` §12.5 實測：**建立表單**只給兩個，**篩選器三個都給**。原句射程過寬，已就地更正 |
| 逐商品與批次的發布 modal 是同一件事 | `82` §12.2：逐商品**顯示目前狀態**、批次**一律全部未勾**。兩種語義，不得做成同一個元件 |
| Agentic 是一種發布管道（可開關） | `82` §12.4：它是**唯讀的資格審核態**（`Pending` 徽章），沒有 toggle |
| 「variant 不得排程」可以硬編型別名 | 正典鍵是 `future_publishing_unsupported: [variant, ...]`，兩份清單會靜默分岔。改引 limits，且對照用**明確常數表**——`ProductVariant.underscore` 是 `product_variant` 不是 `variant`，靠推導會對不上 |

**重跑方法**：

**紅線**：

1. 🔴 **不要加任何「掃描 due 的 `resource_publications` 並 UPDATE 成已發布」的 job／sweeper**
   ——可見性已由 `published_at <= :at` 動態判定，加了就是第二個事實來源（鐵律 7）。
2. 🔴 **不要把 `isPublished` 改成 V1 語義**（排程也回 true）。有 spec 盯著，理由在型別檔頭。
3. 🔴 **不要把 `published_at IS NULL` 的列放進 V2 的任何 scope**——官方逐字
   `an instance of ResourcePublicationV2 can't be unpublished.`
4. 🔴 **不要在序列化層再寫一次時間比較**。判準的產生處集合＝`grep -n "PUBLISHED_SQL\|def published?" app/models/resource_publication.rb`；
   開第三份會讓「到點」在三個地方各判一次。
5. 🔴 **不要把「到點必須 ACTIVE」加進可見性謂詞**——`purchasable_statuses` 含 UNLISTED，
   加 `= ACTIVE` 會把 UNLISTED 全判不可購（`90` V-2 已裁定過）。
6. 🔴 **不要改 `supports_future_publishing` 的 seed 值**，直到 H-7 的矛盾解掉。
7. 🔴 **不要寫「官方建議改用 V2」「V1 是 legacy」「V2 是 deprecation 過渡」**——
   三句官方都沒說，第三句還已被反證。
8. 🔴 **不要在測試 fixture 或規格寫死 epoch 字面值** `1970-01-01T00:00:00Z`——
   官方只寫 `an epoch timestamp`，確切值未取得。
9. 🔴 **新增排程相關判準時一律引 `config/limits.yml`**，並用**明確的對照常數表**
   ——`underscore` 之類的字串推導會靜默對不上（`ProductVariant` → `product_variant` ≠ `variant`）。
