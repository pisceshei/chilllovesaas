## ② 為什麼這樣改

- 每項修法都對到 hoko 快照／live 或官方逐字（§G17／§G18）；沒有證據的（linklist to_s、link_to_type title、庫存量、most-relevant 語義、Default sort 值域）
  以 V 登記並選最保守的形。
- recommendations 用全域 stub 而非 nil：Ella 印 `{{ recommendations.performed }}`，nil 印空、本尊印 false。
- 篩選字串放 Facets 的語系表而非主題字串：本尊 `filter.label` 是平台翻譯（Ella zh-CN.json 沒有「供貨情況」）。
- 過濾器啟用清單做成 shop 欄位而非 feature_flags：`shops` 既有設定皆為顯式欄位，且 35 §D5 已裁定 `feature_flags` JSON 非權威；設定面（Search & Discovery）
  待做，先給儲存位讓 FA3／FA4 這類「啟用後」行為可測。
- `/collections/all` zh 標題採「产品」推翻 PR-8 的「商品」：兩份 hoko 證據（2026-09-03 快照、2026-09-04 live）＋ `/collections/all.json` 404 證明是虛擬系列
  （非商家自建同名系列）。
- 被推翻的假設：「無序號 `product-apparel-` 佔位名」（探針證明實際是 `collection-apparel-3`）、「`most-relevant` 只在 filter 語境有意義」（admin 實測推翻）。

## ④ 下一個人要注意什麼

- 跑對表：起 server（`CHILLLOVE_BASE_HOST=lvh.me`）→ `render_parity:mirror[mirror]`（冪等，會發布頁面／對齊庫存與 sort_order）→
  `ALLOW_404=1 REF_HOST=hoko.vip CAND_HOST=mirror.lvh.me:3000 CAND_PREFIX=zh-hans-tw bin/rails "render_parity:diff[<快照>,<URL>,<out>]"`。
- 引擎改動後必重啟 server；全套 rspec 前停 server；本包有 migration，test DB 也要 `RAILS_ENV=test bin/rails db:migrate`。
- Normalizer 只抹身分差（id／主機／前綴）；語義差一律修引擎或登記，不得為了變綠加規則（鐵律 22.2）。BLOCK_SCOPE_RE 會把 theme block 前綴差抹掉——
  傳統 block 的裸 key 差只在 `href="#…"` 這類非 wrapper 位置露出，看 diff 時要留意。
- 部署順序：`deploy.sh` → `db:migrate`（production）→ restart puma → `render_parity:mirror[mirror]`（THEME_CHECKSUM 照 D81 做法）→ 公開 diff。
