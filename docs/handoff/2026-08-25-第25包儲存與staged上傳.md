## ② 為什麼這樣改

- **同源 presigned POST**（B6）：實體儲存＝bt3 磁碟（`storage/chilllove/`），
  上傳端點同源 ⇒ 零 CORS 面；nginx `client_max_body_size 32m` > 圖 20MB 上限
  ⇒ image-only 本批穿 puma 可行（1GB 影片被 B9 排除，直傳繞 nginx 的需求
  隨影片包再議）。
- **大小進簽名**：預檢過的 fileSize 被 HMAC 釘住，上傳端點按簽名值再驗——
  「簽小傳大」兩層都過不去（91 §3 F8 的缺口正面收掉）。
- **連線釘選用 `Net::HTTP#ipaddr=`**：只驗 DNS 擋不住 rebinding（12 §B.6 逐字
  警告）；ipaddr= 保留 SNI 與憑證主機名驗證。
- **fs 一律在 DB transaction 之外**（審查後改制；被推翻的初版＝寫檔與 metadata
  同 txn）：檔案系統不參與 rollback，混進去必然在失敗路徑留下 row/blob 不一致。
  順序契約＝寫新 blob → txn → 失敗補償刪新 blob → 成功才刪舊 blob。
- **型別由 magic byte 決定**（審查後新增）：staged 端點只驗簽名與大小、不看內容，
  宣告 mimeType 與副檔名都可偽造。
- **replace 模式保原列 id**：檔案被引用時換內容不換身分，file_usages 不斷鏈。
- **消費者具名化**（name 進投遞帳）：spec 的裸 lambda 全改具名——
  🔴 坑：`define_singleton_method(:call, &block)` 會重綁 self，block 裡的
  rspec let 方法（shop）斷鏈；改存 block 呼叫（relay_spec 檔頭已註）。
