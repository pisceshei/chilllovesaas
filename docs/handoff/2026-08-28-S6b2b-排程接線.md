## ② 為什麼這樣改

**排程不另存狀態**：開一份 `schedule: Map<id, at>` 會產生「schedule 有 id 但 publish 沒有」
的不可能組合，送出去就是一筆沒有目標的排程。本尊也沒有獨立的 schedule mutation
（§15.8 抓包：排程＝帶未來 `publishDate` 的 `publishablePublish`）。

**被推翻的假設**：

1. 我原本以為「有排程」＝`publishDate` 非空。**錯**——每一列都有 `publishDate`，
   已發布的列存的是過去值。正確判準是 `isPublished === false`（V2 的 staged 語義）。
2. 我原本以為排程入口的顯示條件是「目前已發布」。**錯**——§15.10 實測，
   toggle 關掉時 icon 仍在、彈層仍可開。條件是 `supportsFuturePublishing`。
3. 我原本以為 `sameDelta` 比 id 就夠。**錯**——改排程時間會被判成沒變，`Done` 停在 disabled。

**`lockVersion` 那個修法**不是順手擴修，是同一條儲存路徑上的缺陷：
`productSet` 成功後若 publishing mutation 失敗，伺服器版本已遞增而本地沒更新
⇒ 之後每次儲存都撞 `STALE_OBJECT`，永久卡住。本包新增的排程送出正好讓這條路徑更容易失敗。
