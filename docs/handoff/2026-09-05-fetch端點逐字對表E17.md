## ② 為什麼這樣改

- 「動態端點逐字」是 E8／E12 靜態對表之外的另一半：Ella 幾乎所有互動態（抽屜、最近瀏覽、預測搜尋、篩選、快速加購、比較、編輯車）都是
  fetch 回 HTML 再由**同一份主題 JS** 換進 DOM——fetch 回應逐字同形 ⇒ 互動態同形。
- `.js` 端點與 Liquid `product | json` 分成兩個序列化：同日複驗 Ella 商品卡的 `variant | json` 仍是 21 鍵（83 §12.2），而 `.js` 是 22 鍵、url 在 options
  後、無 content；第一版把 drops 的 json 形改掉會破壞集合頁商品卡對位，改成獨立轉換器 `Storefront::ProductAjaxJson`。
- 搜尋序：第一版依 recently-viewed 段的顯示序推成「query 序」——錯；用 main-search 段直接量三組查詢，結果序＝created_at DESC，
  recently-viewed 是主題自己反序。**教訓：量「引擎輸出」要選不經主題二次排序的段。**
- 國旗：本尊 `image_url` 對 country 回 Shopify CDN 圖；鐵律 9 不用本尊圖 ⇒ 路徑形照本尊、圖檔用 MIT flag-icons（同為 640×480 SVG），
  Normalizer 只抹主機。
- 被推翻的假設：「E16 後 fetch 段只差平台功能」——實際 23 對非全同，含 15 條引擎缺口；「recommendations JSON 我方與本尊同形」——本尊回空陣列。
