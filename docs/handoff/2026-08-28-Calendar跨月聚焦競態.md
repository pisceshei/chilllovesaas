## ② 為什麼這樣改

跨月時 `<td key={day}>` 全部換 key ⇒ 被聚焦的舊格被卸載 ⇒ `activeElement` 掉回
`document.body`；而 `handleKeyDown` **逐格掛在 `<td>` 上**、不在 body 的祖先鏈上
⇒ rAF 執行前的窗口內按下的鍵**不經過任何 handler、被整個吞掉**。

`useLayoutEffect` 在 DOM 變更後、繪製前**同步**執行，而 `setRoving` 與 `onCursorChange`
在同一事件裡被 React 批次成一次 render ⇒ 新月份的格子與 ref 都已就位 ⇒ 窗口歸零。

**被推翻的假設**：

1. 我原以為是**日期依賴**（CI 跨日）。**錯**——`Harness` 預設全是字面值，
   `Calendar.tsx` 檔頭明文「本元件不碰 `Date.now()`」。
2. 我原以為是**測試隔離污染**。**錯**——單檔跑也會（用 rAF 推遲配方）。
3. 我原以為 `cell(27).focus()` 沒更新 `roving` 是原因。**錯**——`focusDay` 的 fallback
   本來就是 `today`＝2026-08-27，算出來一樣。
4. 我原以為 C2（連按兩次）用 `userEvent` 就能釘住。**錯**——`userEvent` 每步插一次
   `setTimeout(0)`，Windows 粒度 15.55ms 把窗口撐到 54–97ms，**突變 M-A 殺不掉它**；
   改 `fireEvent` 同步派發才轉紅。

## ③ 還有什麼沒解決

1. **本機無法自然重現**（單檔 10/10、整套 3/3 綠）。要重現一律用 worklog 裡的
   rAF 推遲 400ms 配方。🔴 **不得因為本機綠就判定已修好。**
2. **`!inMonth(roving)` 守衛無測試覆蓋**——兩個突變都殺不掉，因為 `ref` 卸載時已
   `delete(day)` 且對已卸載元素 `focus()` 是 no-op。已在程式碼註釋與 `91` §3.28 W-3 登記。
3. 🔴 **`waitFor` 吸收競態是全倉庫的測試寫法問題**（`91` §3.28 W-1），不只 Calendar。
   要收口需一條通則並掃過所有 `waitFor(...toHaveFocus())`。**本包未做**。
4. **真實瀏覽器的 auto-repeat 間隔未取證**（W-4）：「真實使用者也會踩到」是從機制推得，
   只在 jsdom 量到 16.7ms 幀週期。
5. **CI 上未複驗**：本包推上去前，這個修法只在本機與 rAF 推遲配方下驗過。

- 🔴 **紅線**：**不得把聚焦排回 `requestAnimationFrame`**（或任何非同步排程）。
  這是第二次踩同一個坑——#161 只修了同月那一半。
