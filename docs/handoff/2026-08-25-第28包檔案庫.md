## ② 為什麼這樣改

- **先查官方再動手**（鐵律 16.1），而且**查對了**：原本的設計是「檔案在使用中就
  擋下刪除」，官方文檔明說相反——刪檔會自動解除引用**並補位**。如果照原設計做，
  會做出一個本尊沒有的錯誤碼、少做一個本尊有的副作用，兩邊都要在對齊輪回頭改。
  錯誤碼也一樣：自創的 `FILE_IS_PROCESSING` 在官方值域裡不存在，對應的是 `FILE_LOCKED`。
- **staged 清掃不查 DB 只看時間**：staged key 與永久 key 是兩個命名空間，
  `fileCreate` 從不把 staged key 寫進 `files` ⇒ 拿 DB 比對「有沒有被取用」會得到
  恆空的結果，也就是一個**永遠刪 0 個**的清掃。那種檢查看起來像有在守、實際沒有，
  比不做更糟。判準改成純時間，並加寬限窗（簽名過期那一刻 `fileCreate` 可能正在
  讀那份 bytes）。
- **補位的入口開在 MediaSync 而不是 FileWrite 自己寫**：補位必須走兩階段落位
  （`uq_media_product_id_position` 是 unique），那個知識屬於 MediaSync。
  複製一份到 FileWrite 就是第二個會撞 1062 的地方。
- **`usageCount` 走相關子查詢**：檔案庫列表 50 列逐列 COUNT ＝ 50 條查詢。
  但**不是第二套計數**——算式與 model 的 `usage_count` 逐字同義，單筆路徑仍回落它。
- **被推翻的假設**：①「in-use 應該擋刪」（官方相反）②「alt 我方與本尊一致」
  （本尊是檔案層單一值，我方是 per-product——這是真分歧，見 §③）
  ③「staged 清掃可以比對 DB」（命名空間不同，比不到）。

## ③ 還有什麼沒解決

- 🔴 **alt 分層與本尊不同，等使用者裁定**（`91` §3.10）。本尊：alt 在檔案層、
  只有一份，Files 頁改了會影響所有用到該檔的商品。我方（第 26／27 包裁定）：
  alt 權威在 `media` 那一列，同檔掛不同商品可各有 alt。本包**維持我方裁定**、
  把檔案層 alt 定義成「新掛載的預設值」，並登記為 V。
  🔴 研究方明說 propagation 那一句是 **schema 推論不是官方逐字** ⇒ 依鐵律 19
  不得當已證外部事實發布。複驗方法＝測試店把同一檔掛兩個商品、從 Content › Files
  改 alt、再讀兩個商品的 media alt。
- **線上驗收未做**（合併部署後）：上傳→列表→改 alt→刪一個引用中的檔→驗商品媒體
  補位→跑一次 `Storage::StagedPurge` 看實際清掉幾個（bt3 上第 27 包驗收後留了
  20 個 staged 目錄，正好是現成的樣本）。
- 分頁只有第一頁、排序固定 `created_at desc`、選檔器內不能上傳、`used_in` 值域
  比本尊窄——四條都登記在 worklog Pending，都不在本包射程。
- 附錄 A 名單背離（`91` §3.9）仍未收口；本包同樣只補自己兩份。

## ④ 下一個人要注意什麼

- 🔴 **動 `Storage::FileWrite.delete` 之前先讀它的檔頭②**。那裡有兩件事是官方語義
  不是我方選擇：刪引用中的檔不報錯、刪完要補位。把它改成「擋下來」＝退回對齊輪。
- 🔴 **`Storage::StagedPurge` 的判準不要「改成更聰明的」**。任何「比對 DB 看有沒有
  被取用」的版本都是永遠刪 0 個（見 §②）。要動它先讀 `spec/services/storage/
  staged_purge_spec.rb` 的五例——那五例同時證明會刪與不會誤刪，只證明「腳本能跑」
  不算防線。
- **`FilePickerModal` 的 props 介面改動要先對齊整合規格 §1.7**（Modal 原語同紀律）：
  第 29 包變體子頁的圖格會是第二個消費者。
- **第 29 包入場件**：變體子頁組裝（麵包屑／變體間導航／左欄清單＋pill／選項值／
  價格／per-location 庫存／運送四卡／變體圖）。複用**不改語義**是紅線（§1.1）——
  `InventoryAdjustPopover` 與媒體 tile 都是共用元件，改它們的語義會同時影響
  列表頁與商品頁。
- 媒體線（24→31→25→26→27→28）到此收口，只剩 31（TLS）卡在使用者那邊
  ——需要把 vhost 貼到 192.168.31.187，或把 bt3 的公鑰加進該機的 authorized_keys。
