## ② 為什麼這樣改

- **`?v=` 不是單一時間戳**：hoko 同主題所有資產後 10 位相同、前段每檔不同、compiled 另一時間戳 ⇒ 前段＝每檔摘要、後段＝產生時的主題版本秒；E19a 的 compiled `?v={updated_at}` 是
  10 位形、與本尊 29 位形不同，本包一併改。演算法未公開 ⇒ 只對形不對值（Normalizer 抹）。
- **主機含埠**：`request.host` 無埠，本機 `mirror.lvh.me:3000` 的協定相對 URL 會打到 80 埠；新增 `asset_host`（`request.host_with_port`）而不改 `host` register
  （`request.host`／`__st.pageurl`／`Shopify.shop` 都靠無埠 host）。
- **任一主題 id 可供給**：hoko `/cdn/shop/t/1/assets/base.css` 200 ⇒ 非發布主題以 id 取得是本尊行為；我方以租戶內 `Theme.find_by(id:)` 供給，預覽／編輯器不再需要 `asset_base` 特殊路徑。
- **1 年快取安全**：URL 含主題 id 與 `?v=`（版本秒），主題檔寫入必 `theme.touch`（theme_file_upsert／delete 既有）⇒ 值旋轉；故供給端照 hoko 出 `max-age=31557600`。
- **被推翻的假設**：①「`1.year` ＝ 31557600」——Rails 是 31556952（365.2425 天），hoko 是 365.25 天 ⇒ 顯式常量。②「Rails 能逐字輸出 `public, max-age=…`」——`expires_in`
  會重排成 `max-age=…, public`，語義同、位元組不同（91 記）。③「fixture layout 有 asset_url 可當整頁探針」——minimal-1.0 layout 沒有 ⇒ 另建 `product.t12.json`＋探針 section。
- **未採方向**：把 FontFiles 放進 asset_urls.rb（Zeitwerk 以檔名找常量 ⇒ `uninitialized constant`，拆檔）；以 `belongs_to :theme, touch: true` 旋轉版本（upsert／delete 已 touch，重複）。
