## ① 我改了什麼

**目標**：本尊的變體詳情頁 `/products/{pid}/variants/{vid}`——左欄變體切換清單、
主欄選項值／媒體／定價／庫存／運送五張卡。形態來源＝
`docs/research/93-product-flows-live-walkthrough.md` §2。

**輸入**：`main` head 起點見 `git merge-base main HEAD`。前置包 18（庫存調整列）、
20（變體 CRUD）、23（選項與變體表）、27（媒體卡）皆已在 main。

**遇到的問題與證據**：

1. **這包不是純組裝**。排程假設三塊 UI 都已存在＝可直接拼，實際盤點後三樣讀取面
   缺席：全地點庫存（形狀與 `inventoryItems(locationId:)` 不同，硬套會逼出每地點
   一次查詢）、運送兩欄（schema 有欄、GraphQL 沒面）、變體圖。
2. **`productSet` 是宣告式全量**。子頁只編一列，但送出必須整份回送，否則其餘變體
   被刪、未送欄位回落預設。這決定了整包的架構：payload builder 必須與商品頁共用。
3. **rebase 撞 D48**（alt 權威搬到 `stored_files`）。`ProductVariantType#image` 原本
   `Presenter.new(file:, alt: row.alt_text)`，D48 把 `Presenter` 收成單成員後**直接
   ArgumentError**——那正是把它做成型別守衛的用意。另一處是 spec 的 alt fixture。

**重要動作**：
- 後端：`ProductVariantType` +4 欄；新 `VariantInventoryLevelType`；
  `ProductSetVariantInput` +2 欄；四條寫入路徑（`VariantSync` ×2、`SaveProduct` ×2）；

- 前端：`VariantDetailPage`（新）、`VariantImageSlot`／`Breadcrumb`／`MediaThumb`（新）、

  並補運送回聲欄、`App.tsx` +1 路由、i18n ×5 各 +24 鍵、CSS。
- 測試：`spec/requests/variant_subpage_surface_spec.rb`（6 例）、
  `VariantDetailPage.test.tsx`（7 例）。

**對抗式審查（本輪最重要的一段）**：先 commit 凍結受審樹（`91` §3.12 的固定處理），

## ② 為什麼這樣改

**共用 builder 而不是各寫一份**：症狀不對稱——各寫一份時兩邊測試都會綠，但在 A 頁
存檔會抹掉 B 頁設好的值，而且沒有錯誤訊息。運送兩欄是最新一組回聲欄，也是最隱蔽的
一組（重量預設 0、requiresShipping 預設 true，回落後看起來像「使用者本來就沒填」）。

**`MediaThumb` 只抽呈現層**：媒體卡的 tile 帶拖曳重排與精選標記；變體只有一格
（`max_images_per_variant`＝1），那兩個語義在這裡不存在。整個 tile 搬過去等於把拖曳
帶進一個不能拖的地方——這正是 §1.1「複用不改語義」要防的。

**上傳完直接掛給變體**：`uploadProductMedia` 改成回傳 `mediaId`。使用者在變體圖格按
上傳，意圖就是要它當變體圖，再要求從檔案庫選一次是多餘的。

**庫存卡唯讀**：D43「庫存唯一入口＝`Inventory::Adjust`」。庫存是 append-only 稽核帳，
把數量塞進 `productSet` 會讓一筆調整沒有 ledger 列。

**重量用公克整數**：與金額同紀律（內部整數、顯示層才換算）。收浮點公斤會在 0.1 kg
上得到 100.00000000000001 g。

**被推翻的假設**：
- 「第 29 包只做組裝」——見上①。
- 「`inventoryItems(locationId:)` 夠用」——形狀不同，見上①。
- 「只補 `VariantSync` 兩條路徑就行」——單變體商品走的是 `SaveProduct` 的隱式變體
  路徑，而單變體是絕大多數商品。四條都要補。

## ③ 還有什麼沒解決

- **線上驗收未做**（合併部署後才能做）。歷史上線上驗收四次抓到本地測試抓不到的缺陷
  （#126 `Current.shop` nil、#128 `fail_on` 掛錯層、#131 衍生檔空目錄外洩、
  #133 EXPLAIN filesort），**它是獨立防線不是複測**。
- **v1 缺口三項**：①頁首「複製」與「更多動作▾→刪除子類」未做——刪除有
  `Catalog::DeleteVariant`（第 20 包）可接，複製沒有對應服務；②左欄「銷售管道▾」
  篩選 pill 需要 publication 讀取面（第 12 包）；③變體 metafields 屬 M2 射程。
- **`SaveProduct` 的 `description_html` 語義改了，射程超出本包**：更新態現在是
  「缺席／顯式 null＝保持現值、空字串＝清除」。商品頁一律送該欄 ⇒ 行為不變；
  受影響的是**不送該欄的 API 直呼叫**（以前被清空、現在保值）。這是修法的重點而不是
  副作用，但下一個改這支服務的人要知道它與 `status`／`vendor`／`tags`／`seo` 現在同語義。
- **`ProductDetailPage` 在 overflow 時鎖了整頁，卻留著可點的變體連結**
  （`fieldset[disabled]` 不 disable `<a>`）。子頁已自己補上封鎖 ⇒ 不再造成刪除；
  但那個入口本身是商品頁的瑕疵，屬第 23 包射程，只登記不順手改（鐵律 20.5）。

## ④ 下一個人要注意什麼

- **入口**：`app/frontend/admin/pages/VariantDetailPage.tsx` 檔頭寫了三條紅線
  （整份回送／庫存不走 productSet／共用元件不改語義）。改這頁前先讀它。
- **前置**：`buildVariantsPayload` 現在有兩個消費者。**加欄位時兩個查詢都要補**——
  只補一邊的症狀是「在另一頁存檔把這個欄位清掉」，而兩邊的測試都會綠。
  複驗＝`git grep -n buildVariantsPayload app/frontend`。
- **重跑方法**：`bundle exec rspec`／`pnpm test`／`pnpm exec tsc --noEmit`／
  `bundle exec rubocop`／`ruby scripts/check-doc-claims.rb --base origin/main --require-base`。
- 🔴 **紅線**：庫存不得經 `productSet`（D43）；變體圖的 alt 屬於 `StoredFile` 不屬於
  媒體列（D48，`ImageType::Presenter` 是型別守衛，照舊寫法會 ArgumentError）；
  CSS 只用 `tokens.css` 已定義的 token。
- 🔴 **`Card` 沒有 `title` prop**。寫 `<Card title={...}>` 不會報錯——它被展開到
  `<section>` 變成原生 tooltip 屬性，標題在畫面上根本不存在，而測試若沒斷言標題就全綠。
  卡片標題一律 `<Card padded><h3>…</h3>`（`.cl-product-detail .cl-card h3` 有樣式）。
- 🔴 **`fetch(key, default)` 擋不住 GraphQL 的顯式 null**。nullable 的 scalar argument
  在 key 存在時會把 nil 寫進 `to_h`，default 不生效。要回落預設一律顯式判 `.nil?`
  （`SaveProduct#boolean_or`）。這一條對所有 `null: false` 的欄位都成立。
- 🔴 **源碼裡不要出現裸 NUL**。本輪一個字串分隔字元誤打成字面 NUL，git 立刻把整個
  `.tsx` 判成 binary（grep 回「Binary file matches」、diff 不可讀）。
  要複合鍵就用 `JSON.stringify`，不要自造分隔字元。
- **不得外推**：本包只碰變體讀寫與子頁。變體的建立／刪除／批次編輯在第 20/23 包，
  庫存調整在第 18 包——那些的既有問題只登記 `91` §3，不在本包順手改（鐵律 20.5）。
- **停止條件**：審查零未清 ∧ 全部正典閘門綠 ∧ CI `quality`＋`test` 綠 ⇒ squash 合併
  ⇒ 部署 bt3 ⇒ 線上驗收。線上驗收發現缺陷 ⇒ 另開修復包，不回改本 PR。
