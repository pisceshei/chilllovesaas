## 第一步：把倉庫還原出來

我的 `C:\Users\pisce\Downloads\shopifysystem` 資料夾裡有一個 `chilllovesaas-full.bundle`（5.5 MB，完整 git 歷史，67 個 commit，branch = main）。請把它 clone 成一個可用的 git 倉庫：

```
git clone chilllovesaas-full.bundle chilllovesaas
```

**clone 到別的資料夾名字**（例如 `chilllovesaas`），不要蓋掉 `shopifysystem` 那份——那是沒有 `.git` 的散檔複本。clone 完先跑 `git log --oneline | head -5`，HEAD 應該是 `08dd260`。

## 我的工作規則（硬性，不是選配）

- **每次工作結束前一律寫交接文件**：`docs/handoff/YYYY-MM-DD-<主題>.md`，四段固定（①我改了什麼 ②為什麼這樣改，含被推翻的假設 ③還有什麼沒解決 ④下一個人要注意什麼），**和該次改動一起 commit**。
- **改過原型就跑 `python3 scripts/lint-prototype.py`**，ERROR 必須為 0。
- **不要用「應該可以」交差**。要嘛實際跑起來給我看證據，要嘛老實說「這個環境做不到」。前一輪有好幾條結論是被實測推翻的，我要的是這種誠實。
- **來源分級**：`src`（原始碼）>`std`/`google`（標準）>`help`/`dev`（Shopify 官方文檔）>`alt`（競品官方）>`press`（第三方）>`blog`。**`press` 級只能「登記為未知」，不足以翻面一條已生效的預設**——前一輪違反這條，同一條規格一天內改了兩次。
- 規格沒寫到的才問我；寫到的自己去讀。

## 環境注意事項

- 前一輪容器出站被 proxy 以 403 CONNECT 擋掉大部分主機，`gem install` 與 `gh` 不可用。**要做任何抓網頁／裝套件的事，先確認出站權限再排計畫**，不要做到一半才發現不通。
- `Shopify/liquid` gem **沒有 `handleize`**，「讀官方原始碼推 handle 演算法」這條路永久不通，已掛帳。

先做第一步和第二步，讀完之後跟我說「你理解到的專案現況是什麼、你認為下一步該做什麼」，**先不要動手改任何東西**，等我確認。
