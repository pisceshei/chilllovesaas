## ② 為什麼這樣改（含被推翻的假設）

**被推翻的假設一：「YAML 的 on/off 陷阱是值的事」。**
所有人都知道 `enabled: on` 會變布林，但沒人預期**同一條規則適用於鍵**。
`{ on: gift_card_issued_by_admin }` 讀起來完全正常，實際鍵是 `true`。
這是它能活到現在的原因——它不是打錯字，是**看起來對的東西**。

**被推翻的假設二：「載入時會炸，所以會被發現」。**
不會。`deep_symbolize_keys` 對非字串鍵**原樣保留**（`true` 不能 `to_sym`），
載入一路綠燈，錯誤延到取值端才變成 `KeyError: key not found: :on`。
🔴 **KeyError 的訊息完全看不出根因是 YAML 1.1** ⇒ 撞到的人手上只有「這個鍵不存在」，
而檔案裡明明寫著 `on:`。這種落差正是誤修的溫床。

**為什麼加引號、而不是改用 `true` 當鍵**：後者能讓 `fetch(true)` 通過，是最省事的「修法」，
也正是我判斷實作者最可能採取的路徑。但它把 bug 固化成契約——**鍵名從此不是它在檔案裡看起來的樣子**，
下一個讀 limits.yml 的人會再被騙一次。所以腳本的錯誤訊息裡明文寫了「不要改成用 true 當鍵」。

**為什麼要 CI，而不是「知道了就好」**：這一類缺陷只在**鍵名剛好是那幾個字**時出現，
寫的人與 review 的人都不會特地去想。它符合本專案反覆出現的判準——
**靠肉眼守不住的不變量必須機制化**（同 `check-tenant-isolation.rb` / `check-reversal-naming.rb` 的理由）。

**兩個實作選擇，都是為了「機制不要比它守的東西更脆弱」**：
- 走 **Psych AST** 而非 load 出來的 Hash ⇒ 報得出**確切行號**（Hash 只剩值，報不出位置）。
- 判定用 `key_node.to_ruby` 的**實際型別**，不自己重寫一份 YAML 1.1 字表。
  檔內那張字表**只用於產生提示文字**——表漏了哪個字並不會讓違規逃掉。
  副作用是順手擋住 `off/no/true/false`（含 `On`/`YES` 這類大小寫變體）、`~/null`、`2026-08-15`（→ Date）等同類鍵，
  三種已實測判得出來。

**兩處中途修正（都值得記，因為它們是同一種錯）**：

1. 腳本與 YAML 註釋初稿都寫成「`Limits.fetch(..., :M27, :on)` 會 KeyError」——
   **這個倉庫裡根本沒有 `Limits` 模組**（實際存取是 `Rails.configuration.x.limits`，
   grep 確認只有 3 個 call site）。我自己在提交前抓到，已改成真實存取路徑。

2. 🔴 **初稿宣稱裸字 `y`/`n` 會被轉布林——這是錯的**，由 PR #33 的兩個驗收方
   （Claude bot 與 Codex）**各自獨立**指出。複驗（Ruby 3.4.10 / Psych 5.2.2）：
   `YAML.load("y: 1\nn: 2\nY: 3\nN: 4").keys` → `["y", "n", "Y", "N"]`，全是 String。
   YAML 1.1 **規格**的 bool 全集確實含 y/n，**Psych 5 的實作不轉**——我把規格當成了行為。
   判定邏輯沒事（它比對型別不比對字面，y/n 鍵本來就正確放行），壞的是**錯誤訊息與文檔**：
   鍵解析成 TrueClass 時字面只可能是 on/yes/true 的變體，訊息裡的 `y` 永遠是假訊息，
   而 §④ 更把它寫成給下一個人的操作規則。

🔴 **這兩處合起來是本輪最該記的教訓**：一個以「註釋↔行為矛盾掃描」為起點的 PR，
自己在註釋裡放了兩個與行為不符的斷言。**寫機制的人不會自動免疫於該機制要防的錯誤**——
差別只在第 1 個我自己抓到、第 2 個要靠外部驗收方。
⇒ 對外宣稱的規則性斷言（尤其會被下一個人當操作規則照做的那種）
**一律當場跑一行複驗**，並比照專案慣例標註取證環境與日期。

順帶在複驗時補到初稿也漏掉的一件事：**大小寫變體會轉**（`Off`→FalseClass、`TRUE`→TrueClass）。

**第 3 輪：兩個假設同時過期。**

1. 🔴 **「這個倉庫沒有 `Limits` 模組」過期了**。main 合入 PR #29 後
   `app/models/limits.rb` 存在，`Limits.fetch(*path)` 就是使用者最初報告時寫的那個 API。
   ⇒ 第 2 輪那次「修正」在當時是對的，現在要**改回去**。
   教訓：**對倉庫現況的斷言有保鮮期**，尤其在多 PR 並行時；引用一個 API 之前先 grep 一次。
2. 🔴 **「既有 `check-*.rb` 都沒有回歸測試，比照辦理」過期了**。
   同一次合併帶進 `scripts/test-money-rules.rb`，而 65 §K.7 逐字寫「只有前者綠不算交付」。
   ⇒ 補上。**理由會過期，過期就要重判**，不能因為當初寫過就一直援引。

還有一個同形的教訓，是我自己的工具犯的：監看 CI 的腳本第一版只依 **branch** 過濾，
而上一輪的 run 早已 completed ⇒ 它在 `等待 0s` 就回報了**上一輪的舊結果**，
run ID 與前一次逐字相同。真實情況是**這一輪根本沒有觸發任何 run**（PR 衝突 ⇒ 建不出 merge ref）。
🔴 這與本 PR 的主題是同一件事：**綠燈來自一個沒真正驗到目標的檢查**。
已改為依 `head_sha` 過濾並要求 ≥2 個 run。

## ③ 還有什麼沒解決

0. 🔴 **ERB 是「擋下來」不是「檢查過了」**（驗收後補的閘門）。loader 走
   `ActiveSupport::ConfigurationFile.parse`，它**先 render ERB 再解析 YAML**，
   本腳本讀原始檔 ⇒ 兩邊輸入不同。已實測 `<%= "on" %>: v` 在原始檔的 AST 裡是合法 String 鍵，
   但真 loader 產出 `[true]`——**不擋就是 CI 綠燈而 runtime KeyError**，機制形同虛設。
   `limits.yml` 目前零個 ERB，所以選擇 fail-closed 而不是跟著 render（跟著 render 會失去行號）。
   日後真要用 ERB，**先擴充腳本，不要拿掉閘門**。

1. **只管鍵，不管值**（腳本檔頭有誠實聲明）。值寫成裸 `on` 而意圖是字串會出同一種錯，
   但機械判定會大量誤報 ⇒ 仍靠 review 與 spec。
2. ✅ **已解決（第 3 輪）**：`scripts/test-limits-key-rules.rb` ＋ 三份 fixture，已掛 CI。
   原本判為「比照既有兩支 `check-*.rb` 不補」，但 main 合入 PR #29 後
   `scripts/test-money-rules.rb` 立了慣例（65 §K.7：**只有前者綠不算交付**）⇒ 理由過期，改判。
   meta 驗證做過：把判定改壞成 `if false` 後，checker 對乾淨倉庫**仍 exit 0**，
   而回歸測試 exit 1 抓到。
3. **只納管 `config/limits.yml`**，其他 config YAML（如 `brand.yml`，同樣走 symbolize）未納管。
4. **沒有檢討 `on` 這個鍵名本身**該不該叫 `on`——那是規格決定，我沒有代為改名。
5. ⚠️ **`y`/`n` 的結論綁在 Psych 版本上**（Ruby 3.4.10 / Psych 5.2.2，2026-08-15 取證）。
   那是**實作行為**不是規格保證（規格反而含 y/n）。升級 Psych 時要重驗字表與各處敘述。

## ④ 下一個人要注意什麼

- 🔴 **在 limits.yml 新增鍵時，鍵名若是 `on/off/yes/no/true/false/null/~`（含 `On`/`YES` 這類大小寫變體）
  或看起來像日期，一律加引號。** 忘了也沒關係——CI 的 `Check limits.yml key types` 會擋下來，
  訊息裡直接給行號與修法。
  ⚠️ **`y`/`n` 不在此列**：YAML 1.1 規格含它們，但 Psych 5.2.2 實測不轉（Ruby 3.4.10，2026-08-15 取證），
  裸字 `y:` 的鍵就是字串 `"y"`。本檔初稿把它們寫進來過，是錯的，見 §② 末段。
- 🔴 **CI 擋下你時，不要改成用 `true`／`false`／`nil` 當鍵。** 那能讓測試變綠，
  但會把「鍵名不等於它看起來的樣子」寫進契約。正解永遠是加引號。
- **實作禮品卡會計（M27–M32）的人**：`gift_card_entry_points` 現在可以正常
  `dig(..., :M27).fetch(:on)` 了。如果你是在本次之前寫的代碼、且為了繞過 KeyError
  做了任何 workaround（用 `true` 當鍵、改用 `[]` 吞 nil、硬編事件名），**回頭清掉**。
- **要擴大納管範圍**：`scripts/check-limits-keys.rb` 的 `TARGETS` 加一行路徑即可，邏輯不用動。
- **要補回歸測試**：比照 `scripts/test-lint-rules.py` 的形態，
  準備一份「已知有違規」的 fixture YAML 斷言 exit 1。本輪的手動反向測試做法寫在 worklog，可直接沿用。
