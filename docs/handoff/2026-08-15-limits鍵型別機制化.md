## ② 為什麼這樣改（含被推翻的假設）

**被推翻的假設一：「YAML 的 on/off 陷阱是值的事」。**
所有人都知道 `enabled: on` 會變布林，但沒人預期**同一條規則適用於鍵**。
`{ on: gift_card_issued_by_admin }` 讀起來完全正常，實際鍵是 `true`。
這是它能活到現在的原因——它不是打錯字，是**看起來對的東西**。

**被推翻的假設二：「載入時會炸，所以會被發現」。**
不會。`deep_symbolize_keys` 對非字串鍵**原樣保留**（`true` 不能 `to_sym`），
載入一路綠燈，錯誤延到取值端才變成 `KeyError: key not found: :on`。
🔴 **KeyError 的訊息完全看不出根因是 YAML 1.1** ⇒ 撞到的人手上只有「這個鍵不存在」，
而檔案裡明明寫著 `on:`。這種落差正是誤修的溫床。

**為什麼加引號、而不是改用 `true` 當鍵**：後者能讓 `fetch(true)` 通過，是最省事的「修法」，
也正是我判斷實作者最可能採取的路徑。但它把 bug 固化成契約——**鍵名從此不是它在檔案裡看起來的樣子**，
下一個讀 limits.yml 的人會再被騙一次。所以腳本的錯誤訊息裡明文寫了「不要改成用 true 當鍵」。

**為什麼要 CI，而不是「知道了就好」**：這一類缺陷只在**鍵名剛好是那幾個字**時出現，
寫的人與 review 的人都不會特地去想。它符合本專案反覆出現的判準——
**靠肉眼守不住的不變量必須機制化**（同 `check-tenant-isolation.rb` / `check-reversal-naming.rb` 的理由）。

**兩個實作選擇，都是為了「機制不要比它守的東西更脆弱」**：
- 走 **Psych AST** 而非 load 出來的 Hash ⇒ 報得出**確切行號**（Hash 只剩值，報不出位置）。
- 判定用 `key_node.to_ruby` 的**實際型別**，不自己重寫一份 YAML 1.1 字表。
  檔內那張字表**只用於產生提示文字**——表漏了哪個字並不會讓違規逃掉。
  副作用是順手擋住 `off/no/y/n`、`~/null`、`2026-08-15`（→ Date）等同類鍵，
  三種已實測判得出來。

**一處中途修正（值得記）**：腳本與 YAML 註釋初稿都寫成
「`Limits.fetch(..., :M27, :on)` 會 KeyError」——**這個倉庫裡根本沒有 `Limits` 模組**
（實際存取是 `Rails.configuration.x.limits`，grep 確認只有 3 個 call site）。
本輪的起點就是「註釋↔行為矛盾掃描」，註釋自己指向一個不存在的 API 會很諷刺，已改成真實的存取路徑。

## ③ 還有什麼沒解決

1. **只管鍵，不管值**（腳本檔頭有誠實聲明）。值寫成裸 `on` 而意圖是字串會出同一種錯，
   但機械判定會大量誤報 ⇒ 仍靠 review 與 spec。
2. **腳本沒有自己的回歸測試**。反向測試是本輪**手動**跑的（鏡像目錄 ＋ 修前版檔），
   沒固化。判定邏輯被改壞（例如 `is_a?(String)` 寫反）時 CI 會靜默放行。
3. **只納管 `config/limits.yml`**，其他 config YAML（如 `brand.yml`，同樣走 symbolize）未納管。
4. **沒有檢討 `on` 這個鍵名本身**該不該叫 `on`——那是規格決定，我沒有代為改名。

## ④ 下一個人要注意什麼

- 🔴 **在 limits.yml 新增鍵時，鍵名若是 `on/off/yes/no/y/n/true/false/null/~` 或看起來像日期，一律加引號。**
  忘了也沒關係——CI 的 `Check limits.yml key types` 會擋下來，訊息裡直接給行號與修法。
- 🔴 **CI 擋下你時，不要改成用 `true`／`false`／`nil` 當鍵。** 那能讓測試變綠，
  但會把「鍵名不等於它看起來的樣子」寫進契約。正解永遠是加引號。
- **實作禮品卡會計（M27–M32）的人**：`gift_card_entry_points` 現在可以正常
  `dig(..., :M27).fetch(:on)` 了。如果你是在本次之前寫的代碼、且為了繞過 KeyError
  做了任何 workaround（用 `true` 當鍵、改用 `[]` 吞 nil、硬編事件名），**回頭清掉**。
- **要擴大納管範圍**：`scripts/check-limits-keys.rb` 的 `TARGETS` 加一行路徑即可，邏輯不用動。
- **要補回歸測試**：比照 `scripts/test-lint-rules.py` 的形態，
  準備一份「已知有違規」的 fixture YAML 斷言 exit 1。本輪的手動反向測試做法寫在 worklog，可直接沿用。
