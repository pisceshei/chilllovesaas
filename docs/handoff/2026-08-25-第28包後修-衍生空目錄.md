# Handoff：第 28 包後修——衍生空目錄（2026-08-25）

## ① 我改了什麼

第 28 包合併部署後的線上驗收發現：`fileDelete` 刪掉衍生檔但留下空目錄。
base＝main `ea5e980`。修法＝新增 `Storage::LocalDisk.delete_with_empty_parents`，
並把三個同型呼叫點（`FileWrite.delete` 一處、`ProcessFile` 兩處補償刪除）改走它。
配對 worklog＝`docs/worklog/2026-08-25-第28包後修-衍生空目錄.md`（含 bt3 實測數字）。
驗證：rspec 587/587、rubocop 0 offense。

## ② 為什麼這樣改

- **這是線上驗收才看得到的一類缺陷**（本專案第三次）：單元測試每個 example
  各自建檔各自清，空目錄累積要跨很多次刪除才顯形；線上是同一個資料夾一直用下去。
  前兩次是 #126（`Current.shop` 在 rails runner 為 nil）與 #128（`fail_on` 下錯層）。
- **用 `Dir.rmdir` 的 ENOTEMPTY 當停止條件**，不自己判斷「還有沒有別人在用」：
  自己判斷就要先 list 再刪，中間有競態；`rmdir` 是原子的，非空就失敗，天然安全。
- **射程取「同一個孤兒目錄產生者」的完整集合**而不是只改被抓到的那一行
  （鐵律 20.5）：`ProcessFile` 的兩處補償刪除寫在同一種 key 底下，會留同一種空目錄。
- **原圖 blob 刻意不 prune**：`shops/{id}/files/` 是共用層，收掉下次上傳還要重建。
- **被推翻的假設**：「`rm_f` 刪檔就乾淨了」——對扁平目錄成立，對每檔一棵樹的
  衍生結構不成立。

## ③ 還有什麼沒解決

- **既有 17 個空目錄不追溯清理**：修產生端不修既有。它們無害（空目錄、無資料），
  同 file_id 重產衍生時會重用。刻意不寫一次性刪目錄腳本——那種腳本路徑打錯的風險
  高於它解決的問題。複驗：`find storage/chilllove/shops/*/derivatives -type d -empty | wc -l`
- **只涵蓋本地磁碟後端**：換物件儲存後「空目錄」概念不存在，本支會變 no-op。
- 第 28 包 worklog 的 Pending 諸條仍然有效（alt 分歧待裁定、分頁只有第一頁、
  排序固定、選檔器內不能上傳、`used_in` 值域比本尊窄）。

## ④ 下一個人要注意什麼

- 🔴 **新增任何寫進 `derivatives/` 的路徑時，刪除端要用 `delete_with_empty_parents`**。
  判準很簡單：key 裡有沒有「每個資源自己一層」的段（`{file_id}`／`{checksum}`）——
  有就要 prune，沒有（像 `files/`）就不要。
- **`delete` 與 `delete_with_empty_parents` 是兩支、語義不同，不要合併**。
  `spec/services/storage/local_disk_spec.rb` 最後一例就是釘住「舊 `delete` 保持原行為」
  ——合併掉會讓共用層的目錄在最後一個檔被刪時消失，下次上傳多一次 mkdir。
- 媒體線（24→31→25→26→27→28）到此收口。下一包＝29（變體子頁），
  它會複用媒體 tile 與 `FilePickerModal`，**複用不改語義**是紅線（整合規格 §1.1）。
