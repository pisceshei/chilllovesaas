## ② 為什麼這樣改（含被推翻的假設）

- 🔴 **「唯讀」也會判錯方向**：我先依實測把幣別改成純唯讀（BUG1 初版修法），help 隨後證明存在
  「管理→切換帳單幣別」對話框——只是**選項集由公司所在國家/地區決定**，HK 恰好單選項所以實測
  看不到按鈕。教訓：**單一商店的實測會把「條件性控件」誤判成「不存在」，help 是條件枚舉的來源**。
  最終修法＝唯讀＋DOCS 記條件（73 §7.5）。
- 🔴 **導航子項是狀態函數**：本店財務無子項→我登記 STRUCT1「本尊無子項」；help 明文「財務 > 支付款項」
  ——未啟收款＝無、啟用＝有。與 Cookie 橫幅「依市場需求顯示」同構。**對照導航樹時必須帶商店狀態**。
- **CSS 研究的紅線劃法**：73 §5 記的是量測值（事實），§5.3 是「量測值→我方 token」映射；本尊的
  inset-bevel 主鈕明確標記「不複製」（鐵律 9），交互等價物＝我方 .btn-pri。之後每輪 CSS 研究照這個
  三段式（token 表/元件量測/映射）。
- **平台金融產品邊界（G15）落地形**：Balance/Capital/Bill Pay/帳戶卡四總額＝登記不建；撥款排程/
  匯出餘額交易＝PSP pack 對應面（做 UI、資料源標 PSP）；帳單=平台自己的（全做）。三層分法寫進 73 §7.2-7.3。
- critic agent 回 null——workflow 的 agent() 錯誤即 null 不拋錯，**返回值要判空**；缺口自查補登，
  但下次 critic 這種單點 agent 應加重試或雙 agent。
