## ② 為什麼這樣改（含被推翻的假設）

- 🔴 **R0 初稿誤判被工作流推翻**：拿 M0 React shell 當對比對象把成長/內容/財務標成「整區缺失」——原型 full 版
  其實都有。教訓固化：**先建我方側地圖再標缺口**（71 §B.1 追溯註釋）。

  ≠ 商店設定**，URL query 化是判準。
- 🔴 **campaign 概念錯位**：原型把 activity 層（內容製作）壓進 campaign 層（歸因容器）——「同名不同物」形態。
- 🔴 **R0-MISS2 的教訓**：「API 相關需求搜尋結果」看名字像獨立功能，點開才知是釘選對話——**登記缺口前先點開**。
- 測試店授權（使用者明示可寫入）讓 teardown 深一級：建立→捨棄 campaign 草稿抓到完整建立流。
- palette 靜態 HTML 誤寫模板字串、CH 資料 HK$ 字面量違鐵律 10——都被自己/lint 當場抓住，證明防線有效。
