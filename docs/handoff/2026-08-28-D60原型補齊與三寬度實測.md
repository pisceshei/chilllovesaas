## ③ 還有什麼沒解決

1. 🔴 **390 的 `h1` 是 17.94 不是 18**，成因是既有規則
   `@media (max-width:47.9975em){ h1{font-size:clamp(17px,4.6vw,20px)} }`（390×4.6vw = 17.94）。
   **那條規則對不對＝未取得**：本尊有 mobile 覆蓋機制（`--p-when-mobile`，閘門是
   `@media (pointer: coarse) and (max-width: 47.9975em)`，**比我方多一個 `pointer: coarse`**），
   但**本尊 `display-small` 在該閘門下是否縮小、縮到多少未取得**。本輪不動它。
2. ⚠️ **三寬度只驗了原型首頁**。其他頁未逐頁驗；`.od-grid`／`.vd-grid` 的收合是用
   **隔離探針**驗的（臨界點精確落在 752 ✅），不是頁面實況。
3. ⚠️ **未驗實作端（Rails app）**。兩邊值都指向同一組 token，應該一致——但那是推論不是量測。
4. ⚠️ **側欄在 768／390 是 272px**，本尊窄版形態未對照（本尊 767 以下側欄寬 0）。
5. 🔴 **未截圖**。截圖需要 Claude Code 的 Browser pane 顯示，而使用者要求一律用本地 Chrome。
   本輪證據是 DOM 稽核（機器可判定、可重跑）。

## ④ 下一個人要注意什麼

- 🔴 **所有實測一律用本地 Chrome，不用內嵌瀏覽器**（使用者 2026-08-28 明示）。
  內嵌瀏覽器的行動模擬會扭曲值：`html` 回報 **14px 而掃遍樣式表沒有任何規則設它**、
  `devicePixelRatio` 回報 **2.0000000596**、`innerWidth` 與 `clientWidth` 差 4px
  （我第一版稽核就因此誤報 4 個「溢出」）。
- 🔴 **`resize_window` 在本地 Chrome 回報成功但不生效**（`screenX=0` 也一樣）。
  取三寬度的方法是**同源 iframe**：把頁面載進指定寬度的 iframe，
  media 與 container query 都按 iframe 寬度求值。**要標明這是隔離重現，不是實際視口。**
- 🔴 **MCP 回傳的鍵名含 `token` 會被安全過濾器吞成 `[BLOCKED: Sensitive key]`，而且不報錯**
  ——很容易誤以為量到空值。改鍵名即可（本輪 `tokenT450` → `v450`）。
- 🔴 **量字重前先停用 `#font-bolder-style`，父頁與 iframe 都要停**，量畢還原並複驗
  （本輪複驗 `disabled: false`、body 回到 500）。
- ✅ **批次改檔的固定處理**：「錨定字串 ＋ `assert count == 1` ＋ **全部驗過才動手**」。
  本輪批次驗證擋下兩次：`.nav-group` 的 pattern 命中 3 次（另兩處是 `.pal-group`／`.zone-sub`）、
  `.pill`／`.toast`／`.avatar` 命中 0 次（宣告順序與假設不同）。兩次都整批不做、修正後才套用
  ——那正是 D59 偏移漂移 bug 的解。
