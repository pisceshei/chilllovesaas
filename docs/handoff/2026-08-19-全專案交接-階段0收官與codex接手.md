  而 R-9 要 teardown 的功能全在**傳統版**（`shoplineapp.com`）。
- Codex[3]（#58 r40）的第二案「撤回禁行號判準」方向錯——`91` §3 已自登「禁行號是對的、`91` 該改」。

而本專案的很多選擇是**裁定**不是機械修復。這正是 2026-08-15 廢止「自動 @codex 派修」的理由，
**不得回退**。

### 2.2 被推翻的假設：`${{ }}` 寫在 `prompt:` 裡是安全的

第 5 輪在 `prompt:` 塊裡加了 `${{ github.event.pull_request.number }}`。
**整份 workflow 從此無法解析**——一個 YAML 純量若含 `${{ }}`，**整個純量成為單一 template
expression**，而 Actions 對單一 expression 有 **21000 字元上限**。超過即整檔失效 ⇒
`pull_request` 觸發器**不再啟動**，症狀是「CI 全綠、Claude Review 消失」。

本機所有檢查（`ruby -ryaml`、`bash -n`、`@action-validator/cli`）**全過**——**只有 GitHub 判得出來**。
用 8 個丟棄分支二分定位，修法＝改走 step 層 `env: PR_NUMBER`、prompt 內用 `$PR_NUMBER`。

> **接手輪查證補記（2026-08-19；不改寫上方事故紀錄）**：GitHub 官方 `actions/runner`
> 固定 commit `258d6c8` 的 `TemplateReader.cs` 對含 expression 的字串逐字註解
> “Break the value into segments of LiteralToken and ExpressionToken”，混合 literal／expression 後再
> “Build the new expression, using the format function”，最後回傳單一 `BasicExpressionToken`；
> `ExpressionConstants.cs` 逐字為 `internal static readonly Int32 MaxLength = 21000;`；
> `ExpressionParser.cs` 逐字判斷 `if (Expression.Length > ExpressionConstants.MaxLength)` 後拋出
> `ParseExceptionKind.ExceededMaxLength`。來源：
> <https://github.com/actions/runner/blob/258d6c857db3519913f7deb6004b60172f8043ae/src/Sdk/DTObjectTemplating/ObjectTemplating/TemplateReader.cs#L503-L619>、
> <https://github.com/actions/runner/blob/258d6c857db3519913f7deb6004b60172f8043ae/src/Sdk/Expressions/ExpressionConstants.cs#L29-L35>、
> <https://github.com/actions/runner/blob/258d6c857db3519913f7deb6004b60172f8043ae/src/Sdk/Expressions/ExpressionParser.cs#L440-L446>。
> 這三段支持「混合純量會組成單一 format expression，parser 上限 21,000」；「該次 workflow
> 整檔失效、pull_request 未觸發」則是本倉 #60 的 GitHub 實測結果，不冒充官方通則，
> `eec1cfa` 尚未進 main；接手環境要先執行
> `git fetch -f origin tag pr60-last-push`，再用
> `git show eec1cfa -- .github/workflows/claude-review.yml` 重看修復差異。
> 2026-08-19 複驗：`git merge-base --is-ancestor eec1cfa pr60-last-push` 回 0，證明該固定
> commit 可由這個已指定抓取的 tag 取得。

### 2.3 被推翻的假設：15.2「重拉留言」＝看最後一則

條文原文是「最新時刻的**每一則**」。第 7 輪我只看了最後一則，於是 review `4969100476`
（審 `32708a9`）**整整躺了兩輪**——複驗後兩條意見**都成立**。

⚠️ 附帶查到的工具陷阱：`gh api .../pulls/{N}/comments` **不加 `--paginate` 只回前 100 則**。
本 PR 的 inline 留言早已超過 100 ⇒ 不分頁會「查不到最新那批」而**誤判成 Codex 沒給 inline**。

### 2.4 被推翻的假設：`claude_args: |` 裡的 `#` 是註釋

那是**字面塊純量**，塊內的 `#` 是**字串內容**。22 行「註釋」實際是 prompt 的一部分，
沒出事純粹因為上游有 `stripShellComments()`——那是上游對 issue #802 的 bug 修法，
不是 `claude_args` 的輸入契約，而我們把 action 釘在**浮動 tag `@v1`**。

### 2.5 被推翻的假設：`set -uo pipefail` 表示這一步沒有 `-e`

GitHub Actions 未指定 `shell:` 時預設 `bash -e`，`set -uo pipefail` **關不掉**已經開著的 `-e`
（實測 `$-` ＝ `ehuB`）。同一份檔另一處的註釋是對的 ⇒ **兩種互斥的心智模型並存於同一份檔**，
而只有錯的那一個被寫成了推理前提。

### 3.5 兩個結構性問題

**① #60 在條文上不可能雙清。** 它改 `.github/workflows/claude-review.yml`。

**已查證的部分**（`anthropics/claude-code-action`，取證 2026-08-19）：
- `src/github/token.ts` 定義 `WORKFLOW_VALIDATION_ERROR_CODES = new Set(["workflow_not_found_on_default_branch"])`
  與 `WorkflowValidationSkipError`；判別**靠伺服器端在 app-token 交換時回的 error code**，
  不是本地檔案比對。<https://github.com/anthropics/claude-code-action/blob/main/src/github/token.ts>
- `src/entrypoints/run.ts` 捕捉它之後**逐字是**：`core.setOutput("skipped_due_to_workflow_validation_mismatch", "true")`
  ＋`console.log("Exiting due to workflow validation skip")` ＋ **`return`**——
  **沒有 `setFailed()`、沒有 rethrow** ⇒ **步驟成功、零判詞**。
  <https://github.com/anthropics/claude-code-action/blob/main/src/entrypoints/run.ts>

**〔推論〕的部分**：伺服器**用什麼判準**判定 mismatch（我先前寫「逐位元組相同」）——
客戶端原始碼看不到，Anthropic 也未公布該端點的比對規則。⇒ **只能說「執行中的 workflow
與預設分支版本不一致時會被判 mismatch」**，不得寫成逐位元組。

> 🔴 **接手輪更正（2026-08-19；原文保留但不再代表已證事實）**：上句「Anthropic 也未公布」
> 是無法由一次搜尋證成的外部全稱句。已證範圍只到 Anthropic 官方 client 固定 commit
