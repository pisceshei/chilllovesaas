## ② 為什麼這樣改

- **manual 先行、PSP 不動**：15-F4.2 使用者裁定＝付款方式是 PSP capability 查詢結果、
  manual 不經 capability（F4.2(d)）；測試店無 PSP ⇒ 本包唯一可實測、可落地的付款
  集合＝manual 四型（86 §3 DOM 逐字）。開源對照（Medusa MIT `pp_system`／Solidus
  BSD-3 `PaymentMethod::Check`）同構支持「離線付款＝一等方法、不開 if 分支」。
- **快照含 payment_instructions**：86 §3 官方 helper 逐字——instructions 顯示在
  「下單後確認頁」；訂單成立時商家可能已改文案 ⇒ 選定當下定格（同 shipping_lines 紀律）。
- **duties_included 必須顯式 false**：Ella 四分支 `== false` 顯式比較（fixture 實
  grep），Liquid `nil == false` 為假——這是「miss-nil 碰巧安全」哲學的反例，W1 直接
  寫 Ella 分支形釘死。
- **試算 price＝字串**：86 §6 官方回應形逐字 `"price":"6.00"`——十進位主單位字串屬
  序列化層（鐵律 3 邊界），divmod 轉換與 Seo::JsonLd 同紀律。
- **被推翻的假設**：①「配送三分法 Ship/Pickup/Local delivery 單一切換器」——官方研
  究證實是 Ship/Pick up 二元＋Local delivery 作為 Shipping 區塊選項（研究筆記 §5c，
  spec 15-F3.1(a) 的三分法屬資料層不屬 UI 切換器）；②「cart 試算 API 已棄用」——官方
  現行頁三支健在，同步支只是「不建議」非 deprecated（兩者不得混寫）。
