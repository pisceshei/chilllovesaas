## ② 為什麼這樣改（含被推翻的假設）

- 「digest 從 DB pluck 就夠」被推翻：`assoc.build` 的列與已編輯未存的列都不在 DB，
  兩層靜默資料遺失。背後是三個 Rails 邊界（詳見 docs/dev「驗收輪修正」節）：
  預設 has_many 不存髒的持久化子物件；未載入關聯 `.first` 回脫離物件；
  `build` 不標 `loaded?`。
- 「`Integer()` 當防呆」被推翻：`Integer(1.9)==1` 是截斷不是拒絕——與檔頭 @raise
  宣稱矛盾。兜底層對輸入必須嚴格。
- 「索引夠用」被推翻：`restrict_with_error` 的 `shop_id+option_value_id` 反查，
  三支既有索引都只能吃 shop 前綴；migration 註釋還宣稱已涵蓋（不實），一併修。

## ④ 下一個人要注意什麼

- 🔴 **schema.rb 重生**：本機空 DB 時 Rails 8 `db:migrate` 會直接載 schema.rb
  跳過 migration（runner 也會經 maintain_test_schema 載入）。要真跑 migration：
  暫移 schema.rb → drop → create → migrate → 比對 dump diff（本輪恰好一行新索引）。
- 🔴 讀變體座標的記憶體狀態一律走 `effective_option_value_pairs`，不要自己 pluck——
  否則兩層遺失會以新形態回歸。
- `insert_all`／`upsert_all` 繞過 callback，但 digest 欄 `null: false` 無 default
  會大聲失敗——這是刻意的，不要補 default。
