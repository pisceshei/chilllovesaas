| 2. 有沒有做到一半的分支？ | `git branch -a --sort=-committerdate \| head` 與 `git status` | 有 `m2/*` 分支且不等於 main ⇒ 有半成品，看下面「半成品分支怎麼續」 |

### 半成品分支怎麼續（本節最重要）

工作包的狀態全部可以從磁碟推出來，不需要對話記錄：

1. **看分支上有沒有 commit**：`git log --oneline origin/main..HEAD`
   - 空的 ⇒ 還沒 commit，工作樹裡就是全部成果。`git status` 看改了哪些檔，`git diff` 看內容。
   - 有 ⇒ 已經凍結過一次，看 commit message 判斷做到哪。
2. **看 worklog**：`docs/worklog/` 下該包那一份。**閘門段還寫著「（凍結 tree 後填。）」＝閘門還沒跑完或還沒填**；
   有閘門表但沒有突變表 ⇒ 卡在突變那一步。
3. **看閘門 log**：`tail -3 <scratchpad>/gates_e8b.log`。有 `SUMMARY` 且 28 支全 `exit=0` ⇒ 閘門通過過一次；
   但**只要之後又改過任何檔就作廢**（鐵律 15.4），要重跑。
4. **看 scratchpad 該包目錄**：`ls <scratchpad>/t*/`。每個包都留了 `patch_*.py`（補丁）、`mutate_*.py`（突變）、
   `fill_*.py`（填表）、`finish_*.py`（提交鏈 driver）、`bt3_deploy_*.sh`、`verify_bt3_*.sh`。**直接重跑這些腳本就能續**，
   它們都是逐步 check 的，失敗會停在原地並印出原因。
5. **資料庫可能半套用**：`bin/rails db:migrate:status | grep down`。migration 檔改過表名之類的情況下，
   MySQL 的 DDL 不會回滾，可能出現「欄位已建但 migration 沒記錄」——這時先手動 `remove_column` 清乾淨再重跑
   （2026-09-05 T14 就踩到：`add_column :stored_files`／實際表名是 `files`，前三個欄位已建、第四個失敗）。

### 背景 Workflow 中斷了怎麼辦

2026-09-05 的 `real-store-full-audit`（run `wf_e62960e6-03a`）跑了兩輪都因額度用盡中止：第一輪 23/33 完成，
resume 之後只剩 12/33（快取失效重跑），**合成報告 `scratchpad/audit/REPORT-real-store-audit.md` 是空檔**。
