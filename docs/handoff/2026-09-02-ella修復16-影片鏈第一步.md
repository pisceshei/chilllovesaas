## ①我改了什麼

影片鏈 filter 層：VideoUrlDrop（video_url setting）＋external_video_url／
external_video_tag／video_tag 真實作（URL 形）。逐檔＝worklog。

## ②為什麼這樣改

- 分兩步是艦隊 fix 原案：filter 層先救 settings 裡的影片 URL（首頁
  slideshow／section 背景影片），媒體資料模型（上傳影片）另輪——
  前者零 schema 變更即生效。
- VideoUrlDrop 用 Drop 不用 String 子類：`String#[]("id")` 子字串搜尋
  會產生 `url['id'] == "id"` 假值——這是 Liquid 非 Drop 取值的通則陷阱，
  以後做「字串＋屬性」值物件先問這條。

## ③還有什麼沒解決

- 媒體模型 video/external_video 型＋VideoDrop＋media_tag/model_viewer_tag

## ④下一個人要注意什麼

- ExternalVideoUrlResult 是攜帶式 String——只餵 external_video_tag 或直出
  屬性值；別讓它進 Liquid 屬性存取（同上 `[]` 陷阱）。
- video_identity 的 duck-check 先認 external_id（media 形）再認 type/id
  （setting 形）且 type 白名單 youtube/vimeo——很多 drop 都 respond_to
  :type，別拿掉白名單。
- 接媒體模型時：video_tag 的 sources 分支已在，VideoDrop 只要曝
  `sources[].url` 就直通。
