## 1. 專案是什麼

**CHILL LOVE** — 多租戶電商 SaaS，**功能邏輯與交互 1:1 對齊 Shopify 2026 春季版，視覺用自有設計語言**。

商業動機（使用者原話）：「這也能變相**吸引 shopify 的客戶轉投到我們的平台**。」⇒ **驗收標準不是「功能等價」而是「逐控件對得上」** —— Shopify 商家切過來時肌肉記憶不能斷。

- **技術棧**：Rails 8.1 + MySQL 8 + Vite/React(TS) admin + Liquid 相容前台；Solid Queue/Cache，不用 Redis

- **分工**：Codex 實作（`AGENTS.md`）、Claude 審核驗收
- **使用者的真實 Shopify 商店**：`chill-love-u5q5mnzq`（Plus，香港，前台 `chill.deals`），主題是 Ella 7.2.0

## 5. 踩過的坑（這一節最值錢）

### 5.1 `s-` 元件是 **open** shadow root，不是 closed
44／47／59 三輪都寫「讀不到」——**錯的**。穿透後節點數 4,893 → **15,169**，先前只看到全站三分之一的 DOM。

兩個必踩的技巧：`s-internal-*` host 是 `display:contents` ⇒ 量到 0×0，要量 **shadow 內第一個有尺寸的後代**；slotted 內容的 `textContent` 是空的 ⇒ 文字要**從 host 取**。**每次 navigate 後要重新注入走訪器。**

⇒ 量測一律用 `getComputedStyle` 穿透，**不要再開截圖**（CDP `Page.captureScreenshot` 在本專案已逾時 3 次）。

### 5.2 「無變體商品」根本不存在
pill 分組 id 是 `product_variant_collapsible_*` —— **那三張卡從來都是變體的卡**。有變體時商品頁的價格/庫存/運送整組消失、移到變體詳情頁。官方佐證：`Product` **沒有** `price` 欄位（只有衍生的 `priceRangeV2`）、`ProductVariant.price` 是 non-null。

### 5.3 一個會收錯 100 倍錢的形態
儲存一律 ×100、顯示兩位小數 ⇒ JPY `¥1,480` 存 `148000`，直接送 Stripe 就是收 **¥148,000**。
**它危險不在難懂，在於 HKD／USD 下錯的實作與對的實作輸出一模一樣** —— 本地、CI、staging 全綠。
處置是四層防呆，**最關鍵一條是值物件不實作 `to_i`**（實作了的話 `Integer()`、序列化器、字串插值會自動呼叫，上面三層全部作廢）。

### 5.4 找同根因要 grep 跨界點，不要 grep 那句錯話
`15 §F4-5` 的登記表寫三處，grep 出來是**七處** —— 其中三處不含「零小數幣別」那個字串。

### 5.5 來源分級決定你能做什麼
B-3 在同一天反轉兩次：第三方（`press`）翻面 → 官方原生（`help`）翻回。
**`press` 足以「登記為未知」，不足以翻面一條已生效的資料安全預設。**
另外：「查不到」有兩種 —— 還沒找對地方（Shopify 原生翻譯 CSV 在 Settings → Languages，不在 app 裡），和永久不通（`Shopify/liquid` gem 沒有 `handleize`，閉源）。前者換查法，後者掛帳停損。

### 5.6 並行 agent 撞出矛盾是好事
68／69 同時跑，69 推翻了 68 兩條前提。**序列跑的話 68 的錯結論會被當成既成事實往下傳。**
但**併行改共用設定檔（`limits.yml`）是運氣不是流程** —— 下次要嘛分檔，要嘛序列化。

### 5.7 我自己講錯過的
`llms-full.txt` 我說是「整站內容打包」——**錯的**，Shopify 的那個是 `agents.md` 的第三個別名，而且預設開。
「加地區碼就不會被判重複」——**不成立**（已寫進 `62 §I.2-2`）。真正防重複的是 hreflang ＋ 頁面上真有市場差異（幣別/運費/可售性），不是 URL 形態。

### 5.8 MySQL 的 nullable 欄位讓 UNIQUE 索引失效
`UNIQUE (…, market_id, …)` 配 `market_id NULL` ⇒ **NULL ≠ NULL，索引什麼都擋不住**。裁定 10 之後 `market_id` 永遠是 NULL ⇒ 建議整欄拿掉（本檔產出時尚未執行，見 §4「需要授權」）。

### 5.9 同名頂層函式會靜默吃掉整頁功能
`billingPage` 被同名函式覆蓋，導致財務·帳單發票頁**整頁消失且無任何錯誤訊息**。lint 已固化這條規則。**新增函式前一律先 grep 全檔。**

## 6. 工作方式（硬性）

1. **每次工作結束前寫交接**：`docs/handoff/YYYY-MM-DD-<主題>.md`，四段固定（①改了什麼 ②為什麼／含被推翻的假設 ③還有什麼沒解決 ④下一個人要注意什麼），與改動一起 commit。
2. **原型改動後跑 `python3 scripts/lint-prototype.py`，ERROR 必須為 0**，WARN 不得新增（基線 A 2／P 1／S 10）。
3. **驗收看實跑證據，不看宣稱**。稽核抓過 9 條「宣稱做了但實測不成立」，其中 3 條是主導者自己的。
4. **原型與規格要同輪同步**。這輪之前規格跑了六份文件、原型一份沒動 —— 兩邊會分岔。
5. **Cowork artifact 與 repo 是兩套**。改完原型要另外呼叫 `update_artifact`，否則使用者側邊欄看到的還是舊快照。
6. **推理與事實分開標**；未查證的登記 V-編號（目前最大 **V-223**）。
7. **修改處留追溯註釋** `<!-- 依 XX 號 §Y 修正，原文：… -->` ＋ 🔴 防回退註記（本專案發生過「翻舊版改回去」）。
