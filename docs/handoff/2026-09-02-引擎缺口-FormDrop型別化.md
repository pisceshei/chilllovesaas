> 工作包＝分支 `engine/formdrop-typed`（base main `553312b0`）。依鐵律 21 四段。
> 配對 worklog：`docs/worklog/2026-09-02-引擎缺口-FormDrop型別化.md`。

## ① 我改了什麼
- 依官方 tags/form 與 objects/form 兩頁（取證 2026-09-02）重寫 `FormTag`／`FormDrop`：
  逐型固定 opening tag、參數解析（連字號 key、變數值）、主題 id／class 取代預設、fragment 跟隨
  生效 id、型別隱藏欄；`form` 物件依型別宣告屬性，`password_needed`＝true、`posted_successfully?`
  純 GET＝false、`errors`＝nil。
- 證據鏈：①官方兩頁逐字（註釋內引）；②真店 hoko.vip（Ella 7.2.0）2026-09-02 `curl` 首頁與
  `/pages/contact` 取得的 `<form>` 逐字——`customer_login`（主題 id／class 覆蓋、`data-login-with-shop-sign-in`
  在 class 之前）、`customer`／`contact`（action fragment＝生效 id；預設 class 被主題 class 取代）、
  隱藏欄 `<input type="hidden" … />` 自閉；③Ella `contact-form.liquid` 的成功訊息在真店純 GET
  未輸出 ⇒ `posted_successfully?` falsy。
- 驗證：`spec/liquid/form_tag_spec.rb` F1–F8 綠；四個突變各自轉紅（worklog 列明）；
  `storefront_blog_spec`＋`theme_conformance_spec`（TC-M1／TC-K1）回歸綠；rubocop 綠。

## ② 為什麼這樣改
- 原實作只有 action 表＋固定 `accept-charset`、參數只吃引號字串、`form` 只宣告三鍵：
  Ella／Kalles 的 `{%- if form.password_needed -%}` 密碼欄整段不渲染（triage 已驗證、最高影響），
  Ella `id: form_id` 這種變數 id 被丟掉（hoko 稽核候選），成功訊息每次載入都出現。
- 為何整支重寫而不是補三個鍵：同一 producer（FormTag）的完整狀態矩陣＝官方型別表
  （型別數：`grep -c 'action: "/' app/liquid/theme_engine/tags.rb`）× {id／class／enctype／data／
  hidden}，補鍵只會讓下一套主題再踩一次；鐵律 17.2 的射程就是這個矩陣。
- 被推翻的假設：「fragment 是固定 `#contact_form`」——真店證明 fragment 跟隨主題給的 id；
  「主題 class 與預設 class 合併」——真店只剩主題 class。
