## ② 為什麼這樣改

- 使用者裁定（D79）：UI 與功能都要與 Shopify 一樣。E1 實測給出分帶規則、列解剖、隱藏態、Add block 位置、右鍵選單
  項目、鍵盤表、picker 的群組限定與 "(1/1)" 灰化——本包逐項對位。
- 樹拆成純展示元件＋純函式模型：展開狀態、選取路徑、改名都放頁面，因為 Shift+↑↓、Ctrl+Shift+O／P、URL 還原與預覽
  `cl:select` 都要改同一份；模型純函式便於單測與突變。
- 顯示名改用 JSON `name` ?? schema name：本尊 Rename 就落在模板 JSON `name`（Ella 匯出即帶此欄）；舊版顯示 section id
  與本尊不符。
- 被推翻的假設：①「URL 還原後樹立即可斷言」——還原走載入後的 effect，測試要 `findBy` 等它（ED40）；
  ②「`enabled_on` 的 `*` 語義可憑記憶寫」——倉庫內無來源，改上官方頁取逐字（鐵律 16／19）；
  ③「E2 舊鍵可全部清掉」——`editor.duplicateOp` 雖無 UI 消費者但 E4 會用，只清十個確無消費者者；
  ④「子 block 全在 `block_order`」——Ella 的靜態容器只在 `blocks` map（66 §A.5.2），樹改讀 `visibleBlockIds`。
- 未採方向：把 Preview 列鉛筆做成內嵌整份產品表單的 modal（本尊形態，超出本包射程）；把 picker 一併改兩欄（E5）。
