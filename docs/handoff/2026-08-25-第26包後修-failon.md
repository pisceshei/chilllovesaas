# Handoff：第 26 包後修 `fail_on` 下錯層（2026-08-25）

## ① 我改了什麼

PR #127 合併部署後，線上七幕驗收幕五（截斷檔）失敗：`status=ready`——壞檔被當成
正常圖處理。在 bt3 上直接對照實測兩條路徑後，重構 `VipsBackend` 成
`open`／`Source#derive` 形，把 `fail_on: :error` 移到 loader 層。
base＝main `5743306`。配對 worklog＝`docs/worklog/2026-08-25-第26包後修-failon.md`。

## ② 為什麼這樣改

- 實測（external-facts C1）：`thumbnail_buffer(fail_on: :error)` 對截斷 JPEG
  **不報錯**，只印一行 `VIPS-WARNING error in tile`；同一份 buffer 走
  `new_from_buffer(fail_on: :error)` 則在 `write_to_buffer` 拋
  `VipsJpeg: premature end of JPEG image`。`fail_on` 兩邊的參數表都有，
  差別在**生效層級**，官方文檔對此未見明文。
- 一次 `open` 共用來源順帶解掉「每個 variant 重新解碼一次」的成本問題；
  `autorot` 也只做一次，orientation metadata 被移除後 `thumbnail_image`
  不會再轉第二次。

## ③ 還有什麼沒解決

- 無新缺口。原 #127 的 Pending 五條仍有效。

## ④ 下一個人要注意什麼

  改回 `thumbnail_buffer` 會讓截斷檔重新靜默通過（本機與 CI 都測不出來）。
- 替身測試無法覆蓋 libvips 的實際行為；改影像路徑後**必須跑線上七幕驗收**
  （腳本在 session scratchpad，可重建：造 JPEG → 截斷 → 走 ProcessFile → 斷言 failed）。
