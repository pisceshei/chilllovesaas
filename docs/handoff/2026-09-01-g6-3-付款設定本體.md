## ②為什麼這樣改

- 值域正典＝limits `capture.modes` 四值，modal 只展示三值：86 §2 實測 modal 恰三
  radio，官方 help 另列第四值（V 項）——展示跟實測、值域跟 limits、Plus 專屬值
  誠實拒絕（`FEATURE_NOT_ENABLED`），三層各自對齊自己的真相來源。
- 權限門檻改回「登入態」：初稿驗 `can?("settings.edit")`，但該 key 不存在於 RBAC
  種子 ⇒ 會鎖死全部非 owner 員工且無從授予；改與既有 anchor `shopPaymentProviderSet`
  同門檻（被推翻的假設：「settings 線該有自己的權限 key」——那是 M5 RBAC 的事）。
- checkout 門從「有指紋」改「status active」：activation 狀態機要成為唯一真相，
  否則 admin 的停用鈕是裝飾（突變 M4 直接證明這一格）。
