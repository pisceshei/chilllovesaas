## ②為什麼這樣改

- 全頁 srcdoc 而非逐 section morph：三類變更（佈景設定影響全頁 CSS 變數、
  結構操作動 order、undo 可能跨帶）都需要整頁一致性；本尊的 partial morph
  是優化不是語義，先取一致再談增量。
- draft 覆蓋做在 Runtime 層（draft_sections kwarg）而不是只在 renderer：
  群組帶由 `{% sections %}` tag 在 runtime 深處渲染，renderer 層攔不到——
  DP1 紅過一輪的實證。
- previewPaths 服務端出樣本路徑：前端不猜 handle，無資源型不出鍵回落首頁。

## ④下一個人要注意什麼

- draft 覆蓋現在有**三個消費點**：`section_data_for`（片段）、
  `render_template_sections`（整頁模板帶）、`render_section_group`（群組帶）
  ——動 draft 語義三處同步，缺一處就是「存前存後不一致」型 bug。
- `draftsVersion` 是前端唯一觸發源；新增任何會改 draft 的操作記得 bump，
  否則該操作改即見靜默失效（M11-3 突變即此形態）。
- previewPath 宣告必須在所有引用它的 useEffect **之前**（deps 陣列 render
  時求值，TDZ 會炸）——已踩過，別搬。
