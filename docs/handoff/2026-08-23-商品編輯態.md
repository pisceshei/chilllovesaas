## ① 我改了什麼

- productSet 更新分支（63 §B.4 同支雙態收齊）：`FOR UPDATE` 行鎖＋lockVersion
  比對（缺=BLANK／過期=STALE_OBJECT field null）＋宣告式覆寫＋全樹版本 bump。
- 讀取面：`ProductVariantType`（金額 R4 出向走 Money::Storage#to_decimal）、
  ProductType 補 descriptionHtml/variants、`product(id:)` 查詢。
- 前端同元件雙態：編輯載入填表、右欄狀態卡（四態 select＋可購買/可被發現
  兩維讀值）、儲存帶 id＋lockVersion 不帶冪等鍵、成功留頁吸收新版本。

## ② 為什麼這樣改（含判斷）

- **lockVersion 比對放在 FOR UPDATE 行鎖內**：先鎖再比，兩個並發儲存被序列化，
  輸家讀到新版本吃 STALE——不靠 Rails 內建樂觀鎖的 save 路徑（它在「只改變體
  不改商品列」時不會發 UPDATE、版本不 bump，全樹鎖就破了）。恆 touch
  `updated_at` 保證每次儲存版本前進。
- **更新不帶冪等鍵**：宣告式覆寫天然冪等（重放同輸入＝同結果），防線是
  lockVersion——這正是 limits 冪等區塊「刻意不列入」註釋的適用態（D-PS5 的
  另一半）。建立態照舊強制。
- **handle 變更暫拒、同值 no-op**：301 基建（url_redirects 表）不存在，
  62 §F.3 要求改名必建轉址——靜默改名會斷 SEO 與外部連結。同值放行讓
  「前端送全樹」契約不受影響。
- **status 更新缺席=保持現值**（建立缺席=draft）：宣告式契約下前端一定送；
  缺席只發生在 API 直呼叫，保持現值比靜默改 draft 安全。

## ③ 還有什麼沒解決

- handle 變更（URL 包）；具名選項/多變體 B.5（變體包）；status→ACTIVE 不觸發
  auto_publish（88 §5 #2）；編輯態內容語言切換器（多語言包）；SEO 文案欄位
  （input 無 seo）。M1 剩餘：媒體、系列、庫存 ledger。
- 執行緒級同時儲存未加測（行鎖序列化使第二個必然 STALE，邏輯由跨請求測試
  覆蓋）——庫存包做 ledger 併發測試時一併補。

## ④ 下一個人要注意什麼

- 動 update 的交易邊界前先讀 `save_product.rb` update 的註釋——「先鎖再比」
  與「恆 touch」各擋一個事故形。
- 前端編輯態的 handle 欄是 **disabled**；解開它之前必須先落 url_redirects。
- 本輪一個流程教訓（已當場修復）：`git add -A` 把未追蹤的下一包半成品掃進
  docs PR（91 已登記的老坑重犯）——發現時 PR 未合併，用 plumbing 重建分支
  剔除；**commit 前 `git status` 看 untracked 是鐵律，不是建議**。
