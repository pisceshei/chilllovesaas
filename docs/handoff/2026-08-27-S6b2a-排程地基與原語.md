## ② 為什麼這樣改（含被推翻的假設）

- 🔴 **被推翻：外部研究建議的「第二層 dialog ＋ 把外層 modal 也設 inert」**。
  本尊實測是 **popover**：無 `role="dialog"`、無 `aria-modal`、portal 到 modal 之外
  （`modalDialog.contains(popoverOverlay) === false`）、**沒有 focus trap，底下 modal
  完全可互動**（點它的搜尋框會取得焦點）。⇒ 照本尊（鐵律 12）。

- 🔴 **被推翻：外部研究建議的「不可選過去一律在 grid 層 aria-disabled 擋」**。
  本尊對**日期**是 disabled，對**時間**是**靜默吸附到 now**。決定性實測：先設 `11:00 PM`
  再打 `1:00 PM`，blur 後值變成**當下時刻**而非回退 ⇒ 那是「夾到 now」不是「回退上一個
  有效值」，**兩者只有這個順序分得出來**。

- 🔴 **一條刻意不照抄**：本尊按 `Escape` 會把 popover 與 modal 一起關掉、**丟失 modal 內
  未存的改動**（重現 2 次、無確認）。判準是「行為差異照抄、資料遺失缺陷不照抄」——
  而且 `Modal.tsx` 檔頭本來就明文設計了「Escape 尊重 `defaultPrevented`」，照抄等於
  主動破壞既有的正確行為。

- 🔴 **牆鐘→UTC 需要兩次迭代**：`Intl` 沒有反向 API，反推偏移要把牆鐘當 UTC 造 instant，
  但偏移本身依賴 instant。2026-03-08 03:00 America/New_York 第一次會算成 `08:00Z`
  （錯一小時），第二次才收斂到 `07:00Z`。
  ⚠️ **香港全年 +08:00 無 DST ⇒ 兩次迭代的結果永遠相同，只用它測完全看不出來。**

- 🔴 **MS3 沒殺掉「預設值用店鋪時區」那一格，那是我測試描述的問題不是實作問題**：
  那格驗的是 `initial`（預設值）、MS3 改的是 `nowWall`（下限基準），**兩條不同路徑**。
  已補一格真的驗 `nowWall` 的並更正原格描述。**與 S6b 的 M11 同型**。

- **兩處測試工具限制**：①`<td>` 被 testing-library 算成 `cell` 而非 `gridcell`
  （ARIA in HTML 的上下文推導 `dom-accessibility-api` 沒實作）⇒ 顯式寫 role；
  ②我自己算錯 8/27+7 天（是 9/3 不是 8/31），修正後多一格跨月翻頁的測試。

- 🔴 **對抗性審查抓到 42 條、10 條 🔴，全部修完**（逐條見配對 worklog §8 與
  `docs/dev/m2-schedule-popover.md` 的「對抗性審查」節）。三條最值得下一個人記住：

  **①我把一個副產物寫成了「ours 裁定」，而測資恰好落在它能自證的那一側。**
  兩條 DST 敘述（不存在的往後推、重複的取較早）**只在 UTC 以西成立**——
  審查掃全部 418 個 IANA 時區後得到：往後推有 57 個時區相反、取較早有 73 個相反，
  而當時的測資只有 `America/New_York`（UTC 以西）。而且程式碼**根本沒實作任何裁定**。
  ⇒ **寫「ours 裁定」之前先問：程式碼裡哪一行在執行這個裁定？指不出來就不是裁定，是副產物。**
  【複驗：`grep -n "America/New_York\|Europe/London\|Australia/Sydney"
   app/frontend/admin/lib/timezone.test.ts` 應同時列出三個時區】

  **②我自己在 dev doc 點名的陷阱，自己踩了。** 文件寫「三個在香港測不出來的陷阱、
  測資主力刻意用 NY」，而元件層 15 格**全部**用香港，runner 的 TZ 又剛好與香港同偏移。
  ⇒ **點名一個陷阱之後，要回頭檢查自己的每一份測資有沒有真的避開它。**

  **③`Popover` 在 `Modal` 內鍵盤完全不可達**——而我在檔頭明文寫了「本元件不做焦點管理」，
  把一個缺陷寫成了設計決定。⇒ **「不做 X」寫進檔頭之前，先確認不做 X 的後果是什麼。**

## ③ 還有什麼沒解決

- 🔴 **S6b-2b（接線）未做**——本包合併後**使用者看不到任何新功能**。
  下一步：發布 modal 的管道列加日曆 icon（條件＝`supportsFuturePublishing`，
  **不是**「目前已發布」，§15.10）、delta 加排程欄、送出帶 `publishDate`
  （UTC 帶毫秒 `Z`，§15.8）、發布卡加排程 badge（§15.9）。

- 🔴 **鐵律 13 的三寬度對比未做**：憑證腳本 `scripts/rwd-check.mjs` 尚未建立（PR-C0）
  ⇒ **不對任何寬度做 PASS 宣稱**。`Popover` 的「下方放不下就翻上方」只有本地推理。

- 🔴 **GraphQL 認證失敗回 HTTP 200，與鐵律 4 第三層直接衝突**（既有行為，非本包引入）。
  全倉 request spec 原本**沒有任何一格測未登入**。依鐵律 20.5 登記 `91` §3.25 不擴修——
  但這是**鐵律違反不是偏好差異**，不適用「裁定不修」的清法。

- ⚠️ **`publishDate` 只送 UTC instant 無時區名**：與本尊一致，但 RFC 9557 §1.2 逐字
  指出「UTC 偏移不適合做本地時間運算」——未來時刻若該時區 DST 規則在到點前改變，
  商家設定的牆鐘時間會跑掉。依鐵律 12 不偏離本尊，登記為已知限制。

- ⚠️ **`82` §15.11 六條未取得**，其中 U1／U2（改店鋪時區後徽章是否跟著變、
  徽章來自店鋪級還是使用者級）需要**使用者本人同意**才能實測——實測方正確地停在這裡。

- ⚠️ **登入節流的 spec 是時序敏感的既有 flake**（本包執行時遇到）：
  `staff_authentication_spec.rb` 的「第 11 次登入被擋」在全套執行時偶發紅。
  機制實測：`Rack::Attack` 是**固定窗口**、period 60 秒，那 11 次請求跨越整分鐘邊界時
  計數分裂到兩個 bucket ⇒ 第 11 次不被擋。同一棵樹連跑兩次全套：一次 1 failure、
  一次 0 failure；單獨跑該檔綠。
  ⚠️ **未做「改動前連跑 N 次」的對照** ⇒ 不宣稱本包完全沒提高觸發率（本包讓套件變長，
  機制上會微幅提高撞邊界的機率）。根因與改動內容無關。已登記 `91` §3.26（含修法方向）。

- ⚠️ **`Popover` 不做完整碰撞偵測**：只做「下方放不下就翻上方」與左右夾住視窗。

## ④ 下一個人要注意什麼

1. 🔴 **凡是時區相關的測試，測資不要只用香港**。`Asia/Hong_Kong` 全年 +08:00 無 DST，
   至少三種錯誤實作在它上面 100% 測綠。用 `America/New_York`（2026 DST：3/8–11/1，
   以 `Intl` 實測確認，不要查表）。

2. 🔴 **「今天／現在」一律走店鋪時區**（`Query.shop.ianaTimezone`），不是瀏覽器。
   `Calendar` 的 `today` 是 prop 不是內部算的——這是刻意的，別把它改成 `Date.now()`。

3. 🔴 **`shops.timezone` 與 `staff_members.timezone` 兩張表都有**，排程用**店鋪級**。
   兩者 default 相同 ⇒ 拿錯測不出來，spec 必須讓它們不同值。

4. 🔴 **突變殺不掉時先分清是哪一種**：實作沒問題／我理解錯了／**測試選錯了路徑**。
   本包的 MS3 是第三種——測試描述說它驗 A，實際走的是 B。

5. **`Popover` 給 S6c 用時注意**：`dismissOnOutsideClick` 預設 `false`（照本尊的排程面），
   S6c 的系列 popover 若要點外關閉，顯式傳 `true`。

6. **本機跑測試**：前端 `npx vitest run`（不需 MySQL）；後端 rspec 需要
   `C:\Users\pisce\chilllove-mysql\start-mysql.cmd`。
