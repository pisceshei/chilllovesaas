## ② 為什麼這樣改（含被推翻的假設）

**被推翻：「jsdom＋本機全綠＝可部署」。** 三個 bug 全是部署後才炸的：

1. 🔴 **nginx `$host` 會剝埠號**：外部走 28080 轉發時，Rails 未登入轉導產生
   `http://demo.chilling.com.hk/login`（掉埠）→ 落在前置機 404。看起來像
   「應用壞了」，其實是 proxy 層一個變數選錯。修＝`$http_host`。
   ⚠️ 這條在 TLS＋標準埠後兩者等價——**不要在那時「清理」回 $host**。
2. 🔴 **`crypto.randomUUID` 是 secure context 限定 API**：明文 HTTP 下是
   undefined ⇒ 建立頁一掛載整頁白（React error boundary 畫面）。jsdom 與
   localhost **都算 secure context**，測試永遠測不出。修＝`uuidV4()` helper
   走 `getRandomValues`（無此限制）。教訓：**TLS 前的過渡期，所有
   secure-context 限定 API（clipboard、randomUUID、SW…）都是地雷**，用前先查。
3. **測試消歧第三次同型**（側欄「草稿」vs 徽章、雙儲存鈕）：shell 存在後，
   全文件查詢恆有撞名風險 ⇒ 一律 scope 到語義容器（main／savebar region）。

**SaveBar 架構選擇**：頁面持狀態、topbar 渲染——用 context 註冊
（`SaveBarState`）而不是把表單狀態提升到 shell。理由：SaveBar 是**每個**
編輯頁的共用形態（商品/訂單/設定都會用），shell 不該知道任何表單的內容；
context 契約只有五件事（dirty/saving/onSave/onDiscard/shakeSignal）。

## ③ 還有什麼沒解決

- 未接線欄位全部 disabled（數量/地點/重量/包材/SEO 文案/發布開關/類別/中繼
  欄位）；各自依賴的里程碑見 dev doc §4。
- 說明欄 v1＝純文字→段落 HTML；富文本工具列是視覺佔位。
- guardNav 不攔瀏覽器關閉/重整（原型也沒有）。
- read_page 對長頁的 a11y 樹會截斷（工具怪癖）——實機驗證時用 get_page_text
  對照 DOM 全文，不要只信 interactive 樹（本輪差點誤判「定價卡沒渲染」）。

## ④ 下一個人要注意什麼

- **編輯態**：在同一個 `ProductDetailPage` 加分支，禁止另開檔案（53 號 N-01
  事故守則）；SERVER_PATHS 映射表＋SaveBar 契約直接複用。
- 金額輸入鏈：輸入字串→`parseMoneyToCents`（整數運算）→`centsToApiString`
  （恆兩位）→伺服器 `Money::Decimal`。**任何一環都不走 float**。
- 下一包建議：**商品編輯態（productSet 更新分支＋lockVersion）** 或
  **商品列表補齊**（分頁/篩選/批次），二者都只差後端一小步。
