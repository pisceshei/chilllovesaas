# 交接：第 37 包 外嵌 ExternalVideo

分支 `m1/p37-external-video`，base＝`main`。射程＝整合執行規格 §4-37（B9 收斂面）。

## ① 我改了什麼

**目標**：商品媒體卡可以貼 YouTube／Vimeo 的網址嵌入影片。**影片檔上傳仍然擋**
（伺服器只有 libvips、沒有轉碼器——B9 裁定）。

**遇到的問題與證據**：

1. **取證推翻了三件我原本會寫錯的事**（全文＝`docs/dev/external-facts.md` §D1–D8）：
   官方型別叫 `MediaHost` 不是 `ExternalVideoHost`（後者不存在）；`presentation`
   只在 Storefront、Admin 沒有；官方對「該貼哪種 URL」**三處措辭互斥且無規範列舉**
   ⇒ 我方的形態集合全部是 ours。
2. 🔴 **D48 與外嵌影片直接衝突**：D48 把 alt 權威搬到 `files.alt_text`，
   但外嵌影片**沒有檔案**，alt 無處可住。
3. 🔴 **注入面**：`javascript:` 放進 iframe `src` 會在我方 origin 執行（MDN 逐字：
   繼承載入它的文件的 origin）＝完整 XSS。

**重要動作**：新 `Catalog::ExternalVideoUrl`（解析／正規化／導出，零外部 IO）；
`media` 表 +2 欄；`MediaSync` 前置分派＋外嵌建立＋外嵌 alt 更新；
新 `ExternalVideo` 型別與 `MediaHost` enum；`MediaContentTypeEnum` 改兩鍵聯集；
媒體卡「嵌入影片」入口＋modal；`MediaThumb` 影片分支。

**對抗式審查**：25 項主張、14 項複驗成立、10 個根因全部修完（詳表見配對 worklog）。
最重要的一個＝Vimeo unlisted hash 的 query 載體（官方 Share→Embed 給的形態）被
靜默吃掉——存進去的影片前台一定播不出來、建立當下零錯誤。

## ② 為什麼這樣改

**注入面的主防線放在資料層而不是樣板層**：落庫的只有封閉值域的 `host` 與受字元集
約束的 `external_id`，使用者可控字元從此不存在於任何會進 HTML 的欄位。
樣板層防禦（跳脫、CSP）是第二道——第一道失守時它們才有機會發揮，而把使用者
字串存進 DB 再指望每一個消費端都記得跳脫，是遲早會漏的做法。

**embed URL 導出不落庫**：隱私決策會變；落庫等於改設定後舊資料還停在舊網域。

**D48 的窄縫只認 `external_video`**：放寬成「file 為 nil 就回落」會讓 D48 停用的
舊語義從 M0 遺留圖片列的後門復活。已下反向 spec 釘住。

**兩個 limits 鍵而不是一個**：`upload_*` 是 B9 的閘門（`m0_configuration_spec` 釘死
它等於 `[image]`），`embed_*` 是本包。合併會把閘門一起弄鬆。

**不建 `files` 列**：`files` 的四個欄位都是 `null: false`，塞一個沒有 bytes 的實體
就得把它們全部可空化＝拆掉既有防線。

**被推翻的假設**：
- 「enum 叫 `ExternalVideoHost`」——不存在，正確是 `MediaHost`。
- 「照抄官方的 URL 規則就好」——官方沒有規則，三處互斥。
- 「外嵌影片的 alt 跟圖片一樣走檔案層」——它沒有檔案。
- 「`media.status` 對外嵌湊巧正確就不用管」——A 面正確，B 面會被縮圖狀態冒充。

## ③ 還有什麼沒解決

- 🔴 **B 面（oEmbed 驗證＋縮圖）＝與本尊最大的行為差距**：貼一支私人／已刪除／
  禁止嵌入的影片，我方**靜默接受**，前台才顯示錯誤。本尊那六個 `EXTERNAL_VIDEO_*`
  錯誤碼正是為此存在。閘門已備（`media.external_video_oembed_enabled: false`），
  前置＝一輪 oEmbed 取證（端點、回應欄位、403/404 語義）。
- 🔴 **Vimeo 的 embed URL 形態＝未取得**（`developer.vimeo.com` 是 JS 渲染頁，
  抓到空殼）。limits 的 `player.vimeo.com/video/%{id}` 是 ours 暫定；
  **第 33 包前台上線前必須補取證**，否則 Vimeo 影片可能整批播不出來。
- **已知偏離**：本尊建立時 `MediaStatus`＝`UPLOADED`，我方建立即 `ready`。
- **沒有 Shopify 測試店可點** ⇒ URL 形態、同步層錯誤訊息、是否進檔案庫全是 ours。
- **前台未渲染**：本包只保證資料形狀夠用。

## ④ 下一個人要注意什麼

- **入口**：`app/services/catalog/external_video_url.rb` 檔頭寫了四條
  （零外部 IO／注入防線／形態是 ours／跨功能影響）。改外嵌相關的東西先讀它。
- 🔴 **要加平台（例如 Bilibili）不是改 regex**：`external_video_hosts` 是**官方
  `MediaHost` enum 的值域**，恰兩值且封閉。加第三個平台＝造一個本尊沒有的 enum 值，
  前台 Liquid 的 `external_video.host` 也會跟著對不上。要加請先當作裁定提出。
- 🔴 **`Limits.fetch` 的巢狀 hash 是 symbol 鍵，`Limits.enum` 回大寫字串**
  ——兩者不同，混用會 `KeyError`。本輪踩過一次。
- 🔴 **前端不要補一套 URL 驗證**：判準只有一份、在後端。兩份遲早漂移，
  症狀是「前端說不行、後端其實可以」。
- 🔴 **文案紅線**：官方對 youtube-nocookie **整頁沒有 cookie 敘述**，只宣稱不用於
  個人化；Vimeo `dnt` 官方逐字警告 "some essential cookies will still be active."
  ⇒ UI **不得**寫「不設 cookie」／「零 cookie」。現行文案用的是「減少追蹤用途的
  資料收集」。
- **重跑方法**見 §①。**不得外推**：本包只碰媒體的外嵌路徑；圖片上傳管線
  （第 25／26 包）、檔案庫（第 28 包）的既有問題只登記 `91` §3。
- **停止條件**：審查零未清 ∧ 全部閘門綠 ∧ CI 兩測綠 ⇒ squash 合併 ⇒ 部署 ⇒ 線上驗收。
