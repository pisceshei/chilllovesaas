## ②為什麼這樣改

- sticky cookie 不是猜的：83 §12.3 對本尊 live 實測（帶過一次之後不帶參數
  照樣渲染預覽主題；復位＝帶正式 id）——機制逐格對位。
- 資產跟主題＋no-store：同 URL（/theme-assets/x.css）在兩主題間切換，
  max-age=300 會讓瀏覽器把預覽版快取進正式路徑——這格是設計時抓到的，
  不是事後補。
- 預覽繞頁快取：快取鍵含 theme 擋得住互汙，但「讀」也要繞——釘選使用者
  第二個請求若命中正式頁快取，看到的不是預覽（TP5 殺手格實證 M12-3 轉紅）。

## ④下一個人要注意什麼

- `current_theme` 是店面渲染主題的唯一入口——新增任何渲染型 storefront
  端點一律用它，用 `published_theme` 就是「預覽時供正式內容」型 bug
  （M12-2 的形態）。
- `resolve_preview_theme` 會寫 cookie（帶參數時）——別在 robots／純 API
  端點呼叫 preview_theme_active?，那會對爬蟲種 cookie。
- preview-mini fixture 是 minimal-1.0 的複本＋兩個標記；minimal-1.0 加
  section 時不需同步它（spec 只斷言標記與否）。
