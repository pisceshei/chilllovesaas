# Handoff — D67 頂欄三欄 grid（2026-08-28）

工作包＝`docs/specs/91` §3.40 W-1。配對 worklog：`docs/worklog/2026-08-28-D67頂欄三欄grid.md`。
輸入 ref：`main` = `b8c4afa`（D66 已合併）。分支 `m2/d67-topbar-grid`。

## ① 我改了什麼

頂欄由 flex 改成三欄 grid（本尊實測 `960px 640px 960px` ＠ 2560 ⇒ `1fr 640px 1fr`），
原型與 `AdminShell.tsx` 各包三個 zone wrapper，中槽同時是搜尋列與存檔列的槽位。

實測：`admin.css` 在 1280 搜尋中線**精確落在視口中線**（偏 0）；三寬度兩份檔 zone 溢出皆 0。

## ② 為什麼這樣改，以及踩到的坑

**為什麼不是排版偏好**：舊的 `flex:1 + margin:0 auto` 把搜尋框置中在**剩餘空間**，
左右不等寬時會偏。三欄 grid 兩側同為 `1fr` ⇒ 中欄恆在視口中央。

🔴 **第一版用純 `1fr` 兩側 ＋ zone `min-width: 0`，是錯的**。768 實測側槽被壓到 48px，
而 `.top-right` 實際佔 414–752 ⇒ **內容跨進中槽重疊**。
改成 `minmax(max-content, 1fr)`：側槽拿到內容寬，中欄讓步。

🔴 **而那一輪的溢出稽核回報 0** ——因為它只比視口邊緣。**典型 fail-open**。
判準已改成「每個 zone 的子元素必須落在自己 zone 的矩形內」，
並排除定位祖先脫離流的子代（≤767 時 savebar 是 `position: fixed`，
它的子元素在流外，舊寫法會誤報）。
反向 canary：把中欄改回純 `1fr`，768 下抓到 **28 處**；改回來 **0**。

## ④ 下一個人要注意什麼

- 🔴 **grid 側槽別配 `min-width: 0`**。那會讓側槽壓到比內容還窄、內容往鄰槽重疊，
  而**視口邊緣的溢出檢查完全看不到**。要嘛 `minmax(max-content, 1fr)`，要嘛別設 `min-width: 0`。
- 🔴 **溢出檢查要比「該元素所屬容器」的矩形，不是視口**。並且**一定要配 canary**
  ——把判準改回壞值，確認它真的轉紅。本輪 canary 是 28 vs 0。
- 🔴 **檢查定位祖先**：`position: fixed` 的容器其子元素在流外，逐元素比矩形會誤報。
