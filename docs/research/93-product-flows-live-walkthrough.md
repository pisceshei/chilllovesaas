## 1. 建立多變體商品（全流程）

1. 商品列表右上「新增商品」→ 建立頁。
   - 🔴 **建立頁右欄有狀態卡，預設「啟用」**（≠我方「建立固定草稿、無狀態卡」——D-PS6 裁定衝突項，
     需請示：本尊的 productCreate 預設其實是 ACTIVE？but help「Active＝新商品預設值」（92-A）互證。
     我方 63 §B.4「建立未帶 status ⇒ draft」是**照 productSet API 語義**；本尊 admin UI 建立頁是
     **顯式帶 ACTIVE**——兩者相容：UI 恆顯式送 status。⇒ 修正方向＝我方建立頁補狀態卡（預設值另裁）。
   - 🔴 **空白建立頁一進來 SaveBar 就顯示「未儲存的變更」**（含捨棄/儲存），不等首次輸入。
   - 建立頁右欄卡序：狀態｜發布（骨架）｜商品組織分類（類型/廠商/商品系列/標籤）。
2. 標題輸入後 **SEO 卡 SERP 預覽即時生成**（handle 段即時從標題推導，如 `products › t`）。
3. 子類卡「⊕新增尺寸或顏色等選項」→ popover（搜尋＋「沒有可用的相容中繼欄位」＋⊕建立自訂選項）
   → inline 編輯器：
   - 選項名稱 input（placeholder 尺寸、右上 metafield 圖示）＋選項值列（placeholder 中）。
   - 輸入第一個值後**自動長出「新增其他值」空列**；每個已填值列帶 ⠿ 拖曳把手＋🗑 刪除。
   - 值列輸入的同時，**卡底變體表即時渲染**（未儲存就出現）。
   - 按鈕：刪除（紅）｜完成（黑）；卡底「⊕新增其他選項」（開第二選項的同型 popover）。
4. 按「完成」→ 選項卡收合成：選項名標題＋值 chips（S/M/L）＋⠿＋「⊕新增其他選項」。
5. **變體表（建立態）**：表頭 `全選☐｜子類｜價格｜可售數量｜發布`；每列＝☐｜媒體 icon（可點）｜
   值名｜`HK$ 0.00` input｜可售數量 input｜發布欄兩計數（管道 icon 3｜市場/catalog icon 0）；
   右上搜尋＋篩選 icon；表尾「Shop location 總庫存：0 件可供貨」。
6. 儲存 → toast「商品已建立」→ 轉導編輯頁，頂部綠色 banner
   「✓已新增 <名>／新增其他商品、檢視狀態為有效的商品或新增運送服務包材」。
   - 🔴 **廠商自動預填店名**（CHILL LOVE）——92-F「未指派 vendor 預設＝商店名稱」實測互證。
   - 🔴 **handle 生成保留 CJK**（`實測用-t恤-多變體-測試資料`）——**與我方 product-token8
     fallback 不同**（我方純 CJK 標題退化為隨機 token）。登記差異：本尊支援 UTF-8 handle。
   - 編輯態變體表：可售數量欄變**唯讀**（建立態是 input）；價格仍 inline input。

## 2. 變體子頁（/products/{id}/variants/{variant_id}）

- 頁首：麵包屑（商品名 › S）＋右上 `複製｜更多動作▾｜︿﹀`（變體間導航）。
  **更多動作值域＝單項「🗑 刪除子類」（紅）**。
- 左欄：商品卡（縮圖＋名＋狀態 badge＋「3 個子類」）→ 搜尋子類 input → 篩選 pills
  （`尺寸▾`＝按選項值過濾｜`銷售管道▾`）→ 變體清單（S/M/L 各帶縮圖框，當前高亮）。
- 主欄：變體圖「+」上傳格＋變體名＋「所有管道｜無」列｜**選項值 input（尺寸=S，可直接改值）**｜
  價格卡（HK$ input＋pills：比較價格/單價/收取稅金 是/每品項成本＋共用 chevron）｜
  庫存卡（per-location 表＋檢視調整記錄＋pills：存貨單位(SKU)/條碼/無庫存時繼續銷售 關閉）｜
  運送卡（實體商品 toggle＋包材＋商品重量 0.0 kg＋原產地/HS pills）。

## 3. 庫存調整（實測整流程）

1. 庫存表點「可供貨」數字 → 出現**調整列**：
   `模式 select▾｜數字 stepper｜來源 select（Shop location）｜📝 新增原因｜✓`。
2. **模式二值：設定為｜調整**（＝help 的 Set to/Adjust by，92-C 互證）。
3. **原因選單七值（繁中全量）**：更正｜盤點｜已收貨｜退貨重新入庫｜損壞｜遭竊或遺失｜促銷或捐贈
   （＝Correction/Count/Received/Return restock/Damaged/Theft or loss/Promotion or donation）。
4. ✓ 後**不即時提交**：表格顯示藍字 pending 變化（`0 → 10`）且 **SaveBar 出現**——
   庫存調整與表單同一 SaveBar 提交模型（離頁未存＝丟棄，92-C「pending 全丟」互證）。
5. 儲存後「檢視調整記錄」→ 調整記錄頁（URL `/products/inventory/{inventory_item_id}/inventory_history?location_id=…`，側欄高亮「庫存」）：
   - 空態：「Shop location在過去 180 天內沒有任何庫存調整記錄」＋「深入瞭解調整記錄」——**180 天窗口實測互證**。
   - 有記錄列：`日期（相對時間「剛才」）｜活動（**已手動盤點庫存**＝Count 的繁中 Activity）｜建立者（staff 名）｜
     不可供貨｜已預訂｜可供貨 (+10) 10｜現有庫存 (+10) 10`——「(變化量) 新總量」格式互證。
   - 🔴 **措辭不一致（本尊自己的）**：調整記錄頁欄名「已預訂」vs 商品頁庫存表「已承諾」＝同一
     Committed 概念兩處不同譯文。我方統一用「已承諾」（71 §A ours）。

## 4. 複製商品（modal 全值域）

- 更多動作→複製商品 → modal（URL `/duplicate`）：
  - info banner：「此商品包含需要唯一性的中繼欄位值。這些值不會複製，將留空處理。」
    （因商品掛了 unique metafield——**唯一性 metafield 的複製語義＝留空**）。
  - 標題預填「<原名>（副本）」。
  - **「複製所選商品詳細資料」checkbox 五項**：多媒體檔案｜存貨單位 (SKU)｜條碼｜庫存數量｜翻譯
    ——**本品沒有的資料項呈 disabled**（本例前三項灰）。
  - **商品狀態 radio 三值**：設為「草稿」（●預設）｜設為「有效」｜設為未刊登。
  - 取消｜複製商品。
- 複製後：新 ID、標題帶（副本）、**狀態＝草稿**（92-A「Draft＝複製後預設」互證）、
  廠商/類別建議等組織欄位跟隨。

## 5. 封存／取消封存

- 更多動作→封存商品 → 確認 dialog：「要封存商品嗎？／封存此商品會將其從您的銷售管道和 Shopify
  管理介面中隱藏。您可以在商品清單中使用狀態篩選器找到該商品。／取消｜封存商品」。
- 封存後：badge「已封存」；🔴 **右欄狀態卡整個被「已封存」專用卡取代**——
  卡內：封存 icon＋「已在您的 Shopify 管理介面中隱藏 (產品清單外)。」＋**「取消封存商品」按鈕**
  （不是 select 選項）。⇒ 我方 P1 的「ARCHIVED 時 listbox 多顯示已封存項」形態不對，
  **P2 修正：封存態換專用卡＋按鈕**。
- 更多動作選單隨狀態切換：封存商品 ⇄ 取消封存商品（我方 P1 已同型）。

## 6. 刪除商品

- 更多動作→刪除商品 → 確認 dialog（URL `/delete`）：
  「刪除 <名>？／若您刪除「<名>」，此動作即無法復原。**任何僅供此商品使用的多媒體檔案也將一併刪除**。
  ／取消｜刪除 商品（紅底）」。
  - 🔴 媒體刪除語義＝**引用計數**：只刪「僅供此商品使用」的檔案（共用檔保留）——媒體管線（G9）
    的刪除規則要照此設計。
- 確認後：toast「商品已刪除」＋轉導商品列表。
