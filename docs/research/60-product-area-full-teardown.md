## 0. ⭐ 方法論修正：`s-` 元件是 **open** shadow root，不是 closed

**44／47／59 號都寫「`s-` 前綴是封閉 shadow root，內部讀不到」——這個結論是錯的。**

實測 `element.shadowRoot` **可存取**。寫一支穿透走訪器後：

| | 節點數 |
|---|---:|
| `document.querySelectorAll('*')`（light DOM） | 4,893 |
| 穿透 shadow root 後 | **15,169** |

**先前三輪只看到全站三分之一的 DOM。** 47 號因此改用「CSS transform 放大 + 截圖判讀」來認 badge 形狀，59 號因此把類別 picker、更多動作選單記為「拿不到」——**那些現在全都拿得到**。

### 兩個踩過的坑（照抄可省時間）

1. **`display:contents` 的 host 量不到尺寸**。`s-internal-button` 的 `getBoundingClientRect()` 回 0×0，真正有尺寸的是 shadow root 內的 `<button>`。
2. **slotted 內容的 `textContent` 是空的**。shadow 內的 `<button>` 裝的是 `<slot>`，文字節點在 light DOM。所以「找按鈕」要**從 shadow 內取尺寸、從 host 取文字**：
   ```js
   const host = el => { let n=el; while(n){ const rt=n.getRootNode&&n.getRootNode(); if(rt&&rt.host) return rt.host; n=n.parentElement; } return null; };
   const label = b => { let t=text(b); if(t) return t; let h=host(b); for(let i=0;i<3&&h&&!t;i++){ t=text(h); h=host(h); } return t||b.getAttribute('aria-label')||''; };
   ```
3. **導航會清掉注入的全域**——每次 navigate 後要重新注入走訪器（別像我一樣先踩一次）。

## 1. ⭐ 架構發現：無變體商品 ＝ 只有一個隱含變體的商品

59 號在**無變體**商品頁量到三組 pill，分組 id 是：

```
product_variant_collapsible_pricing / _inventory / _shipping
```

當時只當成命名。本輪拆了**有變體**商品的變體詳情頁 `/products/{pid}/variants/{vid}`，發現**同樣三組、同樣的 id、同樣的 pill 組成**。

於是名字解釋了架構：**那三張卡從來都是「變體」的卡，不是「商品」的卡。**

| | 無變體商品 | 有變體商品 |
|---|---|---|
| 商品頁的 價格／庫存／運送 卡 | **有**（其實是那唯一隱含變體的卡，就地內嵌） | **完全消失** |
| 子類卡 | 空態「新增尺寸或顏色等選項」 | 選項 chips ＋ 變體表格 |
| 那三張卡去哪了 | — | 移到**變體詳情頁** |

**對我方的意義**：資料模型要照這樣做——商品**恆有**至少一個變體，「無變體」只是 `variants.length === 1` 的呈現特例。若做成「商品有價格欄位、變體也有價格欄位」兩套，之後同步邏輯會爛掉。這也解釋了為什麼 Shopify 的 GraphQL 把價格掛在 `ProductVariant` 而不是 `Product`。

## 4. ⭐ 庫存五態的官方定義（逐字，來自欄位標題 tooltip）

`/products/inventory` 的欄位標題 tooltip **就是官方定義**，不必再猜：

| 欄位 | 官方定義（逐字） |
|---|---|
| **不可用** | 無法銷售且未保留給任何訂單的庫存。 |
| **已佔用** | 已保留給未出貨訂單的庫存。 |
| **可用** | 您的商店中可供銷售的庫存。 |
| **現有庫存** | 某個地點的庫存總量。這是 **不可銷售、已保留 和 可供銷售 品項的總和**。 |
| **在途** | 正運往您的地點的庫存。 |

→ **恆等式（官方背書）：`現有庫存 = 不可用 + 已佔用 + 可用`**。`在途` **不在**恆等式內。

### ⚠️ Shopify 自己的譯名不一致
同樣五個量，兩個頁面用不同詞：

| 概念 | 商品／變體頁 | 庫存頁 |
|---|---|---|
| unavailable | 無法供貨 | **不可用** |
| committed | 已承諾 | **已佔用** |
| available | 可供貨 | **可用** |
| on_hand | 現有庫存 | 現有庫存 |
| incoming | （不顯示） | **在途** |

**我方要挑一套並全站統一**。建議採庫存頁那套（定義 tooltip 掛在那邊，是權威來源）。

### 庫存頁其他事實
- 欄位：`圖片｜商品｜存貨單位 (SKU)｜不可用｜已佔用｜可用｜現有庫存｜在途`
- checkbox value ＝ `gid://shopify/InventoryItem/51159633494251` — **InventoryItem 是獨立實體**，不是 variant 的欄位
- URL 帶 `?location_id=93626073323` — **庫存視圖是地點範圍的**
- 頁首動作：`匯出｜匯入`（與商品列表各有一套 CSV）
- 檢視：`All`＋`顯示選項`＋`重設檢視畫面`＋`儲存`

## 7. 採購單 / 轉移 / 禮品卡

三者列表在本店**皆為空態**，空態文案與主要動作：

| 模組 | 空態文案 | 動作 |
|---|---|---|
| 採購單 | 管理您的採購單 / 追蹤並接收向供應商訂購的庫存。 | `建立採購單` |
| 轉移 | 在地點之間轉移庫存 / 在您的商家地點之間轉移並追蹤庫存。 | `建立轉移` |
| 禮品卡 | 開始販售禮品卡 / 新增禮品卡商品來販售，或建立禮品卡並直接寄給顧客。 | `建立禮品卡`／`新增禮品卡商品`（＋服務條款同意註記） |

### 採購單建立頁
`出貨地與收件地`（選取供應商／選取收件地）｜`搜尋要新增的商品`｜**成本摘要**（採購訂單詳情／`N 個子類 (N 個品項)`／`稅金 (內含)`／`總計`）｜採購單詳情（`給供應商的備註 0/5000`｜`付款條件 無`｜**`幣別 HKD HK$`**｜`搜尋或建立標籤 0/40`）
> 採購單**自帶幣別**——供應商可能用別的幣別結算，與商店 presentment 幣別無關。這對我方的 integer cents 模型是重要約束。

### 轉移建立頁
`選取出貨地` → `運送中` → `選取收件地`｜`搜尋要新增的商品`｜日期｜`新增參考名稱`｜`新增備註`｜`新增標籤`｜**`連結採購單`**
> 轉移可以**連結到採購單** ⇒ 採購單→轉移→庫存入帳是一條鏈，不是三個獨立模組。

### 禮品卡
「**新增禮品卡商品**」與「**建立禮品卡**」是兩件事：前者是可販售的商品，後者是直接發給顧客的卡。我方 56/57 號的禮品卡會計討論只涵蓋後者。
