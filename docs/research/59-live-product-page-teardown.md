## 2. ⭐ 核心交互發現：pill 收合模式

**這是本輪最重要的發現，我方原型完全沒有。**

卡片內的**次要欄位不展開顯示，而是收合成一排 pill**。每個 pill 是 `<button aria-expanded="false" aria-controls="<共用區域 id>">`，內容為：

- 欄位**有值** → `標籤 + 目前值`（例：`比較價格HK$2,000.00`、`存貨單位 (SKU)7340032861976`）
- 欄位**空值** → 只有 `標籤`（例：`單價`、`每品項成本`、`HS 代碼`）

點任一 pill 展開**該卡片共用的一個** collapsible 區域（不是每個 pill 各自展開）。

### 三組 collapsible（`aria-controls` 值即分組鍵）

| 分組 id | pill 清單 | 展開後內容 |
|---|---|---|
| `product_variant_collapsible_pricing` | 比較價格 `HK$2,000.00`／單價／收取稅金 `否`／每品項成本 | 原價 `HK$` ／ 成本 ／ **利潤 `--`** ／ **利潤率 `--`** ／ 其他顯示價格 |
| `product_variant_collapsible_inventory` | 存貨單位 (SKU) `7340032861976`／條碼 `7340032861976`／無庫存時繼續銷售 `關閉` | — |
| `product_variant_collapsible_shipping` | 原產地國家/地區／HS 代碼 | — |

DOM 形狀（**只記結構不抄樣式**）：
```
button._UnstyledButton_ < div._BasePill_ < div(InlineStack) < div(InlineStack) < div(Box)
```

### 為什麼這個模式重要

它解決的是「商品頁欄位太多」這個真問題：主要欄位（價格、數量、重量）常駐可見，次要欄位（成本、HS 代碼、條碼）收成一行 pill，**但仍然顯示目前值**——所以不必展開就知道有沒有填。這比「全部展開」和「摺疊成一個標題」都更省視覺成本。

**利潤／利潤率是衍生唯讀欄位**（價格 − 成本），算不出來時顯示 `--` 而不是 `0`——與我方 P0-17 剛做的「未計算 ≠ 0」是同一條原則。

## 7. 商品**建立**頁（`/products/new`）— 與詳情頁是同一個元件

拆解結果：**版面、卡片順序、pill 分組 id 全部相同**（`product_variant_collapsible_pricing` / `_inventory` / `_shipping` 三組，一字不差）。

差異只有三類，全部是**預設值與空態**，不是結構：

| 類別 | 詳情頁（已存在商品） | 建立頁 |
|---|---|---|
| **預設值** | `收取稅金 否`（該商品被改過） | `收取稅金 是`（**建立時預設收稅**） |
| **庫存區形態** | 逐地點表格：`地點｜無法供貨｜已承諾｜可供貨｜現有庫存` ＋ `檢視調整記錄` | `數量` input ＋ `Shop location` ＋ `可用數量`（**還沒有異動歷史，所以沒有那四欄與記錄連結**） |
| **空態** | SEO 顯示富摘要預覽（含價格） | SEO 顯示「新增標題和描述以預覽此商品在搜尋引擎產品資訊中的顯示方式」 |
| | 多媒體為已上傳的圖格 | 多媒體顯示 `上傳新檔案`／`選取現有檔案`／「接受圖片、影片或 3D 模型」 |
| | 右欄有 狀態／發布／銷售／商品組織分類／佈景主題範本 | 右欄只有 `發布`（其餘卡片在有資料後才出現） |

> **架構結論**：**不要做成兩個頁面。** 建立與詳情是同一個元件的兩種狀態（`isNew`）。我方原型目前只有 `productPage()` 一個詳情頁，`新增商品` 走的是別的路徑——這一點要對齊，否則兩邊會各自長歪（本專案已有前例：`billingPage` / `setBillingPage` 分家造成的靜默覆蓋事故）。

## 9. 這間商店沒有多變體商品

`/products` 列表全頁掃描：`\d+ 個子類|個變體|variants?` **命中 0**，列表也沒有任何展開變體的箭頭按鈕（`expandBtns = 0`）。商店品項是香水／保養品，全部單一 SKU。

→ 所以 **U-1 不是「這一個商品剛好沒有變體」，是整間商店都沒有**。要拆變體 UI，只能自建一個有變體的測試商品，或換一間商店。**在拆到之前，我方原型既有的變體矩陣不得以「Shopify 沒有」為由刪改。**
