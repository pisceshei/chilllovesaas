**規則編輯頁 `/settings/legal/cancel-return-rules/{id}`**（實測 id=16371777771）：

| 區塊 | 內容 |
|---|---|
| 麵包屑 | `🗒 › 預設規則`（icon chip ＋ ›） |
| 卡片 1 | `退貨規則`「套用於訂單中**已履行**的品項」＋ toggle；`取消規則`「套用於訂單中**未出貨**的品項」＋ toggle |
| 卡片 1 footer | 灰底提示 **「退貨與取消規則適用於在啟用或更新規則後所購買的品項」** |
| 卡片 2 | `最終銷售品項`「顧客無法針對最終銷售商品提出退貨或取消要求」；radio `商品系列` / `商品`；`⊕ 新增最終銷售商品系列`（規則關閉時整卡 disabled/灰化） |
| footer | `深入瞭解退貨與取消規則` |

**三條必須寫進 44 號防呆冊的業務邏輯**：
1. **規則版本綁在購買時點**：訂單品項在下單當下就 snapshot 當時生效的 return rule；之後改規則不影響舊訂單。→ `order_line_items.return_policy_snapshot_id`（不可只存 rule_id 外鍵，規則會被改）
2. **退貨 vs 取消以履行狀態切分**：`fulfilled` 品項走退貨流、`unfulfilled` 品項走取消流，同一張訂單可能兩者並存 → 前台「申請」按鈕要**逐 line item 判斷**顯示哪一種
3. **最終銷售（final sale）**：以 collection 或 product 為粒度標記，命中即**完全不出現**退貨/取消入口（不是提交後才拒絕）
