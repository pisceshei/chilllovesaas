# 商品模塊 ↔ Liquid 引擎 ↔ 買家商品詳情頁：對接缺口分析（2026-08-30）

> 問題（使用者）：既有商品模塊與 Liquid 引擎、買家前台商品詳情頁的接口對接
> 是否需要補充？
> **結論：需要。**缺口分三級：A 級 3 項會讓頁面**行為錯誤**（售罄可購、
> 變體切換壞死、售罄樣式失真），A′ 級 7 項是「資料在庫、drop 沒出口」，
> B 級是 stub 契約與 W6 端點面。清單如下，逐項帶證據錨。
>
> 證據基礎（四源交叉）：
> ① 真店實測（83 號；Ella 7.2.0 商品頁的請求鏈與行為）
> ② fixture 商品頁家族的屬性消費集（templates/product.json 遞移閉包掃描，
>   本輪執行：product 側 ~25 屬性、variant 側 13 屬性）
> ③ docs/research/26 §1 的 T0/T1/T2 分層與 stub 規則
> ④ 倉內現況（db/schema、models、GraphQL、`app/liquid/theme_engine/drops.rb`
>   ＝包 30 #197 的生產 drops、specs/93 契約）

## §A 行為錯誤級（買家可感知的錯；建議下一個商品前台包首批修）

### A1 `VariantDrop.available` 恆 true（超賣入口）
- 現值：`def available = true`（註記「v1：可購買性由 lookup 前置；庫存感知隨前台包」）。
- 消費端：Ella 售罄 radio 的 disabled/劃線樣式、加購鈕禁用全靠它
  （83 §4.5 實測：M/L 售罄劃線＋點擊無效）。
- 後果：我方前台**售罄變體顯示可購**，加購進 cart 後才在下游炸。
- 修法：tracked（`inventory_management` 有值）⇒ `available = 可售量>0 ∨
  inventory_policy=continue`；untracked ⇒ true。資料全在
  （inventory_levels＋product_variants.inventory_policy）。
- 同批：`ProductDrop.available` 恆 true ⇒ 改「任一變體 available」。

### A2 `?variant=` 未接進渲染管線（變體切換壞死）
- 現值：`page_renderer` 只取 path（`render("/#{params[:path]}")`），query
  params 不進 context；`selected_variant = nil`、
  `selected_or_first_available_variant = variants.first`。
- 消費端：Ella 變體切換＝重抓
  `GET /products/{h}?variant={id}&section_id=template--…__main` 讓伺服端
  按 URL 參數重算價格/庫存塊（83 §4.1 真點擊抓包）——我方引擎收到後
  **永遠回第一變體** ⇒ 切 M/L 價格不變、變體圖不換。
- 修法：renderer 收 query params → drop context 帶 `selected_variant_id` →
  `selected_variant`／`selected_or_first_available_variant` 按官方語義
  （選中→availability fallback）實作。`?section_id=`／`?sections=` 的
  Section Rendering API 端點面同屬 renderer 參數化（W6 包 33 射程，
  形態照 83 §3.4 六格）。

### A3 `product_option_value` 缺 `available`/`selected`（售罄樣式失真）
- 現值：`options_with_values` 只回 name/values 名稱投影；docs 26 §1
  `product_option_value` T0 面＝id/name/available/selected/swatch/variant/
  product_url。
- 消費端：Ella 的 M/L 劃線＝per-value availability（83 §4.5）。
- 修法：value.available＝該值參與的變體中任一 available（join 已有：
  product_variant_option_values）；selected 隨 A2 的選中態。swatch 無存儲
  ⇒ nil stub＋登記（見 §B）。

## §B stub 契約級（現值正確，立契約防走樣＋登記未取得）

- **正確的 nil/空 stub（26 §1 明文 T0 stub 規則）**：`unit_price`／
  `unit_price_measurement`（T1，EU 法域 pack 素材）、selling plan 全族
  （訂閱功能未做）、`quantity_price_breaks` []、`gift_card?` false
  （**gift_cards 表不存在**——若日後做禮品卡，此欄同批補）、
  `store_availabilities`（T2）、swatch（無存儲）。
  ⇒ 建議在 drops 測試裡**逐一釘死 stub 值**（mutation 防有人「順手」改成
  半真值）；47 屬性對照表掛 specs/93 附錄。
- **W6 端點面（包 33 驗收項，非本包缺口）**：`/products/{h}.js`（cents）
  vs `.json`（decimal string）vs suggest（decimal string）三形、
  `?sections=`（≤5、缺失→null、超限→400）、`?section_id=`（wrapper HTML、
  亂 id→404）、`?view=`（缺模板→200 回退）、cart 家族（FormData＋
  bundled sections）——形態全部已在 83 §3 定格，包 33 照抄驗收。
- `ShopDrop.money_format = nil`：Ella 直接餵 money filter 時走 registers
  ✓；但主題 JS 讀 `theme.moneyFormat` 的形態（Ella settings 注入）未驗
  ——隨 W6 快取/i18n 包對表。

## §C 建議的落地切分（不在本檔執行）

1. **商品前台補完包（S 級）**：A1＋A3＋A′1–4、8（全是 drop/renderer 層，
   零 migration）＋ stub 釘死測試。前置：無。
2. **渲染參數化包（M 級）**：A2（query params→context→selected_variant）
   ＋ Section Rendering 兩參數端點（可拆給包 33）。
3. A′5–7（collections/metafields/category 出口）隨對應功能線包
   （系列前台／metafields 面／taxonomy）。
