## 4. 要新建的東西

### 4a. GraphQL 讀取面（目前完全沒有庫存查詢）

1. **`inventoryItems(first/after/last/before, query)`** connection：
   - 列資料＝item ＋ 其變體/商品標題 ＋ 該地點的 level 數量五欄（unavailable/committed/available/on_hand/incoming）。
   - 分頁走 `Products::KeysetConnection`（已泛化，照 collections 用法）。
   - `locationId` 參數（GID）選地點；缺省＝該店第一個地點。
   - 🔴 數量欄**一次 JOIN 帶出**，不逐列查（照 `TOTAL_INVENTORY_SELECT` 的 N+1 教訓；
     測試用**正向計數**斷言——空集斷言測不到缺席，見 P16 worklog 的空炮教訓）。
   - `query` 參數 v1 支援商品標題/SKU 的字面搜尋（照 `Products::SearchScope` 形態，可簡化）。
2. **`locations`**：id/name/active，給地點選擇器。
3. **`inventoryAdjustmentGroups(inventoryItemId, locationId, first/after)`**：歷程頁資料。
   每列（group）帶：createdAt／reason／staff 顯示名（staff_member_id → StaffMember，可 null）／
   client_source／referenceDocumentUri／該 (item,location) 的 changes（delta per 數量欄）／
   🔴 **`quantityAfterChange`**：每數量欄的期後值——SQL window
   `SUM(x_delta) OVER (PARTITION BY inventory_level_id ORDER BY created_at, id)` 升冪算 running
   total，頁面倒序顯示。180 天窗：`WHERE created_at >= ?`（天數引
   `limits.inventory.adjustment_history_retention_days`，鐵律 6）。
   - 🔴 這就是總裁定 §四-2 登記給本包的「第八式」落點：**必須有一條 spec** 驗
     「連續多次調整後，每列的 quantityAfterChange 逐列正確且最後一列＝levels 現值」。

### 4b. A 塊：/admin/inventory 列表

- 欄集（實測 94 §2.1 為準）：縮圖｜商品（variant 標題）｜SKU｜Unavailable｜Committed｜Available｜On hand｜Incoming。
  🔴「箱名稱」欄**遞延**（71-R8-V1 既有登記，不做）。
- 頁首：Export／Import 兩鈕 **disabled**（CSV＝D43 明文延後；放可見但不可用的鈕不如 disabled＋tooltip）。
- 檢視：v1 只做 All（Incoming/Not Fulfillable 檢視遞延——Incoming 恆 0 直到採購線；
  Not Fulfillable＝71-R8-V1）。**worklog 明文登記，不靜默**。
- Unavailable 儲存格：popover 唯讀顯示四子狀態（damaged/quality_control/safety_stock/…；
  本尊有「Open unavailable popover」鈕＝94 實測）。
- **行內調整器**（實測 94 §2.3 形態）：點 Available 或 On hand 儲存格 →
  `[Set to|Adjust by ⌄] [數量] [地點名] [Add reason ⌄] [✓]`：
  - 模式二值：Set to（打 `inventorySetQuantities`，帶 `compareQuantity`＝載入時的現值＝天然 CAS）／
    Adjust by（打 `inventoryAdjustQuantities`，`changeFromQuantity` 帶載入現值）。
  - reason 下拉＝**UI 7 值子集** `limits.inventory.adjustment_reasons_manual_ui`（預設 correction，
    help 明文）；標籤走 i18n（識別字≠標籤，95 §3 的對照表）。
  - 🔴 **兩段式**：✓ 只把變更標成 pending（儲存格顯示 `9 → 10` 於 Available 與 On hand 兩欄
    ＝94 實測形態），頂部 SaveBar 的 Save 才逐筆送 mutation；離頁丟棄（help 明文）。
  - 每筆 pending 各自生成一把 UUID 冪等鍵（`app/frontend/admin/lib/uuid.ts`）；CAS stale（`COMPARE_QUANTITY_STALE`／
    `CHANGE_FROM_QUANTITY_STALE`）→ toast 顯示伺服端訊息並重載該列。
  - 🔴 **Adjust by 的 origin/destination 選擇器（狀態間移動）不做**——那是 Move 語義
    （service 一次呼叫只支援一個 name），Move 已明文延後。**登記 71 §F 新 V**：
    「本尊 Adjust by 有 origin→destination 移動 UI，我方 v1 只有 available/on_hand 的差額」。
- 空態：無追蹤品項時 EmptyState。

### 4c. B 塊：商品頁庫存卡（改造 `ProductDetailPage.tsx`）

### 4d. C 塊：調整記錄頁

- 路由 `/admin/inventory/:itemId/history`；入口＝商品頁庫存卡「檢視調整記錄」連結（77 §1）。
- 欄集（**實測 94 §2.5 為準**，7 欄）：Date｜Activity｜Created by｜Unavailable｜Committed｜Available｜On hand。
  Incoming 欄做**條件性**（該品項 incoming 恆 0 時不顯示——總裁定 §四b 第 4 點的方向）。
- 儲存格格式：「(+1) 10」＝delta＋quantityAfterChange；無變動的欄顯示現值或 0（照 94 §2.5 實測樣式）。
- Activity 標籤＝總裁定 §四b 對照表（**i18n 化**：reason 識別字 → 各語標籤；en 用本尊原文
  Inventory received 等）；Created by＝staff 名或 client_source。
- Activity 儲存格 popover：顯示 referenceDocumentUri／ledgerDocumentUri（有才顯示）——94 §2.5 實測形態。
- 空態：「僅顯示最近 180 天」說明（天數引 limits）。

### 4e. i18n

## 6. 測試要求（每條都是 DoD）

1. **request spec**：三支新查詢——列表數量正確（含多地點）、locationId 過濾、
   🔴 N+1 守衛用**正向計數**（含指紋的 SQL 恰 N 次）且**突變驗證**（拿掉 JOIN/select → 紅）、
   歷程的 quantityAfterChange 逐列正確＋最後一列＝現值（第八式）、180 天窗、租戶隔離、
   `inventory.view` 授權縫存在。
2. **前端 vitest**：列表渲染 8 欄與數值；行內調整器 Set to/Adjust by 切換；reason 七值全列
   （值域窮舉）；pending → Save 送出的 mutation payload 斷言（含 idempotencyKey 存在、
   compareQuantity＝載入值）；CAS stale 的 toast 路徑；歷程頁「(+1) 10」格式與 Activity 標籤。
   🔴 **stub 的分流照真實 payload 形狀**（ML-2b 教訓：宣告式 API 測試必須用前端真正送出的形狀）。
3. **既有守衛不得紅**：cop（前端不碰後端寫入所以天然過）、locales parity、
   mutation idempotency 靜態掃描、tenant isolation。
4. 全套：`bundle exec rspec`／`npx vitest run`／`pnpm typecheck`／`bin/rubocop`／
   `bundle exec brakeman -q`／`ruby scripts/check-doc-claims.rb --base origin/main`（🔴 **commit 後再跑**，
   它掃已提交 diff——本 session 兩次在這裡翻車）。

## 9. 一條需要注意的邊界

行內調整器的 Set to 帶 `compareQuantity`（載入值）＝把 CAS 交給伺服器；**不要**在前端做
「載入後值變了就擋 Save」的第二套檢查——一套檢查兩處實作遲早漂移，stale 就讓伺服器回碼、
前端如實顯示並重載該列。
