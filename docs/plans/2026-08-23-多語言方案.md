## 2. 業務邏輯（充分理解後的推理）

### 2.1 兩層語言，永遠兩個開關
- **介面語言**＝員工屬性（`staff_members.locale`），決定按鈕／欄位標籤／錯誤訊息；字串來自**平台 bundle**（隨版本部署、跨租戶共用）。
- **內容語言**＝商家正在編輯「哪一份譯文」；字串來自**租戶 `translations` 表**。
- 🔴 不連動：員工把介面切英文，不代表他要編輯英文版商品（67 §E.1 事故：把中文打進英文版標題）。SHOPLINE 內嵌形態天然避開這個事故——所有語言同時可見。

### 2.2 語言 ⟂ 市場 ⟂ 法域
- 語言只管文字；幣別／稅／地址／法律文本屬市場與 jurisdiction pack（鐵律 11）。
- `platform_locales` 只存語言（`zh-Hant`），**不存 `zh-Hant-HK`**；「恆帶地區」只發生在 URL 前綴與 hreflang 的**組字串函式**（67 §C.1 規則 1 的防線）。
- 同一份 `zh-Hant` 譯文，HK 與 TW 市場共用（裁定 10：內容不隨市場變）。

### 2.3 來源語言＝en 的含義（R1 的連鎖後果）
1. `products.title`／`description_html`／`seo_*`、`collections.title`／`description_html`／`seo_*` 一律是**英文**。
2. 其他四語（zh-Hant／zh-Hans／ja／fr）全在 `translations`。
3. handle 從英文標題直接 slug（D-67-H1 第 3 步），**品質閘門與 token fallback 只在英文標題本身是殘渣時才觸發**。
4. 現有資料：demo 店由 P1 建立的商品若標題是中文，**遷移時 base row 保留原文＋登記缺口**（67 §C.3(c) 步驟 3：不得清空）。→ §9 ML-0 處理。
5. 🔴 刻意的摩擦（67 §C.3(b)）：建立商品時**英文標題必填**（可短），否則 handle 與站內搜尋都無法判定語言。建立頁 UI 把 English 框放第一位並標必填。

### 2.4 SHOPLINE 形態的精確借法（2026-08-23 實測 admin.shoplineapp.com/…/products/new）
| 欄位 | SHOPLINE 2026 實測 | 我方採用 |
|---|---|---|
| Product Name | **堆疊**：`English`／`Traditional Chinese` 兩個輸入框並列，各自標語言 | 堆疊式，**來源語言（English）置頂且必填**，其餘按 `shop_locales.position` |
| Product Summary | 分頁（語言 link 列） | 我方商品層無 summary 欄（67 V-227），本輪不加 |
| Product Description | 分頁（每語言一個 RTE） | 分頁式 RTE（**一個編輯器實例＋N 個 tab**，切 tab 換綁定值，不是 N 個實例） |
| SEO Title／Description | 分頁 | 分頁式，**SEO 標題＋描述整組同一 tab**（判準：一組要一起看） |
| 提示文案形態 | 「若中文區留空，顧客只會看到英文」 | 我方自寫文案（鐵律 9），語義＝fallback 到來源語言（67 §C.4） |
| 資料形態 | `*_translations[lang]` 欄位 map | 🔴 **不採**：改用 translations 表（六稽核欄；67 §E.2-1(c)） |
| 預設語言規則 | English 恆預設不可移除、最少 2 語 | 🔴 **不採**：來源語言可改（一次性遷移精靈）、最少 1 語 |
| URL | 預設語言無前綴＋裸 `/en/` | 🔴 **不採**：恆帶地區前綴（2026-08-13 裁定、62 §I.2） |
| 刪語言保留資料、加回即復原 | ✅ | ✅ 採（`shop_locales` 刪＝`published=false`＋`enabled=false`，譯文不清） |

### 2.5 fallback（缺譯時顧客看到什麼）
`resolve(resource, field, L)`：`translations[L]` → BCP-47 截尾鏈（`zh-Hant-HK→zh-Hant`，**永不 zh-Hant↔zh-Hans**）→ base row（英文）→ 仍空：必翻欄位回英文、可選欄位（SEO）整欄不輸出。空值定義含 `<p></p>` 等語義空 HTML（RTE 初始值陷阱）。

### 2.6 過期偵測（英文原文改了，譯文怎麼辦）
每條譯文存 `source_digest`（原文正規化 SHA-256）；原文更新時同 transaction 把該欄所有語言標 `outdated`（minor/major 按變更比例）。UI 在該語言 tab 與堆疊框旁顯示「原文已更新」徽章；**過期不影響前台渲染**（仍出舊譯文），只影響後台提示與進度。

### 2.7 哪些欄位在非來源語言下必須唯讀（67 §E.3）
價格／成本／SKU／條碼／庫存／狀態／發布／handle／標籤／類別——本輪因為是**內嵌形態**（全語言同頁），這些欄位本來就只有一份，不存在「在英文 tab 改價格」的路徑；但 **SEO handle 段**要明確標示「網址不隨語言變」。

## 3. 資料庫設計（落 migration 的精確形態）

全部沿用 67 §C；這裡寫成可直接開工的版本（MySQL 8，鐵律 2：業務表帶 `shop_id` 且複合索引以 `shop_id` 開頭）。

### 3.1 `platform_locales`（平台字典；豁免 `shop_id`——跨租戶共用，白名單需同步 CLAUDE.md 鐵律 2 與 71 §A G24）
```
tag VARCHAR(35) PK ｜ language CHAR(3) ｜ script CHAR(4) NULL ｜ region CHAR(2) NULL
endonym VARCHAR(64) ｜ direction ENUM(ltr,rtl) ｜ plural_rule ｜ date_format_id ｜ number_format_id ｜ collation ｜ status
```
**種子五列**：`en`(English) ／ `zh-Hant`(繁體中文) ／ `zh-Hans`(简体中文) ／ `ja`(日本語) ／ `fr`(Français)。
🔴 標籤驗證：拒裸 `zh`、拒 `zh-TW`/`zh-CN`（用 script 不用 region）、大小寫寫入層正規化。

### 3.2 `shop_locales`（租戶啟用的語言）
```
shop_id ｜ locale_tag FK ｜ is_source BOOL ｜ published BOOL ｜ enabled BOOL ｜ position INT ｜ timestamps
UNIQUE(shop_id, locale_tag)；UNIQUE(shop_id, source_guard) 其中 source_guard = IF(is_source, 1, NULL) 生成欄位（MySQL 模擬部分唯一）
```
規則：每店恰一 `is_source`；來源語言 `published` 恆 true 且不可刪；`enabled=false`＝下架但譯文保留（採 SHOPLINE 的「刪語言不清資料」承諾）；上限 `i18n.max_shop_locales`=20。

### 3.3 `translations`（內容譯文，商品與 Collection 共用）
```
shop_id ｜ resource_type VARCHAR(48) ｜ resource_id BIGINT ｜ locale_tag ｜ field_key VARCHAR(255) ｜ value MEDIUMTEXT
source_digest CHAR(64) ｜ outdated BOOL ｜ outdated_severity ENUM(none,minor,major)
value_source ENUM(human,machine,script_conversion,import) ｜ review_required BOOL
source_locale_tag VARCHAR(35) ｜ updated_by_staff_id NULL ｜ timestamps
UNIQUE(shop_id, resource_type, resource_id, locale_tag, field_key)
INDEX(shop_id, resource_type, resource_id, locale_tag)   -- 編輯頁/渲染批次載入
INDEX(shop_id, locale_tag, outdated, resource_type)      -- 列出某語言過期
INDEX(shop_id, locale_tag, review_required)              -- 列出未覆核機翻
```
本輪 `field_key` 射程：PRODUCT＝`title`／`body_html`／`meta_title`／`meta_description`；COLLECTION 同四鍵。
🔴 五欄 NOT NULL 才讓 UNIQUE 真正生效（MySQL NULL≠NULL）；🔴 不做 per-locale JSON blob（會毀掉欄位級 digest／outdated／進度分子／CSV 逐欄）。

### 3.4 `translation_status`（進度物化；鐵律 7 單一來源）
```
shop_id ｜ resource_type ｜ resource_id ｜ locale_tag ｜ required_fields INT ｜ translated_fields INT ｜ outdated_count INT ｜ review_pending INT ｜ updated_at
UNIQUE(shop_id, resource_type, resource_id, locale_tag)
```
寫入時機＝translations 寫入同 transaction 重算；消費者＝編輯頁 tab 徽章、商品列表翻譯欄、設定頁語言總覽三處**同一查詢**。

### 3.5 既有表的調整
- `staff_members.locale`（已存在，預設 `zh-Hant`）＝介面語言；**預設改 `en`**（R1）；值域＝平台 admin 支援的 5 語（limits 新鍵 `i18n.admin.ui_locales`）。
- `products`／`collections` 不加任何語言欄（base row 即英文）。
- `limits.yml`：`i18n.launch_locales` → `[en, zh-Hant, zh-Hans, ja, fr]`；新增 `i18n.source_locale_default: en`、`i18n.admin.ui_locales`。

## 4. API 契約（admin SPA 只打 GraphQL，鐵律 4）

### 4.1 讀
- `shopLocales { locale { tag endonym direction } isSource published enabled position }`
- `product(id) { … translations(locales: [String!]) { locale field value outdated outdatedSeverity source } }`（對齊 Shopify `Product.translations(locale:)` 形態，擴成多語一次取）
- `collection(id) { … translations(locales:) }` 同形
- `translationStatus` 內嵌：`product { translationStatus { locale translatedFields requiredFields outdatedCount } }`

### 4.2 寫（宣告式，與 productSet 同一筆交易）
- `ProductSetInput.translations: [TranslationInput!]`，`TranslationInput{ locale, field, value }`——
  - 缺席＝保持現值；**空字串＝刪除該譯文列**（＝回落英文）；
  - 同一 transaction：寫 base（英文）→ 計算新 digest → 寫/刪 translations → 標 outdated → 重算 translation_status → outbox 事件 `products/update` 帶 `locales_touched`。
  - lockVersion 全樹鎖**涵蓋譯文**（63 §A.4 精神：譯文是商品樹的一部分）。
- `CollectionSetInput.translations` 同形。
- 語言管理：`shopLocaleEnable(tag)`／`shopLocaleUpdate(tag, published, position)`／`shopLocaleDisable(tag)`；錯誤碼 `LOCALE_LIMIT_EXCEEDED`／`LOCALE_TAG_INVALID`／`SOURCE_LOCALE_IMMUTABLE`／`LOCALE_NOT_ENABLED`。
- 🔴 本輪**不做** `translationsRegister` 獨立 mutation（Shopify T&A 工作台形態）——SPA 只有內嵌頁一條路；日後翻譯後台（67 L11）再加。

### 4.3 驗證
- 每語言欄位長度沿用來源欄位上限（`per_field_limits_follow_source_field`）：title 255、body 64KB、SEO 70/320。
- 富文本 sanitize 白名單**每語言各跑一次**（同 `sanitize_description`）。
- `locale` 必須 ∈ 該店 `enabled` 語言，否則 `LOCALE_NOT_ENABLED`。

## 5. 後台介面語言（靜態文字五語包）

### 5.1 機制
- 目錄 `app/frontend/admin/i18n/{en,zh-Hant,zh-Hans,ja,fr}.json`，**英文檔是 key 的正典**（R1），其餘四檔 key 集合必須與 en 完全相同（CI 腳本 `scripts/check-i18n-keys.rb` 擋缺鍵／多鍵）。
- key 命名 `area.screen.element`（例 `products.edit.status.active`）；訊息格式＝**ICU 子集**（`{name}` 插值＋`plural`）——自寫 ≈80 行解析器走 `Intl.PluralRules`，**不引入 i18n 框架**（鐵律 1：未討論的重型依賴；若日後需要完整 ICU 再議 `intl-messageformat`）。
- React：`<I18nProvider locale>` ＋ `useT()`；bundle 以 Vite 動態 import 按語言 code-split；`<html lang>` 同步。
- 初始語言：`staff.locale` → `Accept-Language` 命中平台語言 → `en`。
- 切換器：topbar 帳號選單內「介面語言」，寫回 `staffUpdate(locale)`，**與內容語言無關**。
- 日期／數字格式跟介面語言（`Intl.DateTimeFormat`／`NumberFormat`）；**金額不跟**（鐵律 3/10：幣別符號與位數由市場 locale 決定，H.1）。

### 5.2 伺服端訊息
- `userErrors.message` 目前硬編繁中（`save_product.rb`）→ 改 `I18n.t("errors.product.title_blank")`，`I18n.locale` 每請求取 staff.locale；`config/locales/{en,zh-Hant,zh-Hans,ja,fr}.yml`。
- SPA 顯示時**以 `code` 為主鍵查自己的字串**（鐵律 4：code 恆有值）；`message` 只作 fallback——兩套都在、以 code 優先，避免伺服端文案與前端文案漂移。

### 5.3 翻譯品質
- 首版四語包由我方產出（機器輔助＋人工覆核），每個 key 帶 `// context` 註解檔；術語表（`docs/dev/i18n-glossary.md`）固定專有名詞（SKU／handle／SEO 保留英文，鐵律 10）。

## 6. 商品／Collection 編輯頁的多語言 UI（內容語言）

### 6.1 元件（一個契約，兩種佈局；67 §E.2-1(c)）
- `<LocalizedField mode="stacked">`：對 `shop_locales`（enabled，按 position）repeat 輸入框；每框標 `endonym`（不用國旗、不用語言碼）；**來源語言框置頂＋必填**；其餘框 placeholder「留空時顯示 English 原文」＋右上徽章（過期／機翻待覆核）。
- `<LocalizedField mode="tabbed">`：tab 列＝語言 endonym＋進度點；**單一 RTE 實例**，切 tab 換綁定值（保留各 tab 草稿於 state）；非來源 tab 上方可摺疊顯示英文原文（長文預設摺疊）。
- 資料面：兩種模式都寫 `translations` 列（`mode_does_not_affect_schema`）。

### 6.2 版面（在現有 ProductDetailPage 上擴，不重做）
- 「標題與說明」卡：標題→`stacked`；說明→`tabbed` RTE（G5 的 RTE 工具列一併落地）。
- 「搜尋引擎產品資訊」卡：✏️ 展開後 頁面標題＋Meta 描述→`tabbed`（整組）；handle 段固定一份＋說明「網址不隨語言變」；SERP 預覽隨當前 tab 語言切換。
- Collection 編輯頁（m1/collections 停泊分支接回）：標題 stacked、說明 tabbed、SEO tabbed——同元件。
- 建立態：五語皆可填（§10 C1 修訂）；English 必填；儲存一次寫全樹。
- 鍵盤：tab 列支援 ←/→；堆疊框 Tab 順序＝position。

### 6.3 dirty／SaveBar／lockVersion
- 譯文進 FormValues（`translations[locale][field]`），快照比對同現行 dirty 機制；捨棄一併還原。
- 儲存送全樹（B.4 規則 1）；伺服端 STALE_OBJECT 覆蓋譯文衝突。

### 6.4 進度與提示
- 每個非來源語言的 tab／框顯示：未填（灰點）、已填（實點）、過期（橙點＋「原文已更新」）、機翻待覆核（藍點）。
- 商品列表新增「翻譯」欄（`translation_status` 聚合：`3/4 語已完成`），篩選器「缺譯語言」。

## 7. 設定 › 語言（動態增刪語言）

- 頁面：已啟用語言列表（拖曳排序＝`position`；每列：endonym、來源語言標記、已發布 toggle、翻譯完成率、…選單：設為來源語言（走精靈）／停用）＋「新增語言」按鈕（從 `platform_locales` 選，超出 20 擋）。
- 新增語言後：**商品頁／Collection 頁下次載入即多出該語言欄位**（純資料驅動，零部署）；`translation_status` 對既有資源惰性建列。
- 停用語言：三數字確認（該語言譯文數／前台曝光市場數／未覆核機翻數）後 `enabled=false`；譯文保留；前台切換器立即移除；re-enable 即復原。
- 來源語言變更：一次性遷移精靈（67 §C.3(c)，含 dry-run 與缺譯保留原文）——**本輪只做 UI 入口＋後端 job 骨架，不開放執行**（L17 原排 M6；提前風險高）。

## 8. 前台與 SEO 的對接（本輪不做前台，但模型為它就緒）

- 渲染期唯一入口 `Translations::Resolve`（§2.5），Liquid `product.title` 等 drop 走它（67 §F.3）。
- URL 前綴恆帶地區（`/zh-hant-hk/products/<handle>`），hreflang 由 `hreflang_codes(market, locale)` 組出（62 §I.2）；`sitemap`／`llms.txt` 按已發布語言展開——這些屬 G12/67 L7，**資料層本輪就位**（`shop_locales.published` 就是它們的開關）。
- 快取：只有真的讀了譯文的片段才進 locale 維度（67 §G.2 fail-closed）。
