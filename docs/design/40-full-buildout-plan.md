# 40 — 三端全量原型與開發需求手冊 · 總方案

> 使用者指令：把 platform／admin／storefront **所有頁面原型一次做完**（UI＋交互邏輯＋註釋），三端對接逐項交叉核實 API、深挖業務邏輯防呆，並產出讓 Codex 直接填代碼的超詳細開發需求手冊。本篇是這項工程的總方案與驗收基準；執行產出見 §7 交付物地圖。

## 0. 現況缺口（為什麼要做）

| 端 | 現況 | 缺口 |
|---|---|---|
| **Storefront** | 只有首頁＋購物袋 drawer（品牌方向稿） | **缺 20+ 頁**：系列/商品/購物車頁/結帳三步/帳戶全套/搜尋/部落格/政策/404 全部沒有 |
| **Admin** | 首頁 pulse、訂單列表+詳情、商品列表、分析、設定、折扣類型選擇為完整；**21 個模組是佔位空頁** | 草稿訂單/棄單/系列/庫存/禮品卡/顧客/分群/行銷/內容四件/市場/財務/報告/實況…全部要建；商品詳情（save bar）、顧客詳情、系列詳情等詳情頁缺 |
| **Platform** | 16 區完整（33 號重建） | W5 生態層缺：代理商體系/集團連鎖/方案計費管理/上架審核/平台 BI |
| **對接** | 28 號 API 契約、35–39 平台手冊已存在 | **無機器可查的 UI↔API↔表 對照**；三端副作用一致性靠人腦 |

## 2. 「做出來」的深度標準（每一頁都要達到）

1. **可點擊**：導航、tabs、modal、表單提交（demo 態）、篩選、排序全部實際運作，不是死圖。
2. **狀態完整**：載入(skeleton)/空/錯誤/成功四態；按鈕 loading；表單驗證與錯誤文案。
3. **註釋模式**：每個有邏輯的控件掛 `data-doc`，DOCS 條目寫「功能/邏輯(含數值與出處)/實作(對接的 API 與表)」——**註釋即開發文檔**。
4. **響應式**：34 號六寬度全綠（零橫向溢出/零 console error/觸控 ≥44px）。
5. **tokens**：一律 23 §1（admin/platform）與品牌 tokens（storefront），不自創值。
6. **台灣落地**：結帳含電子發票欄位、超商取貨、NT$ 格式；酒類店 age gate。

## 3. 三端對接與 API 交叉核實（43 號＋腳本）

**方法**：建雙向對照矩陣，並寫成**可執行腳本**（`scripts/crosscheck.py`，進 CI）：

```
正向：原型每個 data-doc 控件 → 宣告其對接（GraphQL 操作 / storefront 端點 / Liquid 物件 / 資料表）
反向：28 號＋35–39 號每個 API 操作 → 至少被一個 UI 控件消費，或標記 API-only（webhook/自動化）
輸出：孤兒控件清單（UI 有、API 無）＋孤兒操作清單（API 有、UI 無）＝必須為零才過 CI
```

覆蓋四層：admin GraphQL（28 §1–14）、platform GraphQL（35–39）、storefront HTTP（28 §16：`/cart/*.js`、SRA、predictive、checkout、customer）、Liquid 物件面（26 號）。跨端副作用（凍結/關店/維護視窗在三端的表現）沿 35 §3 逐條驗證。

## 4. 業務邏輯防呆（44 號）

集中成冊：①狀態機全表（訂單/出貨/退款/結帳/商店 12 態/KYC/爭議/flag，含非法轉移測試）②系統不變量（庫存恆等式、refund≤captured、金額同源、審計 append-only、無資金池）③併發要害與鎖策略（超賣/折扣用量/退款上限/重複 webhook/同時扣款）④冪等鍵一覽表 ⑤跨端一致性（35 §3 擴充）⑥時區/幣別/發票的坑 ⑦每條配對「會出什麼 bug + 怎麼測」。

## 5. 開發需求手冊（45 號）

組裝層（不重複內容，只做**施工序**）：每個里程碑 → 每一頁 → 固定填充順序 `migration → model → service → GraphQL → React 頁面 → 測試 → docs/dev`，每步指向精確章節（22/26/28/34/35–39/41/42/43/44）。含三端頁面總表×建置狀態×驗收出處，Codex 拿到任何一頁都能在 5 分鐘內定位到全部所需規格。

## 6. 執行順序（本輪一次跑完）


## 8. 驗收定義（整包完成的判準）

1. 三端母清單每一頁都可在原型中點到，交互達 §2 深度標準。
2. 34 號六寬度驗證：三檔原型全部零溢出、零 console error。
3. 註釋覆蓋率：每個新控件有 DOCS 條目（腳本統計 data-doc 與 DOCS key 差集＝空）。
4. `crosscheck.py` 跑出孤兒控件＝0、孤兒操作＝0（或明確標記 API-only/UI-later 並有理由）。
5. 44 號每條不變量都有「測試怎麼寫」；45 號每頁都有完整施工序。
6. GitHub/本機/artifact 三處同步，HANDOFF §4/§6 掛接完成。
