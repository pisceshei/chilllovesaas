## 0. 排查方法（可重跑）

全部結論由下列命令導出，任何人可在 HEAD 複驗：

```bash
# ① 各文件的 CSS 量測密度（px 值數／色值數）
for f in docs/research/*.md docs/design/23-*.md docs/design/34-*.md docs/design/48-*.md; do
  printf "%-46s %5s %5s\n" "$(basename $f)" \
    "$(grep -o '[0-9]\+px' "$f" | wc -l)" "$(grep -oE '#[0-9A-Fa-f]{6}\b' "$f" | wc -l)"
done

# ② 量測文件引用的 token vs tokens.css 實有
#    🔴 have 必須用「--name: 的冒號前」抓，**不能用行首錨**——tokens.css 大量把多個
#       token 寫在同一行以 ; 分隔，行首錨只會抓到每行第一個（223 個裡只看得到 131 個）。
#    🔴 cited 要排除 --p-*（本尊命名空間，是事實記錄不是我方 token）
#       與散文殘尾（如正文寫 --sp- 泛指整階）。
python -c '
import io, re, glob
have = set(re.findall(r"(--[a-z0-9-]+)\s*:", io.open("app/assets/tokens.css", encoding="utf-8").read()))
cited = set()
for f in glob.glob("docs/research/8[012]-*.md") + glob.glob("docs/research/73-*.md") + glob.glob("docs/research/91-*.md"):
    cited |= set(re.findall(r"--[a-z0-9-]+", io.open(f, encoding="utf-8").read()))
cited = {c for c in cited if not c.startswith("--p-") and not c.endswith("-") and c != "---"}
print(f"have={len(have)} cited={len(cited)} missing={len(cited - have)}")
for m in sorted(cited - have): print(" ", m)
'

# ③ 各 CSS 三段式節內的量測列數（節內，不是全檔）
for spec in 80-admin-analytics.md:446 81-admin-settings.md:241 82-admin-channels.md:274; do
  f="docs/research/${spec%%:*}"; start="${spec##*:}"
  end=$(awk -v s="$start" 'NR>s && /^## /{print NR; exit}' "$f")
  echo "$(basename $f): $(sed -n "${start},${end}p" "$f" | grep -c '^| [0-9]\+ |') 列"
done
```

> ⚠ 行號是易腐值（鐵律 20.2③）。上面的起始行號是 2026-08-28 的快照；
> 節位置改版後改用 `grep -n "CSS 三段式" docs/research/*.md` 重取。

## 3. 映射欄是空頭支票（本次排查最重的發現）

`73`／`80`／`81`／`82`／`91` 的「我方 token」欄共引用 **46** 個我方 token 名
（已排除 `--p-*` 本尊命名空間與散文殘尾），
其中 **27 個在 `app/assets/tokens.css` 的 223 個 token 裡不存在**：

```
--bd --bd-subdued --bg-critical --bg-hover --bg-inverse --bg-selected --fg-subdued
--font-mono --fs-100 --fs-75 --fw-600 --fw-semibold --h-chip --h-row --h-row-lg
--h-row-sm --lh-125 --lh-140 --lh-150 --num-tabular --sp-500 --sp-800 --w-menu
--w-modal-md --w-modal-sm --w-overlay --w-popover
```

⚠️ **本節數字曾寫錯過一次**（初稿記「131 實有／50 引用／31 缺」）。
根因＝`have` 用**行首錨** grep，而 `tokens.css` 大量把多個 token 寫在同一行以 `;` 分隔
⇒ 223 個裡只看得到 131 個；`cited` 則誤含 `--p-*` 與散文殘尾。
**發現本身不變**（映射欄大半指向不存在的 token），數字已依 §0 ② 的命令重算。

⇒ **量測做了、映射寫了、但沒有一行 CSS 真的用到它們**。
這是「整體 UI 不協調」的機制性根因：量測與實作之間沒有可機械檢查的接線。

**配套建議（登記，不在本輪動工）**：`docs/specs/91-pit-register.md` §2 已有 G-06（CSS 幾何閘門）候選；
本發現應併入該候選的射程——閘門要能斷言「量測文件引用的每個 `--token` 都存在於 `tokens.css`」。
新增機械閘門依鐵律 20.4 須先取得使用者裁定並另開 18.3 PR。

### 7.3 語義色：整族重造

`47` §H2-1 的做法是「取 CHILL LOVE 自有 5 個語義色相，套上量到的明度公式生成」。
結果與本尊差距最大：

| 族 | 我方 fill | 本尊 `bg-fill-*` | 我方 text | 本尊 `text-*` |
|---|---|---|---|---|
| critical | `#db243c` | `#c70a24` | `#921c2b` | `#8e0b21` |
| success | `#158468` | `#047b5d` | `#13634f` | `#014b40` |
| info | `#1e78b8` | `#91d0ff` | `#195885` | `#003a5a` |
| caution | `#847115` | `#ffe600` | `#675914` | `#4f4700` |
| warning | `#af5c1d` | （本輪未取得） | `#814618` | （未取得） |

🔴 **`info` 與 `caution` 的 `fill` 差最遠**：本尊的 `bg-fill-info` 是**淺藍** `#91d0ff`、
`bg-fill-caution` 是**亮黃** `#ffe600`——都是**淺色實填**（配深色前景）；
我方生成的是**深色實填**（配白字）。這不是色相差異，**是配色模型不同**，
照著換值前必須先確認本尊那兩個 fill 實際用在哪個元件上（本輪未取得使用現場）。

🔴 **族數對不上**：`47` §H2-1 記本尊是 5 族，我方也做了 5 族；
但完整抽取後本尊實際是 **7 族**——多出 `highlight`（`#f0f2ff` 系）與 `ai`（`#f8f7ff` 系），
我方**兩族都沒有**（`111` §14.3）。

🔴 **配色模型分兩種**：本尊的 `warning`／`caution`／`info` 的 `-fill` 是**淺色**（配深色前景），
`success`／`critical` 是**深色**（配白字）。我方 5 族一律生成深色實填配白字
⇒ **有三族的模型是錯的**，不只是色相差。
