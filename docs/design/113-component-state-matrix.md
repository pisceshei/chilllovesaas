### §1.3 觀察到的視覺規律

1. 🔴 **狀態＝換底色，不換幾何**：本輪量到的每一個元件，default→hover→focus→disabled 全程 **圓角、尺寸、內距、border-width 一律不變**，只有 background／color（少數再加 outline）改變。沒有任何元件在 hover 時長出 border 或改變陰影層數（primary 按鈕 hover 時 box-shadow 逐字元相同）。
2. :focus-visible **不是獨立配方，而是「hover 底色 ＋ 2px 外環」的疊加**。primary(#1a1a1a)、secondary(#d4d4d4)、tertiary(rgba(0,0,0,.05)) 三個變體在 focus 時的底色，與各自 hover 底色逐一相同（已在滑鼠移開、matches(':hover')===false 的條件下複測確認，排除 hover 殘留）。
3. **全站只有一種焦點環**：`outline: 2px solid #005bd3` + `outline-offset: 1px`，用在按鈕、連結、文字欄位外盒、搜尋列。沒有第二種尺寸或顏色。
4. **disabled 一律不用 opacity**：radio、tertiary 按鈕、primary 按鈕、分頁器的不可用態，computed opacity 全部是 1。變灰靠換 color（→#b5b5b5）與換底色（→rgba(0,0,0,0.17) 或 rgba(0,0,0,0.08)），primary 另把 box-shadow 直接抹成 none。
5. **cursor 在 disabled 時是 default / auto，從來不是 not-allowed**（tertiary disabled = default，primary disabled = auto）。
6. 🔴 **「不可用」有兩種實作，語意強度不同**：①真 disabled（primary Post 鈕：繪製盒帶 disabled 屬性）②純視覺變灰（分頁器 Previous：disabled=false、aria-disabled 未設、cursor 仍 pointer、底色不變，只把圖示 color 換成 #b5b5b5）。照抄同一套會與本尊不一致。
7. **28px 是絕對主導的控件高度**：按鈕（3 變體全部）、icon-only 按鈕（28×28）、badge size-large、下拉選項列、側欄導航項、分頁器按鈕、篩選列——全是 28。文字欄位的輸入盒是**唯一的 32px**。badge size-base 是 20。
8. **圓角只有三階在用**：8px（幾乎所有控件：按鈕、badge、選項列、導航項、tooltip、banner-A、輸入盒、checkbox 除外）／12px（浮層與容器：popover、banner-B 卡片、導航容器）／16px（僅 Modal 面板）。checkbox 是 4px、radio 是 50%。
9. 🔴 **浮層陰影只有兩種配方，且分工明確**：Popover 與 Tooltip 用**完全同一份 6 層**（末層 `rgba(0,0,0,0.06) 0 0 0 1px` 當 1px 描邊代替 border）；Modal 面板反而只有 **1 層有效陰影**且**沒有描邊層**。越大的浮層陰影越簡單，與直覺相反。
10. **沒有元件使用 border 畫外框**：所有量到的繪製盒 border-width 都是 0px。框線一律用 inset box-shadow 或 outline。輸入類控件（text field、checkbox、radio）共用同一條 **0.66px inset 髮絲環**（#8a8a8a），focus 時才升級為 1px（#1a1a1a）。
11. **hover 的移動方向不一致**：實體填色按鈕 hover 變**深**（#e3e3e3→#d4d4d4、#303030→#1a1a1a），透明底控件 hover 變**淺灰**（transparent→rgba(0,0,0,.05) 或 #f7f7f7），而側欄導航的 **hover(#f1f1f1) 比 selected(#fafafa) 更深**。
12. **Badge 的色彩配方是 `bg-fill-{tone}-secondary` 值 ＋ `text-{tone}` 值**（caution #ffeb78/#4f4700、success #affebf/#014b40 兩例一致），而不是名稱最像的 `--p-color-badge-bg-fill-{tone}`（#ffe600/#047b5d）——那組 token 存在但值對不上任何實測 badge。
13. **Badge 只有兩個尺寸階**：base（高 20／字 12／內距 2·8／gap 4）與 large（高 28／字 13／內距 4·8·4·6／gap 4）。有前導圖示時左內距縮到 4px(base)／6px(large)，gap 縮到 2px(base)。圖示是 16×16 實心圖示，**沒有 pip 圓點**。
14. **字重全是非標準變數字重**：450（內文／label／說明）、550（按鈕 label／badge）、600（標題 h1/h2）、650（display/bold）。沒有 400／500／700 出現在 token 表；500 只出現在舊 Polaris React 節點（選項列、表格、導航項）——這正好是新舊兩套系統的分界訊號。
15. **新舊系統的判別法**：繪製盒在 shadow root 內、字重 450/550/600 ⇒ 新 `s-*`；class 帶 `Polaris-` 或 `_Xxx_hash_NN`、字重 500 ⇒ 舊 React。同一頁面（如 /orders）頁首是新、表格是舊。
16. **互動樣式常畫在祖先而非命中元素上**：下拉選項的 hover 底色在 `li[role=option]` 不在 `._RowContent_`；導航項的 hover/selected 底色在 `._ItemInnerWrapper_` 不在 `<a>`；焦點環在 `.input-wrapper` 不在 `<input>`。逐層往上掃是必要步驟，只量命中元素會系統性地把「有樣式」誤記成「無樣式」。
17. **transition 在兩套系統不同**：新 `s-internal-button` 繪製盒的 computed transition 是 **none**（三個變體皆是）；舊 React 的選項列 li 與搜尋列是 **all**。

6. **與 47 §4「控件高度只有三階：24 / 28 / 32（窄版），加 36（頂欄）共四階」相容但需補一階說明**：本輪 1024 寬下量到的共用元件高度為 20（badge base）／28（按鈕全變體、badge large、下拉選項、導航項、分頁器、篩選列）／32（文字欄位輸入盒）／44（banner 標題列）／53（Modal 標題列）／61（Modal 頁尾）。28 與 32 與 47 一致；**badge 的 20px 與 large badge 的 28px 未見於 47 的四階表**，建議補登。

7. ⚠️ **量測寬度不可比**：47 第三輪的桌機正式量測條件是 `innerWidth=2294 / dpr=1.5 / 截圖寬1568`，64 未在本輪查閱其環境宣告，而本檔是 `innerWidth=1024 / dpr=1`。上述衝突項全部是**與寬度無關的排版與色彩屬性**（字級、字重、底色、陰影、shadowRoot 開閉），故不因寬度差異而失效；但任何涉及版面尺寸/欄數/斷點形態的比較都**不得**跨這三份文件直接對照。

### §1.5 未取得（鐵律 19.3）

- **所有元件的 :active（按下）態** —— 原因：CSS `:active` 只由受信任的指標事件觸發，JS 派發的 mousedown 是 untrusted、不會套用；`computer` 工具只有 left_click／left_click_drag，都會在同一次動作內完成 mouseup，無法在按住期間取值。已取得的替代證據僅為 token 值（bg-fill-brand-active #1a1a1a、tertiary-active #ccc、transparent-secondary-active #0000001c，及 --p-shadow-button-inset／button-primary-inset 的 3 層/1 層 inset 值），**但這些 token 與 :active 的綁定關係未經量測證實，不得寫成事實**。取得方式：用 CDP `Input.dispatchMouseEvent{type:'mousePressed'}` 後不送 mouseUp，再 getComputedStyle；或 DevTools Elements 面板的 :hov → force `:active`。
- **Toast 全部屬性**（底色／文字色／圓角／陰影／內距／位置／寬度） —— 原因：唯讀約束禁止寫入動作，而 Toast 在本版 admin 只由寫入結果觸發。已證實「複製到剪貼簿不發 Toast」（點 Copy email 3 次後掃描 fixed 定位元素、class 含 toast、內文含 Copied 三種條件皆 0 命中）。已知 Toast 元件確實存在（:root 有 `--pc-toast-manager-translate-y-out`、`--p-shadow-toast`＝7 層）。取得方式：做一次可還原的寫入（改商品標題→存檔→改回），Toast 出現後 3 秒內量測。
- **輸入框 error 態與 disabled 態** —— 原因：error 需送出非法值（屬寫入），disabled 輸入框在本輪 5 個頁面無實例。相關 token `--p-shadow-input-error` / `-error-focus` / `-critical` / `-disabled` 在 :root 上**取值為空字串**（我第一次用 split 計層數時把空字串誤算成「1 層」，已更正），代表它們不在 :root 作用域。取得方式：在 settings 表單清空必填欄位觸發驗證（會產生未存檔的髒狀態，需使用者授權），或找本來就 disabled 的欄位（如已鎖定的方案/帳單欄位）。
- **Badge 的 tone-critical / tone-info / tone-warning / tone-attention** —— 原因：本店現有資料未產生這些狀態的訂單或商品；本輪掃過 /orders、/orders/7145469575403、/orders/7080261746923、/products 共 4 頁的全部 s-internal-badge，實際出現的 class 只有 5 種組合（size-base|large × tone-auto|caution，加 tone-success）。取得方式：開已取消／已退款訂單，或庫存為負／草稿商品。
- **按鈕 variant=critical 與 variant=plain** —— 原因：本輪頁面未渲染該變體。取得方式：開含破壞性動作的選單（訂單 More actions → Cancel order，或商品詳情底部 Delete），**只開不按**。
- **Checkbox 的 checked / indeterminate / hover / focus / disabled** —— 原因：勾選會改變列表選取狀態並喚出批次操作列，唯讀約束下未點擊。只取得 unchecked 態。取得方式：勾選再取消勾選（純前端選取狀態，不寫入資料庫），或找預設已勾選的設定頁選項。
- **Radio 的 hover / focus 態** —— 只取得 unchecked / checked / disabled 三態。
- **帶插圖與帶 CTA 的空態變體** —— /checkouts 的空態只有標題＋說明兩層，無插圖、無按鈕。插圖尺寸因此**未取得**。取得方式：查其他空列表頁（Gift cards、Transfers、Purchase orders）。
- **分頁器 Previous/Next 的 hover／focus／active** 與「載入更多」形態 —— 只取得 default 與視覺不可用態。
- **麵包屑返回連結的 hover／focus** 與 Modal 遮罩點擊行為。
- **1280 / 768 / 390 三寬度的並排對比（鐵律 13.1）** —— 本輪僅在 innerWidth=1024 單一寬度量測，原因見 environment（多代理共用同一實體視窗，resize 會污染他人量測）。本檔所有數值**不得**被引用為「桌機 1280 已驗證」。
- **s-* 元件的 CSS 規則來源** —— 依任務硬約束 6 與鐵律 9，全程只讀 getComputedStyle 的結果值，未讀取 styleSheets／cssText／class 定義，因此無法（也不應）陳述某個值「引用哪個 token 變數」；tokens 段落中的對應關係一律只是「量到的顏色等於該 token 的值」。
