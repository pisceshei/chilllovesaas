## 已完成的工作 (Done)

1. **更正 `claude-review.yml` 中兩處錯誤斷言**（第 15 輪隨 `325ce62` 進 main、未經任何驗收方）。
   原文：「直接把核准釘在 `$HEAD_SHA` 上：head 若已前進，這則核准就屬於舊 commit，
   分支保護的 dismiss-stale 會自然忽略它，**不再需要賭時間窗**。」
   🔴 **官方文檔不支持這個推論**。`POST /pulls/{n}/reviews` 的 `commit_id` 逐字定義是
   「The SHA of the commit that needs a review. Not using the latest commit SHA may render
   your review **comment** outdated if a subsequent commit modifies the line you specify as
   the position.」（來源：docs.github.com/en/rest/pulls/reviews，取證 2026-08-19）
   ⇒ 它管的是**留言的行定位**，不是核准對分支保護的效力；而 dismiss-stale 是
   **推播事件撤銷全部核准**，與 `commit_id` 指向哪個 commit 無關。
   ⇒ **check-then-act 的競態沒有被關掉**，只是窗變小＋留下「評估的是哪個 commit」的可稽核紀錄。
2. **登記現況實測**：`gh api repos/pisceshei/chilllovesaas/branches/main/protection` 回
   **404 Branch not protected** ⇒ `main` 未設任何分支保護、**核准目前不構成閘門**，
   本項風險現在是**惰性**的；一旦啟用 required approving review 就會活過來。
3. `docs/dev/m0-automation-infra.md` §2.2 同步更正（此前該篇也照錯誤斷言描述）。
