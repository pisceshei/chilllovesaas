## 補審第三輪（2026-08-19；#60 四條點名，**先派研究上網查證再修**）

🔴 **第二輪寫下的「✅ 真正的解＝`require_last_push_approval`」又被推翻——這是同一個
斷言連續第三次寫錯。** 前兩次錯在憑推論寫肯定句，這一次錯在**方向與官方敘述相反**。

**研究結論（4 個代理、183 次工具呼叫，取證 2026-08-19）**：

- **[1] 核准競態**：主張成立。官方在 branch protection 與 rulesets **兩頁逐字重複**：
  「with this option, "stale" reviews are **not dismissed**」——該規則的設計本意就是
  **容忍核准指向舊 commit**；同段結尾更直說「**If you are concerned about pull requests
  being "hijacked"**…**it is safer to dismiss stale reviews**」⇒ 官方自承它在本情境
  **比 dismiss-stale 弱**。⚠️ 它的判準（比 `submitted_at` 還是比 review 綁的 commit）
  **官方從未公布**（窮舉 docs 四頁＋兩則 changelog＋GraphQL schema）⇒ 兩種讀法都不得押注。
  🔴 但驗收方只說「這個也不成立」而沒給替代方案，照做會停在「無解」——**其實有解**：
  官方逐字「Required checks must pass on **the latest commit SHA**. **Checks from earlier
  commits don't satisfy the requirement.**」⇒ **required status check 依構造綁 commit
  且 fail-closed**，這正是核准做不到的事。已寫進註釋（含「不得直接把現有 `review` check
  當 required」——它的 success ≠ 驗收通過）。
- **[2] deadline 沒有真的有界**：三條全中，且量到反例——`DEADLINE_S=1`、`INTERVAL=20`
  實測 **21 秒**才 exit 5；預設值下最壞牆鐘約 11.8 小時 vs 檔頭宣稱的 4 小時。
  🔴 **修法形狀與驗收方描述的不同**：它寫「只在每輪開始時檢查」，最直覺的修法是加檢查點
  ——**那一秒也省不下來**，根因是**睡眠時長沒有被剩餘預算約束**，正解是 clamp。
  🔴 另一處若照字面修會踩官方紅線：夾斷 `wait_for_reset` 後若 `continue`，等於在還沒等到
  reset 時繼續發請求＝官方明文警告的封鎖條件 ⇒ 夾斷一律 exit 5。
  ⚠️ 研究另指出驗收方**漏了第四個洞**（單次 `fetch_state` 自身不受預算約束）——
  **本輪未修**（未被點名），已在檔頭與 `docs/dev` 明寫為已知殘留。
- **[3] Changes 表**：主張成立。原表把整輪寫成「代碼行為未動」，而第二輪確實改了代碼；
  另缺 `scripts/await-verdict.sh` 與 `docs/handoff/…` 兩列。已依 `git show --stat` 逐
  commit 重建。🔴 研究建議的機制化（加 CI 規則驗「該寫的有沒有寫」）**不採**——
  使用者已裁定不再機制化；改以表上方的複驗指令留痕。
- **[4] fail-closed 分支不可達**：主張 **PARTIAL**——「根本不可達」字面不成立
  （first-query 回 `pending` 時確實會執行），但要害那一半完全成立：
  `[ "$CHECKS_STATE" = "pending" ] || break` 讓 `allgreen` 第一輪就 break ⇒ 守衛零覆蓋。
  C3 的狀態共七個：`empty`／`pending`／`allgreen`／`notgreen`／`apifail`／
  `pending-timebudget`／`skipped-no-watermark-ts`，其中**只有 `allgreen` 令 C3=1**
  （複驗：`git grep -n -F -e 'CHECKS_STATE" = "allgreen" ] && C3=1' -- ':/.github/workflows/claude-review.yml'`），
  而 `allgreen` 正是那個 `|| break` 第一輪就跳出的分支。
  配上 C2 的 `${WATERMARK_TS:-0}` 退成 0（jq 實測 CAND 由 0 變 1，時間窗變 no-op），
  交叉表實測復現 `1111 → APPROVE`。
  已改為評估器入口統一前置（`TS_OK`），並刪除變成真正死碼的舊分支。
