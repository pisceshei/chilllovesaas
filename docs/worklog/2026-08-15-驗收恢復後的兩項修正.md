### 3. 補上驗收方的能力缺口：它想實跑，但被我方設定擋住

恢復後第一次驗收（PR #41，run 31870676748）的 log 裡有 **8 次 `permission_denied`**，
被擋掉的逐字是：

```
bash scripts/check-exec-bits.sh
bash scripts/test-exec-bits-rules.sh
sed -n '1,80p' HANDOFF.md | head -5; echo "..."      ← 複合指令，`;` 後半段不在清單裡
```

於是它只能在留言開頭聲明「本輪沒有實跑證據……兩者皆未執行」。
⇒ 🔴 **這是我方設定造成的能力缺口，不是它偷懶。**
本專案的驗收文化是「破壞那一步本身也要有斷言」，而驗收方連跑一次都不行。

✅ 同一份 log 也證實 `git ls-files -s` **當時是通的**（44 行真實輸出，
格式 `100755 <40 位 sha>`）⇒ 它宣稱的旁證是真的，沒有造假。這一點我特地查過才寫。

**修法**：`--allowedTools` 加上 `Bash(bash scripts/:*)`／`Bash(ruby scripts/:*)`／
`Bash(python scripts/:*)`／`Bash(python3 scripts/:*)`，並明文列出 `git ls-files`／`git show`。
prompt 同步加一段「你可以實跑，請盡量跑」，含三條約束：複合指令要分開呼叫、
不得寫檔／commit／push（突變測試在 `$TMPDIR` 造 fixture）、跑不動要明說並登記「未覆蓋」。

🔴 **安全取捨，刻意寫在 workflow 註釋裡**：這等於讓驗收方**執行被審 PR 帶進來的代碼**，
而該 job 握有 `contents: write`／`pull-requests: write` 與 OAuth token。
⇒ 因此**只授權 `scripts/` 底下**，不給裸的 `Bash(bash:*)`。
本倉庫 private、單一作者，威脅模型有限；**日後開放外部貢獻者或轉 public，這一組必須先撤掉**。

### 4. 🔴 依 PR #43 的 Codex review 再修兩條——兩條都是我的錯

#### ① 「根因就是模型」是**先後對照，不是受控對照**

Codex 逐字：

> 若上游故障在 attempt #4 與後來那次之間恢復，即使模型改動無關，
> 這個先後對照也會產生一模一樣的結果；**時間與模型是一起變的**，
> 而這裡既沒有反向的 Fable 重跑，也沒有模型專屬的錯誤訊息。

**它是對的。** 而且這正是我今天自己寫進 worklog 的那條紀律：
「觀察到 A 之後出現 B 時，先問沒有 A 的時候是不是也有 B」——
我把它用在別人的證據上，沒用在自己的結論上。
⚠️ 而且同一段上方的註釋還寫著「不要當成已確認的修復」，**同一份檔前後矛盾**。

**修法**：✅降級成 🟡 假説，並寫出確認它的**兩條路**：
① A/B/A（改回 fable-5 重跑，確認再次秒殺）——代價是還得進 main、把所有分支再失效一輪，
**不值得為了好奇心而做**；② 下次失敗時由 `show_full_output` 帶出的錯誤原文確認。
判準表與優先順序也一併改成「**排進優先檢查項**」而不是「一定是它」。

#### ② prompt 給了一條**不可能被遵守**的指示

原文寫「要做突變測試就在 `$TMPDIR` 造 fixture」，同一行又寫「你不能寫檔」，
而 `allowedTools` 既沒有 `Write` 也沒有任何能建檔的指令。
⇒ 驗收方只能把「最有價值的那一種驗證」寫進未覆蓋，而那本來就是我叫它做的事。

**修法**：不給寫檔權限（刻意：本 job 有 `contents: write` 與 OAuth token），
改成**明講「這種突變測試你做不到」**，並要求它在「未覆蓋」段
**具體寫出該怎麼突變**（改哪一行成什麼），讓人可以照著跑。
