   ⇒ 我方接受的形態集合**全部標 ours**，不得寫成「對齊 Shopify」。

證據全集（含逐字原文與 URL）落 `docs/dev/external-facts.md` §D1–D8。

### 🔴 注入面的主防線在資料層，不在樣板層

`javascript:` URL 放進 `<iframe src>` 是合法導航脈絡，而 MDN 逐字載明該 script
**繼承載入它的文件的 origin** ⇒ 那是在我方 origin 執行的完整 XSS（讀得到 admin
cookie、打得到 admin API）。`data:` 拿到 opaque origin、偷不到 cookie，但仍可在
我方頁框內渲染攻擊者完全控制的 HTML。

⇒ `Catalog::ExternalVideoUrl` 的設計目標就是**讓使用者字串永遠到不了 `src`**：
落庫的只有一個封閉值域的 `host`（youtube／vimeo）與一個受字元集約束的 `external_id`，
其餘（`?si=`、`&list=`、`&t=`、fragment、userinfo）**一律丟棄**。
`origin_url` 與 `embed_url` 都由 limits 樣板**重建**。CSP `frame-src` 白名單
（第 33 包）是第二道，不是第一道。

### 🔴 embed URL 導出不落庫

隱私決策（youtube-nocookie、Vimeo `dnt=1`）會變。落庫＝改設定之後舊資料還停在舊網域，
要跑 data migration 才救得回來；導出＝翻一個 limits 鍵全店立刻生效。

### 🔴 D48 的窄縫：外嵌影片的 alt 住在媒體列

D48 把 alt 權威搬到 `files.alt_text`（一張圖一份說明）。**但外嵌影片沒有檔案**
——它的 alt 無處可住，除非用回 `media.alt_text` 那個 D48 剛停用的欄位。

處置＝開一條**只認 `media_type == 'external_video'`** 的窄縫。
🔴 **不得放寬成「file 為 nil 就回落」**：那樣 D48 停用的舊語義會從 M0 遺留圖片列
的後門復活。已下反向 spec 釘住（沒有檔案的**圖片**列仍然回 nil）。

同理 `status` 也要分支：A 面外嵌沒有 `stored_file`、湊巧落到 `object.status` 而正確，
但 B 面一旦把縮圖檔掛上 `file_id`，**媒體狀態會被縮圖檔的狀態冒充**——影片好好的、
縮圖還在處理，卡片卻顯示「處理中」。現在就分開，B 面不必回頭改。

### 🔴 兩個 limits 鍵，不是一個

`upload_media_types_enabled`（可上傳）與 `embed_media_types_enabled`（可外嵌）
**是不同的事**。合併成一鍵會把 B9 的閘門一起弄鬆——那個閘門正是靠
`upload_media_types_enabled == [image]` 擋住影片上傳的，而 `m0_configuration_spec`
釘死了它。`MediaContentTypeEnum` 改成兩鍵聯集，`upload_*` **一個字都沒動**。

### 其他

- `media` 表只加兩欄（`external_host`／`external_id`），其餘複用：
  `media_type`／`source_url`（＝重建後的 origin URL）／`alt_text`／`file_id` 恆 NULL。
  🔴 **不另開 `external_origin_url` 欄**：`source_url` 是 `null: false`，另開欄就得在
  `source_url` 塞無意義佔位值——那才是真正的兩套真相。
- **不建 `files` 列、不寫 `file_usages`**：`files` 的 `byte_size`／`checksum`／
  `content_type`／`storage_key`(unique) 全是 `null: false`，塞一個沒有 bytes 的實體
  就得把那些 NOT NULL 全部可空化＝拆掉既有防線。代價＝外嵌不進檔案庫（本尊是否如此
  ＝未取得），登記 V。
- 順手修一條鐵律 6 違反：`Media` 的 `alt_text` 長度上限原本硬編 512，而
  `media.alt_max_length` 這個鍵早就存在。外嵌讓 `alt_text` 從停用欄變成**承重欄**，
  這條守衛因此落進本包的根因半徑（17.2／20.5 同元件狀態矩陣）。
- 前端：媒體卡多一個「嵌入影片」入口（**與上傳分開**——影片不是上傳，放進同一個
  檔案選擇器會讓人以為可以傳影片檔）＋貼 URL 的 modal；`MediaThumb` 多一個影片分支
  （顯示平台名＋播放圖示，不是「處理中」）。
  🔴 **前端不驗 URL 形態**：判準只有一份、在後端。前端再寫一套 regex，兩份遲早漂移，
  症狀是「前端說不行、後端其實可以」這種查不出來的假錯誤。
- i18n 五語各 +5 鍵（前端）＋4 鍵（`config/locales` 的錯誤訊息）。
- 測試：rspec **+21 例**（`external_video_url_spec` 28 例含 9 個攻擊形態、
  `external_video_media_spec` 12 例）、vitest **+4 例**。
  🔴 **14 道新守衛全部做過突變驗證**（逐一刪掉再跑，確認轉紅）。
  其中 model 層三條**第一次驗是 GREEN**——因為服務層先把壞 URL 擋掉了，只走 GraphQL
  的測試碰不到它們；補了直接打 model 的例子才測得到。
