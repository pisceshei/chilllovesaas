### 推翻一個既有結論：本尊**有** max-width，我們量錯了層

`111` §16.1 原記「2026 版 s-internal-page 框架在頁面層不設內容區 max-width，內容欄是流體寬度」。

**前提正確**（`main.page` 與 `.page-content` 的 computed 確實是 `max-width: none`，已複驗），
**結論錯誤**：上限在**再下一層 shadow root** ——
`main.page` → `<s-grid>`（`display: contents`）→ `<span class="grid">`，
由 s-grid 的**元素屬性生成 per-instance `<style>`**：

```
@container s-internal-page (inline-size >= 784px)
  "minmax(480px, 638px) minmax(240px, 312px)", "minmax(auto, 966px)"
```

搭配 `justify-content: center`：grid 盒本身恆 100% 寬，被置中的是 **track**。
⇒ 置中在**該 track function 生效的每一個容器寬**都成立（窄容器時 track 已滿寬、看不出來），
不是某斷點以上才出現。**射程＝套用該 track function 的頁面**；首頁 `/` 與 `/themes`
不用這套框架（前者改用 `max-width: 1000/640/490` ＋ flex 置中且由 media query 開關，後者是跨源 iframe）。

🔴 **這是本專案第三次同型事故**（見下方 20.2 掃描表）。

### 🔴 一顆刻意不做的 token

收合門檻 **752 不做成 token**。`@container` 與 `@media` 的條件式**不能用 `var()`**，
而且失敗方式是 **fail-open**——Chrome 151 實測：

```
@container t (width < var(--th))
  → 解析成 CSSContainerRule，conditionText 正常，帶 1 條子規則
  → 但 computed 停在字面值那條，永遠不匹配
```

DevTools 裡看起來完全正常。做成 token 只會製造一顆死 token ＋一條看不出來的失效規則。
**本尊自己也踩同一條限制**：`--p-breakpoints-*` 五顆全站零消費，
真正驅動響應的是建置期展開的字面 media query（源碼複驗）。

### 🔴 本輪撞到的工具鏈陷阱（鐵律 20.2⑦，記憶條目 `publish-machine-output` 的新變體）

既有教訓是「含反引號的內容要用 quoted heredoc（`<<'PY'`）」。**本輪撞到的是它的變體**：
要寫入的**內容本身含有 `<<'PY'`** ⇒ 那一行的 `PY` 把**外層** heredoc 提前終結，
剩下的字串被 shell 當命令逐行執行（本輪因此意外跑了一遍驗證腳本與 lint）。

✅ **固定處理**：外層 heredoc 用**不會出現在內容裡**的分隔符（例如 `<<'PYOUTER'`），
或把內容先寫成檔案再讀。Python 端也因此吃到 `SyntaxWarning: invalid escape sequence`。

⚠️ **這次沒有造成髒資料**：腳本死在 `io.open(...).write()` **之前**，worklog 未被寫入；
意外執行的都是唯讀命令。但下次未必——**寫入型腳本被攔腰截斷是會留下半份檔案的**。

### 🔴 本輪自己踩了兩次 fail-open（鐵律 20.2⑤，都在「驗證自己的宣稱」這一步）

**第一次｜`\b` 被寫成 backspace 字元。** 我在**非 raw** 的 Python 字串裡寫 `\b`，
Python 把它當成合法跳脫（0x08 backspace）寫進 worklog ⇒ 檔案裡是**兩個看不見的控制字元**，
終端顯示時被吞掉，肉眼與一般 grep 都看不出來（`cat -A` 才顯示 `^H`）。
於是「把發布的片段原樣抽出來跑」得到 `0 0 0`——**但那個 0 是因為正則變成
`\x08(?:633|317)\x08`、CSS 裡不可能有 backspace，永遠回 0**，不是因為舊值真的不見了。

**第二次｜修好之後，`\b633\b` 仍然抓不到 `633px`。** `\b` 要求邊界，而 `633px` 的
`3`→`p` **兩邊都是字元、沒有邊界**。⇒ 這條檢查從一開始就**結構上不可能命中任何東西**。

**兩次都是「預期為零的檢查回報零」——而它回零的理由與我以為的完全無關。**

✅ **固定處理（已寫進上面的 B 區塊）**：
1. **任何「預期為零」的檢查，必須同時跑一個 canary**——用一個**一定存在**的值
   （這裡是新值 638／312）走**同一條正則路徑**，證明它抓得到東西。
   canary 為 0 就 `assert` 失敗，不讓那個 0 被當成通過。
2. 寫入含反斜線的內容一律用 **raw 字串**（`r'...'`），或用 `chr(92)` 明寫。
3. 落地後用 **`cat -A`** 或掃 `ord(c) < 32` 確認沒有控制字元混進 tracked 檔。

**本輪 canary 實際輸出＝4**（tokens.css 2 ＋ 原型 2；admin.css 0 是對的，
它只用 `var(--col-*)` 不寫字面值），**舊值 0**。這才是可以採信的「已歸零」。
