## 已完成的工作 (Done)

### 1. Migration ＋ schema

`20260816000000_create_product_variant_option_values.rb`：三張父表補唯一索引、
`product_variants.option_values_digest`、join 表、五支外鍵。已在真 MySQL 8.4.9 上
`migrate` → `rollback` → `migrate` 走過一輪，`schema.rb` +26 行。

🔴 **MySQL 8.4 的複合外鍵限制**（實測，不是查文檔）：`restrict_fk_on_non_standard_key = 1`
是**編譯預設**，被指向的欄位組必須**逐字、同順序等於某支 UNIQUE 索引的完整清單**
——最左前綴 `ERROR 6125`、欄序不同也 `ERROR 6125`。
⇒ 既有的 `uq_*_tenant_id (shop_id, id)` 與 `uq_product_options_product_id_name`
**都無法**讓外鍵指向 `(shop_id, product_id)`。那三支新唯一索引不是順手加的，是**必要條件**。

🔴 **digest 欄分三步加**（可空 → 明文回填 → 收緊），不是一步 `null: false`：
MySQL 在 STRICT 模式下對既有列會**靜默填 `''`**，那會寫進一個不是 SHA1 的假 digest。

### 2. `Catalog::OptionValuesDigest`（digest 的唯一產生處）

依 `product_option_id` 升冪 → `"選項id:值id"` → `,` 相接 → SHA1。

| 事件 | digest | 為什麼 |
|---|---|---|
| 選項值改名 | **不變** | 輸入是 `option_value_id`，改名不動 id |
| 選項重排 position | **不變** | 排序鍵是 id 不是 position |
| 加／刪選項 | 變 | 座標真的變了；由寫入 service 在同一 transaction 重算 |

🔴 **輸入用 id 不用字串，依據是 `67` §B.3-4 逐字**：「譯文掛在 `product_option_values.id` 上，
不是掛在字串上…**若變體以「選項值字串」比對，切語言就會找不到變體**」。
連帶好處：這讓 metafield-linked option value（身分是 GID 不是字串）**自動不成問題**。

### 3. 四個 model

`ProductOption`／`OptionValue`／`ProductVariantOptionValue` **全新**——
表在 M0 就建好了，但 `app/` 對 `product_options`／`option_values` 一直是**零讀寫**
（無 model、無 GraphQL type、無 factory、seeds 也沒有）。D12 是它們第一次上線。

`ProductVariant` 加 `before_validation :recompute_option_values_digest` ＋ format 驗證。

### 4. 測試（275/0，原 255）

新增 20 條。四條 DB 不變量**各自繞過 model 驗 DB**（model validation 是給正常路徑的
可讀訊息，DB 約束才是最後防線）：

| # | 不變量 | 擋它的東西 |
|---|---|---|
| ① | 合法座標寫得進去 | — |
| ② | 同一 (變體, 選項) 不得有第二個值 | `uq_pvov_variant_option` |
| ③ | 說謊的 `product_option_id`（值不屬該選項） | `fk_pvov_value`（三欄歸屬外鍵） |
| ④ | 跨商品掛選項 | `fk_pvov_variant` |

**負面驗證**：拆掉 `fk_pvov_value` ⇒ ③紅；拿掉 digest 的排序 ⇒ 順序無關那條紅。還原後全綠。

### 5. 既有三條測試改形態（**不是改斷言**）

`product_variant_spec` 的 SKU 三條原本在**同一個 product** 底下建多個變體，
D12 之後那會撞座標唯一索引（多個無選項變體是同一個座標）。

🔴 **那個紅燈與 SKU 軟唯一完全無關**——任何人看到它紅，**不得**去動
`ix_product_variants_sku`，也不得把 SKU 索引改回唯一。這句話已寫進該檔註釋。

改法保住原本要證明的東西：`:16` 改成兩個 product（`ix_product_variants_sku` 是
`(shop_id, sku)`，shop-scoped 的斷言原封不動）；`:26` 改成「一商品＋一選項＋5 個值」
的真實 CSV 形態（順帶成為 join 表的第一條整合測試）；`:156` 的 `insert!` 補上
兩個**不同**的 digest。
