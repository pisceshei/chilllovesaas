## 驗收後修正（PR #46 第 1 輪，Codex review）

### 🔴 我在「修指錯出處」的那一行上，指錯了出處

`claude-review.yml` 驗收依據第 0 條初稿逐字：
「`CLAUDE.md` — ⋯worklog／handoff 的格式與**分層規範**在 §工作方式」。

**分層規範不在 `CLAUDE.md`。** 實測：

```
grep -c '歷史層\|終態層\|契約層' CLAUDE.md   → 0
grep -c '歷史層\|終態層\|契約層' AGENTS.md   → 8
```

三層分類是**本 PR 加進 `AGENTS.md`** 的；`CLAUDE.md` 只定義「要不要寫、固定幾段」。

⇒ Codex 逐字指出的後果是對的：「**因為這段的理由正是『讓驗收方拿得到那份標準』，
指錯來源等於重新製造了它本來要消除的模糊**」。

🔴 **這條諷刺得記下來**：本 PR 的主題就是「指出處之前先打開來看一眼」，
而我在寫那條規則本身的時候沒有照做。
⚠️ 而且 `check-doc-claims.rb` **抓不到這一類**——它驗的是「路徑存不存在」，
不是「那個路徑裡有沒有這句話」。這正是 Pending 1 誠實聲明過的缺口（「假逐字引用」），
本輪由 Codex 這第二驗收方補上——**兩個驗收方並列的價值在這裡具體兌現了一次**。

**修法**：
- 驗收依據第 0 條改成只講 `CLAUDE.md` 的職責（要不要寫／何時寫／固定幾段），
  並加 HTML 更正註記保留原文與實測數字；
- 第 1 條 `AGENTS.md` 明寫「**worklog／handoff 的「怎麼寫」在這裡**」並點名該節；
- `AGENTS.md` 該節前言改成職責分工表述，明講「分層規範只在本節，`CLAUDE.md` 沒有」。
