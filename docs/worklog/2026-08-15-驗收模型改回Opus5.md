### 2. 註釋改寫：保留三次裁定的完整沿革

這一行在 2026-08-15 一天內被改了四次，若只留最後一次的理由，
下一個人會看不出「為什麼會來回改」而重蹈覆轍。⇒ 四次全列：

| # | commit | 時間 | 動作 |
|---|---|---|---|
| ① | `f9ee98e` | 00:01 | 由預設改成 Opus（alias） |
| ② | `7c9a9d8` | 00:10 | alias `opus` 釘成完整名 `claude-opus-5` |
| ③ | `9fadba9` | 00:14 | 改成 `claude-fable-5`（官方標示 most capable widely released model） |
| ④ | 本次 | — | 改回 `claude-opus-5`（使用者指示） |

🔴 註釋明寫：**③的理由沒有被推翻**（Fable 5 仍是官方標示的 most capable），
本次是使用者的選擇，不是因為發現③講錯了。想改回 Fable 5 之前先確認是不是又要繞一圈。

### 3. 🔴 釐清一條可能的誤導：換模型**不是**已確認的修復

`claude-review.yml` 原有一段註釋預言：
「若某天這一行開始報『模型不存在／無權限』…先確認訂閱有沒有 Fable 5，再考慮回退 `claude-opus-5`。」

而 2026-08-15 的驗收機器人**確實**連續失敗，簽名是
`num_turns:1`／`total_cost_usd:0`／次秒級（第一個 API 請求就被拒）——
**看起來完全吻合那段預言**。

**但實測證偽了「無 Fable 5 權限」**：

```
$ git log -S "claude-fable-5" --date=format:"%m-%d %H:%M" -- .github/workflows/claude-review.yml
9fadba9 08-15 00:14 ci(review): 驗收模型改用 claude-fable-5（使用者二次裁定）
```

模型自 **00:14** 起就是 fable-5，而 PR #33 的驗收在 **01:41 與 01:54 兩次成功**貼出結論，
失敗是 **01:55 之後**才開始 ⇒ 同一份設定稍早才成功過兩次，**不可能是權限**。
比較像額度／配額或服務端問題。

⇒ 註釋改成：換 Opus 5 **可能**繞過（不同模型可能不同額度池），但**沒有證據保證**；
若換完仍是同一個簽名，往帳號側查，**不要再換模型**。
並在原本那段「歸因成權限」的預言旁加警告，因為它這次會給出錯的方向。
