## 已完成的工作 (Done)

- `scripts/computed-parity.mjs` 加 `--cookie "name=value; …"`（capture／inspect／evaljs 導航前 `Network.setCookie`；JSON 只記 cookie name；
  selftest 加 `parseCookies` 正反格）——編輯器預覽在 staff 閘後，量它就得帶 session cookie 進乾淨 profile 的 headless Chrome。
- 本機 staff cookie **不經登入表單、不碰密碼**的產生法（倉庫外 `issue_local_session.rb`：建指派＋`Session.issue!`＋加密 cookie）；首輪 302 /login
  的根因＝加密值未 `Rack::Utils.escape`（`+` 被讀成空格、簽名失效）。
- 由對表抓到並修的三項預覽缺口（dev doc §1 表）：①預覽主題 `.js` 資產 422（Rails cross-origin JS 防護；`skip_forgery_protection only: :asset`）
  ②預覽無語言（`lang=""`／`Shopify.locale=""`；改以店預設 (market, locale) 渲染）③預覽內主題 JS 打無前綴 SRA 端點 ⇒ 英文（無前綴退回同一預設）。
  ②③的單一真相＝新 `Markets::PrefixIndex.default_hit`，根路徑 302 目標（`PagesController#default_prefix`）改用它。
- 結果（本機 dev server，1280；首頁另 768／390）：每頁「非全同段」恰＝五個 popup-group 段＋`__root__`（＋時間性 countdown）；其餘所有段——
  模板段、header、footer、announcement bar——編輯器預覽與店面／本尊逐屬性全同。首頁 0/21 → 15/21、商品頁 6/15 → 8/15（三寬首頁皆 15/21）。
- popup-group 五段的差異追到主題自身：Ella `base.css` `.shopify-design-mode .shopify-section-group-popup-group { position: fixed }`／`z-index: 99`
  （`inspect` 命中規則）；before-you-leave／cart-drawer 以 `section.index == nil` 直出內容——官方（2026-09-04 重取）`section.index` "returns nil …
  While rendering in the online store editor" ⇒ 本尊編輯器同形。
- 旁證：本尊 `?preview_theme_id=143506604135`（編輯器編輯中的副本）headless 擷取 vs live 首頁＝20/21（只差本尊預覽列）。
- 本尊編輯器預覽擷取（A′）**未取得**：使用者 Chrome 視窗 hidden／無焦點（含新開分頁），嵌入 app 不載入預覽、對 hoko.vip 零請求（dev doc §4、91 §3.80）。
