### 2. 四條腳本執行 allowlist 撤除，實跑證據改讀 CI（條款二，採選項②）

- 條款原文：`docs/worklog/2026-08-15-allowlist語法修正.md` Pending 2——
  「日後若開放外部貢獻者或轉 public，**必須改成 ①（只跑 base commit）或 ②（獨立唯讀 job）**，
  不得只靠降權」。
- 改動：`--allowedTools` 撤掉 `Bash(bash scripts/*)`／`Bash(ruby scripts/*)`／
  `Bash(python scripts/*)`／`Bash(python3 scripts/*)` 四條，新增 `Bash(gh pr checks:*)`。
- 選 ② 而且**不新建 job** 的理由：`ci.yml` 的 `quality` job 本來就以預設唯讀
  GITHUB_TOKEN、零 OAuth secret 跑全部 `check-*`／`test-*` 閘門——它就是那個
  「獨立唯讀 job」。驗收方的實跑證據改為 `gh pr checks` 讀 CI 結論。
- **不採選項 ① 的理由**（寫進 workflow 註釋）：base-restore 擋不住同一份 worklog
  Pending 3 登記的路徑穿越洞——`ruby scripts/../evil.rb` 能匹配 `Bash(ruby scripts/*)`，
  PR 可把代碼放在 `scripts/` 之外再以 `../` 引用；撤掉執行權才同時封掉這個洞。
  而「修改檢查腳本的 PR 需要實跑驗證」的場景在 ci.yml 上照樣被覆蓋（quality job
  跑的是 PR 版腳本，但該 job 權限唯讀、無 secret，爆炸半徑＝標準 CI 威脅模型）。
- prompt 同步改兩處：「你可以實跑檢查腳本」節改寫為「實跑證據＝CI 的結果；你自己
  不執行倉庫腳本」（含 `gh pr checks` 用法與 pending 時的誠實聲明）；
  「文檔引用保真」節由「請實跑 check-doc-claims.rb」改為「以 CI 的 doc claims step 結論為準」。
