> 規格出處：`docs/specs/65` §C.3（四條檢查）、§H.1（兩條矩陣保證）、§K 第 7 條（驗收判準）

## 已完成的工作 (Done)

鐵律 3 的 **L4（機器的編譯期）**。65 §C.1 的四層防呆裡，
L1–L3 只約束**已經用了值物件的路徑**；**L4 約束的是「還沒寫出來的路徑」**。

🔴 三個月後有人在 `app/services/psp/<某家>/charge.rb` 新寫一行、不經 adapter
直接組 HTTP body 時，**擋得住他的只有這個腳本**——他不會先去讀 `money.rb` 的註釋。
而這個 bug **在 HKD／USD 下測試全綠**（exponent=2 時 divisor 是 1）。

### 六條檢查

| # | 規則 | 違反 fixture |
|---|---|---|
| C1 | `app/services/psp/**` 不得出現 `_cents` | `c1_cents_in_psp` |
| C2 | 對 `Psp::*` 的金額 kwarg 須以 `_minor`／`_psp_decimal` 結尾 | `c2_bad_kwarg` |
| C3 | migration 禁 `t.decimal`／`t.float`；`_cents` 須 `bigint` | `c3_decimal_column`／`c3_integer_cents` |
| C4 | PSP 目錄不得出現 R4（`Money::Decimal` 或裸 `_decimal`） | `c4_money_decimal`／`c4_bare_decimal_suffix` |
| **C5** | 🔴 `__build` 只准出現在 `app/models/money.rb` | `c5_build_outside` |
| 矩陣 | zero-decimal 幣別全涵蓋 ＋ 兩種 `amount_format` 各有 fixture pack | `matrix_missing_currency`／`matrix_missing_format` |

**C5 是本輪新增的**（規格沒有）：`__build` 是 R5／R6 的唯一建構入口，
而 **Ruby 表達不了「friend class」**——`Money::Storage` 與 `Money::PspMinor` 是兩個
不同的類別，private class method 呼叫不到 ⇒ `__build` 只能是 public。
**這是四層防線裡唯一一處「型別擋不住、只能靠 CI 擋」的地方。**

### 🔴 §K 第 7 條：檢查器自己綠不算交付

逐字：「**只有前者綠不算交付**」——一個什麼都不檢查的腳本在乾淨倉庫上也是綠的。
⇒ `scripts/test-money-rules.rb`：**九個違反 fixture 各自被打紅** ＋
**一條反向斷言（乾淨倉庫必須 exit 0）**。
沒有那條反向斷言的話，一個「永遠 fail」的檢查器會讓九條全過。

第一次跑時九條全部「擋下來了但不是預期的標籤」——因為 fixture 目錄沒有
`config/limits.yml`，檢查器在讀設定時就崩了：**exit 非零，但原因是錯的**。
補上最小腳手架後才是真的在測那九條規則。

### 🔴 C4 抓到了自己——而正確的修法不是加白名單

第一次跑，C4 命中 `app/services/psp/base_adapter.rb` 兩處：一處在文檔註釋、
一處在錯誤訊息字串。兩者都是**合法的提及**——那個檔案的職責就是拒收 R4，
它得叫得出那個名字。

**不加白名單**（那個檔正是最該掃的），改為：
- 跳過**整行註釋**（必要：唯一正確實作 C4 的檔案不該被 C4 判違規）；
- **不跳行尾註釋**（刻意：要精確剝掉行尾 `#` 就得處理字串內的 `#` 與 `#{}`，
  而那正是 `lint-prototype.py` 踩過六次「漏看」的那類解析。取捨方向是**寧可誤擋**
  ——誤擋會有人來改，漏看不會有人發現）；
- 錯誤訊息改用「R4」這個代號，不逐字寫類別名。

### 🔴 順手抓到一個更嚴重的：整個測試套件變成 0 examples

fixture 裡為了餵矩陣檢查而放的腳手架叫 `spec/models/money_spec.rb`，
被 rspec 的預設 pattern 撿走 ⇒ **233 examples 變成 0**。
這次它是 exit 非零（載入期炸了）所以看得出來，但只要那些檔案是
「合法但什麼都不做的 Ruby」，就會是 **0 examples ＋ exit 0**——**CI 全綠，一條測試都沒跑**。

⇒ 兩件事：`.rspec` 加 `--exclude-pattern`，以及 `spec_helper` 加一道
**「0 examples 不是通過」**的守衛。

守衛本身改了三版才對：

| 版本 | 判準 | 為什麼錯 |
|---|---|---|
| ① | 無條件檢查 | `rspec spec/models/money_spec.rb`（22 examples）被誤擋——**一個妨礙日常操作的守衛會在第一天被拿掉** |
| ② | 「載入的 spec 檔數 < 5 ⇒ 跳過」 | 🔴 **判斷反了**：「載入的檔案很少」正是要抓的那個 bug 的**症狀**，不是它的反例。pattern 壞掉時檔案數變 0，守衛被自己的條件跳過 |
| ③ | 「ARGV 沒有路徑、也沒有 `-e`／`--tag`」 | ✅ 四種情境實測全對 |

（②→③ 的中間還發現 `ARGV.empty?` 不能用：`ARGV` 含 RSpec 自己的 flag，
`bundle exec rspec --no-color` 的 ARGV 是 `["--no-color"]`。）

`config/ci.rb` 原本只有八步（**建檔時**的實數，見 `50a2745`；此後已增為 9 步，後續文件不再寫死步數），而 `ci.yml` 的 quality job 另外跑**五個**專案自訂檢查

## 尚未完成或需注意的風險 (Pending / TODO)

- 🔴 **C2 只掃「明顯的 kwarg 呼叫」**：`Psp::X.new(...).charge(amount_minor: ...)` 這種。
  **動態 `send`、hash splat（`**payload`）它看不到**。這是純文字掃描的天生限度，
  已寫進腳本檔頭的「不檢查什麼」誠實聲明。
- 🔴 **它不驗證語義**：一個叫 `amount_minor` 但其實裝著 cents 的變數，本腳本看不出來。
  那要靠 L1–L3 的型別層。**四層是互補的，任何一層都不宣稱單獨足夠。**
- ⚠️ **`each_line` 不跳行尾註釋是刻意的取捨**（寧可誤擋）。
  若日後誤擋太多，正確的修法是**精確剝註釋**（處理字串與 `#{}`），
  **不是**加白名單——白名單會把「這個檔案不用檢查」變成可以無限擴充的東西。
- ⚠️ **65 §C.3 的 C1 白名單描述是空的**：規則掃 `app/services/psp/**`，
  白名單卻寫「`Money::Storage` 的型別註記與 `#to_psp_amount` 的實作兩處」
  ——那兩處在 `app/models/money.rb`，**本來就不在掃描範圍內**。
  本輪不實作白名單並把這個發現寫進腳本註釋，免得下一個人以為漏做了。
  規格那句話尚未修——下一輪順手改。
- ⚠️ **「金額路徑的測試檔」的定義是本輪自己下的**（`MONEY_TEST_GLOBS` 具名常數）。
  65 §H.1 以它為判準卻沒有定義它。新增金額相關的 spec 時要記得加進那個常數，
  否則矩陣覆蓋度檢查會掃不到——**而它的失效方向是「少掃」**。
- **`spec_helper` 的 `MINIMUM_EXAMPLES = 50` 是硬編的**（不走 `limits.yml`）：
  它是測試基礎設施的參數不是產品上限值，鐵律 6 不適用。刻意設得很低，
  只防「整包沒跑」不防「少跑幾條」，這樣它不需要隨著新增測試而維護。
