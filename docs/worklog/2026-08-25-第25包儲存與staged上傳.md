- **push 前對抗式審查輪**（14 agents 五維度；9 條確認 0 反駁，全部本輪處置）：
  ①🔴 **檔案系統操作原本在 DB transaction 內**（C2 high／C3／C8 同根）——fs 不回滾：
  replace 的舊 blob 在 commit 前就 unlink，rollback 後 row 指向已刪檔（靜默資料遺失）；
  staged 的 move 在 rollback 後原檔已消失。修法＝**fs 全移出 txn**：先寫新 blob →
  txn 只做 metadata＋event → rollback 補償刪新 blob → commit 後才刪舊 blob；
  staged 改「讀 bytes 不 move」（原檔留給孤兒清掃）。
  ②C4 batch 無 rescue：一列 raise（如 staged TOCTOU 的 ENOENT）炸掉整批並讓前面已
  commit 的檔留無主 blob ⇒ 每列各自 rescue 轉 userError。
  ③🔴 C0 SSRF 尺寸上限只在 2xx 分支生效——攻擊者回 404＋數 GB body 走
  Net::HTTP 隱式讀完整 body ＝OOM ⇒ `request` 改回 `[status, headers, body]`，
  **所有狀態一律 streaming cap**。
  ④🔴 C1 denylist 漏 IPv6 transition：NAT64 `64:ff9b::/96`、6to4 `2002::/16`、
  v4-compat `::/96` 都能嵌入私網 IPv4 並通過驗證（IPv6-only＋DNS64 網路上核心會翻成
  內網位址）⇒ 改「先抽出嵌入 IPv4、內外層都套保留域判定」。
  ⑤C5 content-type 只看副檔名／宣告值 ⇒ 新增 `Storage::ImageSniff` **magic-byte
  決定型別**（宣告 png 實傳 HTML ⇒ UNACCEPTABLE_ASSET），檔名副檔名對齊真型別。
  ⑥🔴 C6 `RESOLVABLE_TYPES` 加了 "File" 但 `resolve_type` 無分支、FileType 未
  implements Node ⇒ `node(File-gid)` 從回 null 退化成 500 ⇒ **回退**（完整 Node
  支援屬第 28 包 files query）。
  ⑦C7 fileCreate 是建立型卻無冪等 ⇒ 強制帶 key；批量 claim/replay 的落款形態
  與本包 fs-out-of-txn 相斥，登記 `docs/specs/91-pit-register.md` §3.8。
- 測試：rspec **532/532**（審查後 +8 回歸例：fs 補償／batch 隔離／magic sniff／
