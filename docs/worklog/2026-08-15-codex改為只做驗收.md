# 2026-08-15 — 改制：Codex 只做驗收，不再自動派修

> 使用者裁定（觸發點：PR #29 驗收未通過後，workflow 自動 @codex 派修）：
> 「為什麼是 codex 修，改成 codex 只做驗收」

## 已完成的工作 (Done)

### 1. 廢止自動派修（`claude-review.yml` 兩處）

| 位置 | 舊行為 | 新行為 |
|---|---|---|
| 「需修改」分支 | `@codex 請依本 PR 最新一則 Claude 驗收意見，逐條修復…` | **只通知人**：「驗收未通過（累計第 N 輪），修好 push 本分支即自動重審」——**留言內不含任何 `@` 代理呼叫** |
| AUTO_MERGE 通過後 | 在下一個里程碑 issue `@codex 請開始 $NEXT_TITLE…` | **只登記**：貼上「上一階段已合併，本階段範圍見…」並明寫「**本則為登記，不是派工**」 |

🔴 **為什麼不是只把留言裡的 `@codex` 三個字刪掉**：Codex 對 `@` 提及會接單。
留言裡只要出現 `@codex`，不論措辭多委婉，它都可能開始改代碼。
⇒ 規則寫成「本則留言**不得**包含 `@` 開頭的代理呼叫」，並寫進註釋。

### 2. `MAX_FIX_ROUNDS` 語義改變（不是刪掉）

舊：**派修輪數上限**，超過就停止自動 @codex。
新：**結構問題的警示線**。同一 PR 被打回超過 N 輪，通常不是「再修一次就好」，
而是 **PR 太大該拆** 或 **規格本身還沒定案**——訊息改成往這兩個方向提示。

🔴 `ROUNDS` 的計算**沒有改**（仍是全 PR 累計，不套留言水位）。
理由已在上一輪寫進註釋：加了水位它每輪歸零，這條線就永遠觸發不到。

### 3. `CODEX_PING_TOKEN` 移除

它存在的唯一理由是「讓自動 @codex 留言以**本人身分**發出，Codex 才視為有效請求」。
不派工之後它沒有用途 ⇒ 從 step `env:` 移除，`PING` 變數一併刪除。

🔴 註釋寫明**不要因為「留著也不會怎樣」就加回來**：
一個沒有用途的 write 權限 token 出現在 workflow env 裡，讀的人會以為它有用途。
（GitHub 上那個 secret 本身可以刪，但**刪不刪是使用者的事**，我沒有動。）

### 4. 驗收 prompt 加禁令

原文：「不要自己 @codex、不要 approve、不要 merge——這些由後續自動化步驟處理。」
——這句話**暗示自動化會去 @codex**，與新制矛盾。改成明寫：

> 🔴 **不要 @ 任何代理（@codex 等）派修**：本專案已改制，Codex 與你並列為兩個**獨立驗收方**，
> 實作與修復一律由人主導的工作階段負責。你的產出是意見，不是工單。

### 5. 兩份分工源頭文件同步

- **`CLAUDE.md` 第 3 行**：原本是「分工：**Codex 實作**、**Claude 審核驗收**」。
  改成三方描述（實作＝人主導的工作階段；Codex 與 Claude bot＝兩個獨立驗收方），
  並寫明廢止理由與「不得加回自動派修」。
- **`AGENTS.md` 標題與開頭**：原本是「給 Codex（**實作代理**）的工作守則／你是本專案的**實作方**」。
  改成「專案工作守則（驗收方與實作方共用）」，分別給驗收方與實作方各一段指示。
  🔴 明寫**以下全部技術鐵律照舊適用**——改制改的是「誰來寫代碼」，**不是**放寬任何一條鐵律。

🔴 **不同步這兩份就等於沒改**：`AGENTS.md` 是 Codex 實際會讀的檔（官方明文
「Codex searches your repository for `AGENTS.md` files」），留著「你是實作方」
會讓它繼續以實作者自居；`CLAUDE.md` 則是本專案每一輪工作的第一句話。
