# worklog 2026-08-23 — 系列成員 ID 報錯化與巢狀交易回滾

## 已完成的工作 (Done)

- **成員 ID 不再靜默丟棄**：`resolve_member_ids` 對「非 `gid://chilllove/Product/{id}` 格式」回
  `INVALID`、對「本店查無此商品」（含已刪除與跨店 GID）回 `NOT_FOUND`，整棵樹回滾。
  原本兩者都被 `filter_map` 靜默濾掉，症狀是「存檔顯示成功、成員少一個、沒有任何錯誤訊息」。
- **巢狀交易回滾**：`SaveCollection` 的 create／update 兩條路徑都改用
  `ActiveRecord::Base.transaction(requires_new: true)`。
- **例外類別更名** `TranslationRejected` → `TreeRejected`：它現在承載譯文以外的拒絕（成員 ID），
  舊名字會讓下一個人以為只跟譯文有關。
- 五語錯誤訊息 `errors.collection.product_gid_invalid` / `product_not_found`。
- 測試：`spec/requests/collection_set_spec.rb` 新增一例（格式錯 → INVALID；跨店 GID → NOT_FOUND，
  且不得留下空系列）；新增 `spec/services/catalog/save_collection_spec.rb` 一例守巢狀回滾。
  複驗：`bundle exec rspec`（快照 `400 examples, 0 failures`）、`bin/rubocop`、
  `bundle exec brakeman -q`（`Security Warnings: 0`）、`npx vitest run`（快照 `Tests 41 passed`）。

## 尚未完成或需注意的風險 (Pending / TODO)

- 🔴 **`SaveProduct` 有同形態的交易寫法（兩處 `ActiveRecord::Base.transaction` 無 `requires_new`）**，
  但它走 `Idempotency::Guard`，而 Guard 已用 `requires_new: true` ＋ 顯式 `raise ActiveRecord::Rollback`
  處理同一個陷阱 ⇒ **本輪不動它**（鐵律：修復只針對點名問題）。若日後 Guard 被繞過，
  該處會重現同一個 bug；這一條是登記，不是待辦。
- 實測數據（joined 殘留 1／requires_new 為 0）取自本機 MySQL 8.4.10 + Rails 8.1.3.1；
  若升級 Rails 主版本，這個語義要重測而不是沿用。
- 跨店 GID 現在回 `NOT_FOUND` 而不是 `ACCESS_DENIED`：刻意的——回 ACCESS_DENIED 等於
  向呼叫者確認「那個 id 存在，只是不是你的」，是一個資源枚舉旁路。
