# 2026-09-02 Ella 修復 PR-12：店面主題預覽釘選（?preview_theme_id=）＋預覽列

## 已完成的工作 (Done)

- 使用者點名「連主題預覽功能都沒做」的店面側收口——本尊機制 1:1：
- **釘選**：`?preview_theme_id=` 帶一次 ⇒ 簽名 cookie（`_cl_preview_theme`）
  釘住，之後**不帶參數的請求也繼續渲染預覽主題**（sticky——83 §12.3 live
  實測 2026-08-31）；帶正式主題 id ⇒ 解除（同節「復位法」）；無效 id／
  跨租戶 id（with_tenant 查無）⇒ 解除。robots 既有
  `Disallow: /*?*preview_theme_id=` 官方形不動。
- **渲染面全跟主題**：pages／assets／search suggest／recommendations 四個
  controller 的渲染主題由 `published_theme` 改 `current_theme`（釘選優先）。
  🔴 資產必須跟——預覽頁配正式 CSS＝版面驗證全是假象（TP4 殺手格）。
- **預覽不進頁快取**（不讀不寫）＋`Cache-Control: no-store`＋
  `X-Robots-Tag: noindex`；資產在釘選時也 no-store（同 URL 不同主題，
  瀏覽器快取會互汙 300s）。
- **預覽列**：整頁 HTML 注入 `#cl-preview-bar`（主題名＋「結束預覽」——
  href 帶正式主題 id＝復位法）。功能對位本尊 preview bar，視覺自有
  （鐵律 9）；片段／JSON 回應不注。
- **未發布店可預覽**：`require_published_theme!` 放行有釘選的請求。
- **admin 主題頁**：預覽連結由 admin noindex 端點改店面釘選 URL
  （admin 與店面同 host ⇒ 相對路徑）。
- 測試 TP1–TP5（sticky／復位／無效與跨租戶／資產跟主題／不進頁快取）；
  突變 3/3 殺（M12-1 拔 sticky、M12-2 資產回正式主題、M12-3 拔快取繞道）。
