## 已完成的工作 (Done)

### 🔴 Codex 抓到一條真的：`Money::Storage.new` 我留了 public

原文：「`Money::Storage.new` remains public here, so any caller can bypass `from_cents`
and construct values such as `Money::Storage.new(cents: 1.5, currency: "hkd")`.」

**實測屬實，而且比 Codex 描述的更嚴重**：

```ruby
bad = Money::Storage.new(cents: 1.5, currency: "hkd")
#=> #<data Money::Storage cents=1.5, currency="hkd">
bad.currency          #=> "hkd"     🔴 沒被正規化 ⇒ pack 的 minor_unit_overrides[:HKD] 查不到
bad.to_decimal.string #=> "0.02"    🔴 float 已經進了金額路徑
```

送 PSP 的兩條路徑表現**不同**：

| 格式 | 結果 | 為什麼 |
|---|---|---|
| `minor_units` | ✅ 被 A3 擋下（`1.5 % 1 = 0.5 ≠ 0`） | A3 的餘數檢查剛好也擋住 float |
| `decimal_string` | 🔴 **送出 `"0.02"`** | **那條路徑沒有 A3**——A3 是 `minor_units` 專用 |

⇒ Codex 說的「exponent-2 PSP path can carry the float into `PspMinor`」**方向對但落點不對**：
`PspMinor` 那條被擋了，**沒被擋的是 `PspDecimal`**——而那正是「在 HKD 上也會錯」的那一條。

### 為什麼我第一版留著 `.new`

我的理由是「R1／R4 是入口，要留著可建」。**那個理由是錯的：入口是 `from_cents`，不是 `.new`。**
`from_cents` 的 Integer 閘門與 `upcase` 正規化，只有在 `.new` 也關掉之後才是**閘門**；
在那之前它只是「建議走的那條路」。

修法：四個型別的 `.new`／`.[]`／`.allocate` **全部** private，`#with` 全部 `undef`。
新增 4 條 spec 把 Codex 指出的具體繞過路徑逐項釘住。

🔴 **這一條與本輪主線是同一種病**：我在 worklog 裡寫「`Data` 有三條後門，只關 `.new`
是擋不住的」——然後**自己在 R1／R4 上只關了另外三條、留著 `.new`**。
盤點後門的時候把「`.new` 本身」漏掉了，因為我把它當成「本來就該開的那一個」。
