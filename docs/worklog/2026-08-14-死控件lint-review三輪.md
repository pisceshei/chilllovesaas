### ② `_attr_ok` 跨後代組合子（第八種形態，仍是**誤報**）

第二輪修掉「跨逗號」之後，屬性條件仍會跨**後代組合子**：

```js
querySelector('[data-form="prod"] .cb')   // 原型裡真的有這種寫法
```

`[data-form="prod"]` 掛在**祖先**身上，卻被要求加到把手自己頭上 ⇒ 靠 `.cb` 當把手的
控件被誤判成死控件。

🔴 **查證：這不是假設**——`grep` 三份原型，`'[data-form="prod"] [data-f="…'` 確實存在
（該例因 `data-f` 走 SKIP 而沒發作，但寫法就在那裡）。

修法 `_compound(seg, at)`：在 `seg` 裡以**組合子**（空白／`>`／`+`／`~`，
且在引號外、括號深度 0）切出 token 所在的那**一節**，屬性條件只驗那一節。
🔴 **祖先條件一律不驗**——方向刻意偏向放行，因為這條規則的誤報成本高於少報。

## 尚未完成或需注意的風險 (Pending / TODO)

- 🔴 **`_compound` 只解一層**：它取的是「token 所在那一節」，
  不驗祖先也不驗兄弟。這是刻意的放行方向，但意味著
  `'[data-x] .cb'` 與 `'.cb'` 在本規則眼中等價——
  「祖先根本不存在於原型裡」這種死法它抓不到。維持啟發式限度，未列入解決範圍。
- **`:has()` 沒特別處理**：`:has(.x)` 裡的 token 會被當成把手（因為括號內不切）。
  目前三份原型無 `:has()`，未發作。
- 至此 `r_dead_control` 共登記**八種**形態：前六種少報、後兩種誤報。
  兩個方向都已各有 fixture，但**沒有機制保證下一種形態會被想到**——
  fixture 只固化已知的，未知的仍要靠 review。
- **123 條存量死控件未清**（歸屬 M2／M8），同前兩份 worklog。
