### 🔴 測試拓樸也會騙人（本輪第二課）

MJ3 第一次跑是**綠**的。原因不是守衛無效，而是**我的測試拓樸選錯了**：
A→B→C 鏈裡若 C 含該商品，B 就是空的，於是 A 無論什麼順序都「碰巧」算對。
把 C 的規則改成商品**沒有**的標籤（C 空 ⇒ B 含商品 ⇒ A 應為空）之後才轉紅。
⇒ 教訓：**測依賴順序的測試，必須讓「被依賴方非空」**，否則測的是空集合的交換律。

### 🔴 本輪踩到的流程坑（登記；候選 91 §3）

**timeout 砍掉的突變 runner 會把突變留在樹上**：外層 `timeout` 的 SIGTERM 讓 Python 的
`finally`（還原原檔）不執行，三次逾時各留下一個活突變（C13 的 `if false &&`、
C14 的白名單放寬、C18 的 create 路徑同步移除），其中 C14/C15 進一步讓後續 runner 報
「錨點找不到」而**跳過驗證**——看起來像跑過，實際上該格從未紅過。
固定處理：①每格獨立進程＋比 timeout 短的預算 ②runner 掛 SIGTERM handler 轉
SystemExit（讓 finally 跑）③突變輪結束後**逐一 grep 每個被突變的錨**確認還原
（抽查一兩個＝本輪誤判「樹完整」的原因）④跑一次完整相關 spec 當終驗。
