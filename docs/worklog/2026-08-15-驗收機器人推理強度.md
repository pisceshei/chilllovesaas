## 已完成的工作 (Done)

### 1. Claude 驗收機器人 → Opus + 最高推理強度（已落地）

`claude-review.yml` 的 `claude_args` 加兩行：`--model claude-opus-5`、`--effort max`。

🔴 **關鍵事實（親自查證，不是推測）**：`anthropics/claude-code-action@v1` 的 `action.yml`
**沒有 `model` 這個 input**。抓 `raw.githubusercontent.com/anthropics/claude-code-action/v1/action.yml`
逐一列出全部 **39 個 input**：

```
trigger_phrase, assignee_trigger, label_trigger, base_branch, branch_prefix,
branch_name_template, allowed_bots, allowed_non_write_users, include_comments_by_actor,
exclude_comments_by_actor, prompt, settings, anthropic_api_key, claude_code_oauth_token,
anthropic_federation_rule_id, anthropic_organization_id, anthropic_service_account_id,
anthropic_workspace_id, anthropic_oidc_audience, github_token, use_bedrock, use_vertex,
use_foundry, claude_args, additional_permissions, use_sticky_comment,
classify_inline_comments, use_commit_signing, ssh_signing_key, bot_id, bot_name,
track_progress, include_fix_links, path_to_claude_code_executable,
path_to_bun_executable, display_report, show_full_output, plugins, plugin_marketplaces
```

⇒ 網路上常見的 `with: model: claude-opus-4` 寫法是 **v0 的**。在 v1 上寫它，
GitHub Actions 會把未知 input **靜默忽略**（不報錯、不警告），workflow 照跑、
用的卻是預設模型——**這是最難發現的失效形態**：一切看起來都成功了。
唯一正確的位置是 `claude_args`（`action.yml` 的描述原文：
"Additional arguments to pass directly to Claude CLI"）。

旗標值的來源＝**本機 CLI 的 `--help` 實測**，不是猜的：
- `--model <model>`：接 alias（`fable`/`opus`/`sonnet`）或全名（`claude-opus-5`）。
- `--effort <level>`：`low, medium, high, xhigh, max` 五級，`max` 為最高。
  Opus 5 的預設是 `high` ⇒ 這一行**有實際作用**。
  `max` **不能**寫進 settings 的 `effortLevel`（官方：session-only）⇒ 只能走 `--effort`。

🔴 **本輪內修正一次：alias `opus` → 完整名 `claude-opus-5`**。
第一版我寫 alias，理由是「升版自動跟上」。**這個理由是錯的，因為它假設 alias 一定解析到最新**：
官方明文「Opus 5 requires Claude Code v2.1.219 or later」，且
「Before v2.1.219, `opus` resolved to Opus 4.8」——而 action 內建 CLI 的版號
**官方未公布 SDK↔CLI 對應** ⇒ 我們無法事先知道拿到哪一個。
若它舊於 2.1.219，`--model opus` 會**靜默**跑 Opus 4.8：不報錯、log 看不出來、
使用者以為換好了。釘完整名把「靜默降級」換成「會叫的失敗」。
代價是升版不會自動跟上，這是**刻意付的**——與本專案一貫的取捨方向一致
（寧可失效時大聲壞掉，也不要安靜地做錯事）。

### 三條明確不要做的（已寫進 workflow 註釋）

| 做法 | 為什麼不行 |
|---|---|
| `with: model: claude-opus-5` | v1 沒這個 input，GitHub **靜默忽略**未知 input |
| step `env:` 加 `CLAUDE_CODE_EFFORT_LEVEL`／`ANTHROPIC_MODEL` | action 的 env 白名單只轉發 `ANTHROPIC_DEFAULT_{SONNET,HAIKU,OPUS}_MODEL` |
| 同時用 `settings:` 設 model／effortLevel | 官方：`claude_args` takes precedence over settings ⇒ 永遠不生效 |

### 考慮過但**刻意不加**：prompt 裡的 `ultrathink`

官方確實有這個關鍵字（「Include `ultrathink` anywhere in your prompt to request deeper
reasoning on that turn **without changing your session effort setting**」）。
不加的理由：我們已經 `--effort max`，**那是上限，再深不上去** ⇒ 加了是裝飾。
唯一會有用的情境是「組織層 effort limits 把 max 靜默 clamp 掉」，
但那是 Claude Enterprise 方案專屬，本專案用個人訂閱，**不適用**。
🔴 登記於此是為了讓下一個人不用重新查一遍就知道「這個已經評估過、結論是不加」。

## 尚未完成或需注意的風險 (Pending / TODO)

1. 🔴 **模型名已查實：官方識別字是 `gpt-5.6-sol`**（使用者口語稱「5.6 sol」／「sol 5」）。
   「5.6」是世代、「Sol」是層級，**順序與口語相反** ⇒ config 裡照抄「sol 5」一定失敗。
   但**這不改變結論**：`chatgpt-codex-connector` App 自動貼的那個 review
   **沒有任何 model／effort 設定**。兩路獨立佐證：
   - **UI 全面掃描（我親自點過）**：`settings/general`、`settings/environments`、
     環境詳情頁、`settings/code-review`、`codex/cloud` composer ＋「＋」選單
     ——**六個面全文比對模型關鍵字零命中**。環境詳情頁只有映像檔／網路存取／
     快取／設定指令碼／環境變數／密碼，沒有模型。
   - **官方 GitHub 整合文檔全文 grep**：`reasoning`／`effort` 出現 **0 次**，
     `model` 只出現 1 次而且是 "threat models"。
   ⇒ repo 端能改的是「審什麼」，不是「用多強的腦」。

2. 🔴 **有一條未採用的路徑，待使用者裁定**：官方 `openai/codex-action@v1`
   **確實有 `model` 與 `effort` 兩個 input**（官方描述：「Pick the Codex agent
   configuration you want; leave empty for defaults」）。那是**自架 workflow**，
   與 connector App 的自動審查是**兩條並行的路**，不是同一個東西。
   要真的在 GitHub 上指定 `gpt-5.6-sol` ＋ 最高 effort，這是唯一官方途徑。
   **本輪未做**，因為它牽涉新增一支 workflow、可能要 API key secret、
   且與現有 connector 審查重複——屬於架構決策，不是設定調整。

3. ⚠️ **`.codex/config.toml` 的 `model_reasoning_effort`／`review_model` 不要碰**。
   官方明文只綁 CLI 與 IDE extension（「The CLI and IDE extension share the same
   configuration layers」），對 cloud／GitHub review **完全沉默**。
   本 repo 目前沒有 `.codex/` 目錄，**放一個進去屬於賭，不是設定**。

4. ⚠️ **在 AGENTS.md 寫「請用最高推理強度」不是設定**，是賭它照做。
   官方沒有任何一頁說 AGENTS.md 能控制 model 或 effort。
   （AGENTS.md 的 `## Code Review Rules` 區塊是另一回事——那控制「審什麼」，
   官方支援，但本輪尚未驗證完畢，未落地。）

5. ⚠️ **`--effort max` 與 `--model claude-opus-5` 尚未在 CI 上實跑驗證過**。旗標由
   action 依賴的 `@anthropic-ai/claude-agent-sdk`（`^0.3.232`，caret ⇒ 安裝時取最新 0.3.x）
   內建的 CLI 解析，**與本機 CLI 未必同版**。若不認得，步驟會失敗——
   但 `continue-on-error: true` ⇒ 不擋 CI，會走「步驟失敗」分支貼診斷留言。
   🔴 **第一次跑到時要看那則留言的 stderr，不要直接把旗標拿掉。**
   這正是釘完整名要換來的效果：**失敗會叫**，而不是安靜地跑一個舊模型。

6. ⚠️ **本改動動到 `claude-review.yml` ⇒ PR #30 自己不會被驗收**（反竄改機制，
   見本檔頂部註釋）。真正的驗證機會是**合併進 main 之後開的第一個 PR**——
   也就是 PR #29 重新 push 的那一次。

7. ⚠️ **「啟用積分」開關刻意沒動**（維持關閉）。它是計費設定：
   「允許在超過速率限制後繼續使用積分進行程式碼審查」。
   開了「全面程式碼審查」之後單次審查更耗額度，**比較容易撞到速率上限**；
   撞到時的行為是審查停止，而不是自動扣積分。要不要開由使用者決定，我不代為變更計費。

8. ⚠️ **成本／時長會上升**。`--effort max` ＋ Opus ＋ `--max-turns 200`，
   單次驗收的 wall-clock 與 token 都會比現在的 3–4 分鐘高。
   若之後出現 `timeout-minutes: 30` 被打滿的情況，先調 `--max-turns` 而不是降 effort。
