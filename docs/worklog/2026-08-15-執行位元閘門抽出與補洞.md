## 已完成的工作 (Done)

### 1. 🔴 Y4：非 ASCII 檔名被**靜默漏掉**

`git ls-files -s` 在 `core.quotePath=true`（預設）時，會把含非 ASCII 的路徑**加引號並跳脫**：

```
$ git ls-files -s scripts/
100644 8055503... 0	"scripts/\346\252\242\346\237\245.rb"
```

舊寫法用 `awk -F'\t'` 拿 `$2`，得到的是**那串跳脫字串**（含引號），
`head -c 2 "$f"` 開檔失敗 ⇒ 條件為假 ⇒ **該檔完全不會被抓到**，
而閘門還會印「OK：⋯全部可執行」。

實測（現場建 git repo，放一個 100644 ＋ shebang 的 `scripts/檢查.rb`）：舊寫法 **exit 0，零違規**。

🔴 注意這與 PR #35 修的**不是同一個洞**：那次修的是「含空白的檔名」（`-F'\t'` 解決），
非 ASCII 這一類 `-F'\t'` **完全沒有處理到**，而當時的註釋寫「用 TAB 當分隔符才拿得到完整路徑」
——那句話在這個情境下是不完整的。

**修法**：`git ls-files -sz`（NUL 分隔）＋ `while IFS= read -r -d ''`。
`-z` 輸出**原始未跳脫路徑**，是唯一對任何檔名都正確的讀法。

### 2. 🔴 Y5：掃到 0 個檔卻印 OK

若 pathspec 匹配不到任何東西（跑錯目錄、不是 git repo、目錄改名），
`bad` 為空 ⇒ 舊寫法印「OK：全部可執行」且 **exit 0**。

## 驗收後修正（PR #41 第 1 輪 Codex review，三條全部成立）

### 🔴 shebang 從**工作區**讀，被「部分暫存」騙過

本檢查判的是 `git ls-files -s` 的 mode——那是 **index** 的狀態；
而 shebang 卻從**工作區**讀。實測重現：

```
git add scripts/x.sh              # index：有 shebang
git update-index --chmod=-x …     # index：100644
（把工作區的 shebang 刪掉）
→ 閘門印「OK：執行位元閘門通過」exit 0
```

而**即將提交的內容**是一支帶 shebang 的 100644 腳本 —— 正是它要擋的東西。

⇒ 改用 `git show ":$path"` 從 index 讀，與 mode 的來源一致。
（對含空白／非 ASCII 的路徑同樣正確。）

### 🔴 `bin/` 規則完全沒被測到

前六條 fixture **全部只佈置 `scripts/`** ⇒ 把 checker 裡處理 `bin/` 的那段整個刪掉，

補 `bin_bad`（缺執行位元 → exit 1）與 `bin_ok`（全 755 → exit 0，避免規則寫成永遠紅）。
突變驗證：把 `git ls-files -sz bin/` 那行拿掉 → **exit 1，抓到了**。

### 🔴 第 2 輪驗收：它抓到我上一輪修正裡的 bug（本機全綠、CI 會紅）

逐字：

> `seed_repo` 造出來的基線檔，會被各 case 隨後的 `git add -A` 打回 100644
> （Linux `core.filemode=true`），clean／no_shebang／bin_ok 三條正向斷言在 CI 上會紅。

**實測重現**（probe repo，`core.filemode=true`）：

```
seed 之後：            100755 … bin/baseline
後續 git add -A 之後： 100644 … bin/baseline      ← 被磁碟 mode 蓋回去
chmod +x 後再 add -A： 100644 …                   ← chmod 在 Windows 上救不了
```

⚠️ **`chmod +x` 沒有用**：Windows 的檔案系統沒有真的執行位元。

🔴 **這個 bug 的形態，正是這支閘門存在的理由本身**——「本機全綠 → 推上去 CI 紅，
而擋下來的理由本機沒有機會發現」。它在**這支閘門自己的測試裡復發**，
而且我上一輪還跑了 11 條全過就收工了。

#### 修法兩段

**① 讓測試在本機就能重現 CI**：`make_repo` 強制 `git config core.filemode true`。
Linux runner 自動偵測成 true、Windows 是 false ⇒ 不固定它，本機的綠**證明不了 CI 會綠**。
加上之後本機立刻重現出**逐字相同的三條紅**（clean／no_shebang／bin_ok）。

**② 修 bug**：把基線檔的 mode 重設**移進 `assert_case`**，用 `update-index --chmod=+x`
（平台無關），在跑 checker 之前最後一次設定。

🔴 **放在 `assert_case` 而不是各 case 末尾，是刻意的**：那是唯一保證在「所有佈置都做完
之後」執行的地方，**新增 case 的人不可能忘記**。機制 > 紀律——與本 PR 的主旨一致。
