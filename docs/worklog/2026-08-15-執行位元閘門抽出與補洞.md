## 已完成的工作 (Done)

### 1. 🔴 Y4：非 ASCII 檔名被**靜默漏掉**

`git ls-files -s` 在 `core.quotePath=true`（預設）時，會把含非 ASCII 的路徑**加引號並跳脫**：

```
$ git ls-files -s scripts/
100644 8055503... 0	"scripts/\346\252\242\346\237\245.rb"
```

舊寫法用 `awk -F'\t'` 拿 `$2`，得到的是**那串跳脫字串**（含引號），
`head -c 2 "$f"` 開檔失敗 ⇒ 條件為假 ⇒ **該檔完全不會被抓到**，
而閘門還會印「OK：⋯全部可執行」。

實測（現場建 git repo，放一個 100644 ＋ shebang 的 `scripts/檢查.rb`）：舊寫法 **exit 0，零違規**。

🔴 注意這與 PR #35 修的**不是同一個洞**：那次修的是「含空白的檔名」（`-F'\t'` 解決），
非 ASCII 這一類 `-F'\t'` **完全沒有處理到**，而當時的註釋寫「用 TAB 當分隔符才拿得到完整路徑」
——那句話在這個情境下是不完整的。

**修法**：`git ls-files -sz`（NUL 分隔）＋ `while IFS= read -r -d ''`。
`-z` 輸出**原始未跳脫路徑**，是唯一對任何檔名都正確的讀法。

### 2. 🔴 Y5：掃到 0 個檔卻印 OK

若 pathspec 匹配不到任何東西（跑錯目錄、不是 git repo、目錄改名），
`bad` 為空 ⇒ 舊寫法印「OK：全部可執行」且 **exit 0**。

**一個什麼都沒掃的檢查，看起來與全部通過一模一樣**——本專案反覆出現的「空值長得像資料」。
**修法**：canary，`scanned == 0` 直接 fail 並說明常見原因。

### 3. Y6：抽成 `scripts/check-exec-bits.sh`，並補上回歸測試

抽出的三個理由（都是實測後果，不是整潔潔癖）：

1. **`bin/ci` 跑得到**——inline shell 進不了 `config/ci.rb`，
   `check-ci-parity.rb` 也看不到它。那正是它誠實聲明裡登記的已知缺口，本輪一併關掉。
2. **可以寫回歸測試**（65 §K.7）——抽出前它是全 `ci.yml` 唯一
   「判準才剛被大改、卻沒有反向自測」的檢查。
3. **兩個 job 不會分岔**——原本 test 與 quality 各有一份 inline 複製。
   實測確認抽出後兩個 job 的該步驟 **YAML 完全相同**。

`scripts/test-exec-bits-rules.sh` 六條 case：

| case | 期望 | 守什麼 |
|---|---|---|
| clean | exit 0 | 🔴 反向斷言：乾淨 repo 必須通過 |
| ascii | exit 1 | 基本判準（帶 shebang 卻 100644） |
| no_shebang | exit 0 | 無 shebang 的資料檔不受約束（判準若寫成「scripts/ 全部」會誤傷） |
| spaced | exit 1 | 含空白檔名（PR #35 Codex review 抓到的） |
| **non_ascii** | exit 1 | 🔴 **Y4** |
| **empty** | exit 1 | 🔴 **Y5** |

fixture **跑時現建**而非放進版控：這個檢查讀的是 **git index 的 mode**，
fixture 必須是真的 git repo，而巢狀 `.git` 沒辦法提交進本倉庫。
代價是慢一點（六個 repo），好處是 fixture 與判準永遠不會不同步。

### 4. 三處引用點同步

- `ci.yml` 兩個 job → 改為 `bash scripts/check-exec-bits.sh`，另加
  `Regression-test exec-bit rules` 一步。
- `config/ci.rb` → 補 `Invariants: Exec bits` 與 `Invariants: Exec bit rules regression`。
- `AGENTS.md` → **不再重複貼指令**，改成「直接跑那支腳本，與 CI 是同一份實作」。
  🔴 原本那節貼著一份與 inline shell「逐字一致」的指令，而 inline 有兩份複製
  ⇒ 同一段邏輯散在**三處**，改一處忘兩處是遲早的事（PR #35 就是抓到本節沒跟上）。
  抽成單一腳本之後，**「同步」這個問題本身消失了**——這比「記得同步」可靠。

**自測**：真實倉庫 exit 0（掃描 22 個檔）；六條回歸測試全過；
`ci.yml` 可解析且兩個 job 的該步驟逐字相同；`ruby -c config/ci.rb` OK；
兩支新腳本 `git ls-files -s` 確認 100755。
