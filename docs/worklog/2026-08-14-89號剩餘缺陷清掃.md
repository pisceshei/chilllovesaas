## 已完成的工作 (Done)

### 一、§2 死控件 #5–#13（9 條）

共同判準：**控件畫出來就要接上行為，或明說它是示意**。
🔴 最糟的形態不是「沒反應」，是**回報成功但什麼都沒讀**——使用者以為設定生效了。
所以每一支修好的 handler 都把讀到的值講進 toast 裡，**「有沒有真的讀到」在畫面上就看得見**。

| # | 內容 | 修法 |
|---|---|---|
| #5 | topbar 商店切換器（全站每頁都在，**完全沒有 onclick**） | 接 `storeSwitch()` |
| #6 | 訂單時間軸 ☺／@ | 接 `tcInsert()`，插字元並保持游標 |
| #7／#8 | 商品／應用程式的檢視 chip | 商品頁接 `ddToggle` ＋補選單；應用程式頁明說是示意 |
| #9 | 顧客地址卡 | 接 onclick ＋ 🔴 **拆掉 `<button>` 巢狀 `<button>`** |
| #10 | 建立市場的 6 個國家 checkbox | `marketNewRun()` 真的讀 |
| #11 | 目錄發布開關 ×5 | `catalogSaveRun()` 真的讀 |
| #12 | 匯出報告 radio ×12 | `repExportRun()` 真的讀 |
| #13 | Cookie 橫幅 radio ×8 | 補 `data-f`／`value`／onchange |

🔴 **#9 的 HTML 不合法**：`<button class="pick">` 裡再包一個 `<button>`，
瀏覽器會提前閉合外層，「設為預設」被解析成**兄弟節點**而不是子節點。
改成 `div[role=button]` ＋鍵盤支援後，實測巢狀數 **0**、動作鈕成為真正的子節點。

🔴 **#13 追出一個比原始發現更深的根因**。原始發現只說「Cookie 橫幅的 radio 沒有 `data-f`」。
補上 `data-f` 之後 save bar **仍然不跳**——因為 `formRead()` 對非 checkbox 一律讀 `.value`，
而 **radio 的 `.value` 是固定的，變的是 `.checked`**。
⇒ **任何帶 `data-f` 的 radio 在髒狀態追蹤裡都是隱形的**。
這不是某一頁的問題，是機制本身漏接這個型別。已修 `formRead()` 與 `formDiscard()`。

### 二、§3 假數字 12 條

判準只有一句：**同一個指標只能有一個計算處**。
畫面上任何數字要嘛來自資料、要嘛來自另一個數字——**不得再出現第三份「看起來也對」的常數**。

完整對照表見 `docs/specs/89` §6.4。幾條值得單獨記：

- 🔴 **#9 AOV 的方向**：原本寫死的 42,470 正好等於 `total_sales / orders`，
  而 G25／R11-V13 說本尊 AOV 的分子**刻意排除 post-order adjustments、不與 net_sales 同源**。
  ⇒ 那不只是「數字不準」，是**實作了規格明文說不可以的做法**。
  而且它同時違反了**它自己 tooltip 裡寫的公式**。
- 🔴 **#11 Live View 把因果搞反了**：hbar 的寬度百分比被當成金額乘數（`w*1130`），
  於是前三名商品加總 209,050 比同頁「總銷售額」113,000 **多 85%**。
  正確方向是**金額是資料、寬度由金額導出**。
- 🔴 **#12 庫存恆等式被自己的欄位打破**：橫幅寫著「現有 = 可用 + 已佔用 + 不可用」，
  而「現有」欄只加了已佔用、漏掉不可用 ⇒ 六列有兩列違反。
  **恆等式寫在畫面上就是規格**，不能讓欄位自己破壞它。
- **#6 管道下拉**：原本 `HM_CH` 只出現在標籤與高亮。現在真的過濾，
  且**管道清單改由 `by_channel` 導出**——原本選單裡有兩個資料裡根本不存在的管道。
  無法歸因到單一管道的指標一律顯示「—」，**不拿全店值冒充**。
