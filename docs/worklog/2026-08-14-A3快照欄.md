# A-3：商品維度雙軌（84 §1 A-3／R11-V7 結案＋新登記 V7b）

## 已完成的工作 (Done)

- **補齊 `line_items` 的商品快照欄**。本尊有 **5 個「售出時的」快照維度**，
  我方 M0 只做了 3 個：
  - ✅ 已有：`title`（售出時的產品名稱）／`variant_title`（子類選項名稱）／`sku`（子類選項 SKU）
  - ✅ **本次補上**：`vendor`（售出時的產品廠商）／`product_type`（售出時的產品類型）
  - M0 的表註釋本來就寫著「下單當下不可回溯改寫的商品與金額快照」——**意圖是對的，只是沒做完**。
- **🔴 刻意不回填**：新欄 nullable 且不用當前值回填。既有列補不出正確的歷史值，
  **寧可留 NULL 表示「不知道」，也不要用當前值假裝知道**——回填會製造看起來正確、
  實際錯誤的歷史資料，而且事後沒有任何辦法分辨哪些是真的。
- **`docs/specs/87` 落檔**：雙軌事實（§1）、我方現況與補齊（§2）、寫入規則（§3）、
  附帶發現（§4）、未涵蓋聲明（§5）。
- **🔴 附帶查到一個真問題並登記為 R11-V7b**：查 `information_schema.REFERENTIAL_CONSTRAINTS`
  發現 `fk_line_items_product_variant_id` 的 `DELETE_RULE = NO ACTION`（＝RESTRICT）——
  **只要一個變體被下過單，它就永遠刪不掉**。
  - 這與快照設計**互相矛盾**：快照存在的前提是被參照物可能消失。
  - 而**商品刪除正是 M1 的範圍**（本尊權限樹有獨立的「產品 › 刪除」，81 §1.4）。
  - 🔴 **不能直接改 `ON DELETE SET NULL`**：外鍵是複合的 `(shop_id, product_variant_id)`，
    MySQL 要求所有 FK 欄可為 NULL，而 `shop_id` 是 `NOT NULL`。**這個改法在複合外鍵下不成立。**
  - 三個方向（87 §4.3）：①不做硬刪除只封存 ②拆掉變體外鍵改純快照（與 16 §159 的
    `order_pickup_points` 先例一致）③刪除時先改寫 line_items。**未裁定**，登記為 M1 做刪除前必答。
- **驗證**：rspec 52/52；rubocop／brakeman／bundler-audit／prototype lint／
  tenant isolation／reversal naming 皆 exit 0。
