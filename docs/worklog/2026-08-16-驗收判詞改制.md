背景：重啟計畫階段 0 第二步。使用者裁定「🔴＋🟡 全清才過」；條款本文已由 PR-0a
（reaudit/0a-iron-laws，先行）寫進 CLAUDE.md §驗收基準，本 PR 把判定機制落進
claude-review.yml——兩個 PR 分開走是因為本檔受反竄改保護（動它的 PR 拿不到自動驗收）。

## Done

- 判定規則改制：「存在任何一條 🔴 或**未清 🟡** ⇒ 需修改；🔴＝0 且未清 🟡＝0 才通過」；
  🟡 三清法（修復／裁定不修＋DECISIONS 明文／證偽附證據）；🔴 不適用「裁定不修」。
- 輸出格式段改：🟡 段改名「待清」並要求核對上一輪清況；新增 **⚪ 範圍外觀察**段；
  ✅ 段收已清 🟡（註明清法）。
- 🔴 三處原走 🟡 的鬆綁閥**改接 ⚪**：①doc-claims exit 0 時的散文疑慮 ②腳本抓不到的
  語義錯誤 ③上一輪沒提、本輪沒動的既有段落——不改的話 🟡 成為閘門後每輪擋一批舊帳，
  重演 2026-08-15 九輪不收斂。每處留改制註釋。
- 未通過通知留言同步：「🟡 建議 視情況採納」→「🟡 必須清（三擇一）」。
