### 2. 🔴 實測推翻了外部研究的兩條核心建議

| | 外部研究建議 | 本尊實測 | 處置 |

### 3. 🔴 一條刻意不照抄（資料遺失缺陷）

本尊按一次 `Escape` 會把 popover **與 modal 一起關掉，且 modal 內未存的改動全被丟棄**
（§15.2 重現 2 次，無任何確認）。我方 `Modal.tsx` 檔頭本來就明文設計
「Escape 尊重 `event.defaultPrevented`（內層 popover 先關自己）」⇒ 照抄等於**主動破壞
既有的正確行為**。判準：點外不關是**行為差異**（照抄），Escape 丟資料是**缺陷**（不照抄）。

### 4. 🔴 三個「在香港測不出來」的陷阱

基準法域是香港，而 `Asia/Hong_Kong` 全年 +08:00 無 DST ⇒ 三種錯誤實作只用香港測全部測綠：
①用瀏覽器時區代替店鋪時區 ②用「現在的偏移」換算未來時刻 ③牆鐘→UTC 只做一次迭代。
測資主力因此用 `America/New_York`（2026 DST 為 3/8–11/1，以 `Intl` 實測確認非查表）。

**兩次迭代**是最微妙的一條：2026-03-08 03:00 第一次會算成 `08:00Z`（錯一小時），
第二次才收斂到 `07:00Z`。MT1 突變證實只有那一格殺得掉它。

### 5. 🔴 兩張表都有 `timezone`，選錯 100% 測綠

`shops.timezone` 與 `staff_members.timezone` default 都是 `Asia/Hong_Kong`。
help 明文時區來源是店鋪 Store defaults，本尊設定頁也逐字證實兩級並存。
後端 spec 刻意把兩者設成不同值（`Europe/Paris` vs `America/New_York`）且都不是 default。

### 7. 兩處測試工具的真實限制

- `<td>` 被 testing-library 算成 `cell` 而非 `gridcell`——ARIA in HTML 的「祖先 table 是 grid
  就升級」是**上下文推導**，`dom-accessibility-api` 沒實作。改成顯式寫 `role="gridcell"`。
- 我自己的算術錯誤：測試寫 8/27 + 7 天 = 8/31，實際是 **9/3**。修正後反而多一格
  有價值的測試（方向鍵跨月自動翻頁）。

### 8. 🔴 對抗性審查：42 條 finding，10 條 🔴 全部修復

五維度 fan-out，每個 finder 在 prompt 內就被要求**實跑驗證**。三條最值得記：

**①兩條「ours 裁定」在半數時區是反的，而且程式碼根本沒實作裁定。**
審查掃了**全部 418 個 IANA 時區 ×2025–2031 的所有 DST 轉換點**：「往後推」在
**57 個時區是往回推**、「取較早」在 **73 個時區取的是較晚**。落點只是偏移正負號的副產物，
兩條敘述同時成立的只有 UTC 以西那一側——而本包當時的 DST 測資只有 `America/New_York`
（複驗：`grep -n "America/New_York\|Europe/London\|Australia/Sydney"
app/frontend/admin/lib/timezone.test.ts`，修復後應同時列出三個時區）。
⇒ 我把一個副產物寫成了裁定，還挑了唯一能自證的測資。改成顯式裁定（候選集合＋自洽性檢驗），
補 London／Sydney 的正反格。

**②`Popover` 在 `Modal` 內鍵盤完全不可達。** `Modal` 的 Tab trap 只用 `.cl-modal` 內的
focusables 算 first/last，而 `Popover` portal 在它之外 ⇒ 焦點永遠進不來
（實跑：連按 Tab 12 次只在 modal 的兩個元素間循環）。同一根因還有兩條：焦點停在觸發鈕時
按 Escape 會關掉整個 `Modal`（React 合成事件沿 fiber 樹傳播，到不了 portal 出去的 popover）、
Tab 會逃出 `Modal` 的焦點鎖。

**③vitest 沒釘 TZ，整套時區前提在這台機器上是空的。** runner 的 TZ 是 `Asia/Taipei`
——與測試用的 `Asia/Hong_Kong` **偏移完全相同**。而且 `SchedulePopover` 的 15 格**全部**
用香港，而本檔第 4 節自己宣稱「測資主力刻意用 America/New_York」——那只對
`app/frontend/admin/lib/timezone.test.ts` 成立。**我自己點名的陷阱，自己踩了。**

其餘七條 🔴：listbox 48 個 option 全在 Tab 序列且鍵盤不能選／日期欄不正規化成長格式／
`Done` 未做未改動 disabled／彈層重開不重置／roving tabindex 不 roving／
「不早於 now」比牆鐘字串（DST 日送出早於 now 的值、顯示≠實際、重開平移 ±60 分）。

🔴 **#4 與 #32 的判準互相牽動**：用「碰過沒」的旗標擋不住「改了又改回」；用 instant 比對
在重複小時**已經平移**，會把「改回原值」誤判成已改動。最後用**牆鐘值比對**才同時成立。

順手修掉一個**自己造成的**破壞：插 `def shop` 時把 `shop_locales` 的 YARD 註釋切走了。

**審查方法本身也改了**（使用者裁定）：舊設計是 5 finder → 每條 finding 生 2 個 verify agent
（S6b 那次 69 agent／780 萬 token／97 分鐘，verify 只濾掉 28%）。改成單階段五路並行、
finder 自己實跑驗證、假陽性由主控端過濾。用 `resumeFromRunId` 重啟時 finder 從快取回
⇒ 已投入的 34 個 agent 零浪費。
