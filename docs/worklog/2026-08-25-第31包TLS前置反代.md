## 已完成的工作 (Done)

### 問題不是「沒有憑證」，是「前置機沒有這個 vhost」

先前的判斷停在「WAN:443 落在 192.168.31.187，我方進不去」。實際查證後，
**憑證一直都是好的**：`.187` 對 `demo.chilling.com.hk` 送的就是那張
`*.chilling.com.hk` 萬用憑證（Let's Encrypt，2026-10-06 到期），檔案指紋與線上
指紋逐位元組相同。404 的成因是 `www.chilling.com.hk.conf` 的 `server_name` 含
`*.chilling.com.hk`，把 `demo.*` 一起吃掉，而它的 root 底下沒有 demo 的內容。

⇒ 要做的只有**一個 server block**。nginx 的 `server_name` 比對是**精確 > 萬用**，
所以新檔一存在，demo 就從 www 那個 vhost 手上接管，其餘站台不受影響。

### 取得 `.187` 的存取權

`.187` 上**沒有寶塔面板**（從 bt3 掃完全部 65535 個埠：只有
`21/22/80/443/888/5555/38682`；5555 是一支 Flask 應用、38682 是另一個 nginx
虛擬主機，都不是面板）。使用者登入的那個面板管的是 bt3。
⇒ 改走 SSH 金鑰：使用者在 bt3 的面板終端機執行 `ssh-copy-id` 並**自行輸入**
`.187` 的 root 密碼（密碼不經過工作階段）。之後 bt3 → `.187` 免密。

### 前置機新增的 vhost（不在本倉庫）

`.187:/www/server/panel/vhost/nginx/demo.chilling.com.hk.conf`——**那台機器的設定，
不進本倉庫**（它還跑著 chat／collect／erp／hktvmall／mail.chill.love／seo／

照該機既有的 `erp.chilling.com.hk.conf` 寫法：
80＋443 合併 server、`if ($scheme = http)` 導向、沿用既有萬用憑證。
`nginx -t` 通過才 reload，失敗即刪檔還原。

### 🔴 bt3 這一側的坑：`X-Forwarded-Proto` 必須透傳

鏈路是 `瀏覽器 --https--> .187 --http--> bt3:80 --> puma`。
bt3 原本寫 `proxy_set_header X-Forwarded-Proto $scheme`，而 `.187→bt3` 這一段是
**明文** ⇒ bt3 的 `$scheme` 恆為 `http`。開 `force_ssl` 的當下：Rails 以為使用者
走 http → 301 到 https → 前置機再以 http 轉進來 → **無限轉址迴圈**。
改成 `map $http_x_forwarded_proto` 透傳前置機送的值，缺該標頭時才回落 `$scheme`
（LAN 直連 bt3 的情形）。

🔴 這一條與移除 `DISABLE_FORCE_SSL` **是一組**，不能只改一邊：
只移除環境變數而不改 nginx ⇒ 迴圈；只改 nginx 不移除變數 ⇒ 沒有效果。

### 收尾

移除 bt3 `/etc/chilllove/env` 的 `DISABLE_FORCE_SSL=1`（那個變數同時控
`force_ssl`／`assume_ssl`／session cookie 的 `secure`／`SignedUpload` 的 scheme
四處）。開關本身**刻意保留**在程式碼裡——它是 TLS 壞掉時把站救回明文的退路。
