### 🔴1 五處複驗宣稱與 origin/main 實物不符（本輪最實質）

宣稱「`git show main:<path> | grep -c MAX_FIX_ROUNDS` 應為 **0**」，兩者都錯：
- **值錯**：實測 origin/main 命中 **2 行**（皆在廢止說明註釋裡，非活的常數）。
- **指令三重 fail-open**（研究＋本機實測，取證 2026-08-19）：
  1. ref 不存在時 git 走 `die()`／exit 128，但**被管道吞掉**，空 stdin 進 `grep -c` 回 **0**
     ——恰好等於「已移除」的期望讀數。依據＝POSIX grep EXIT STATUS：「1 - No lines were
     selected」但 `-c` 仍把計數寫進 stdout；實測 `printf '' | grep -c X` → stdout `0`／exit 1。
  2. 🔴 **`set -o pipefail` 零鑑別力**（這條推翻了我原本的直覺修法）：bash 官方定義是
     「the value of the last (rightmost) command to exit with a non-zero status」⇒ grep 的 1
     會**蓋掉** git 的 128。實測「ref 不存在」與「識別字真的不在」在 pipefail 下
     **stdout 與退出碼完全相同**（0／1）。另：貼進互動 shell 會永久改動使用者 session 選項；
     POSIX 到 2024 (Issue 8) 才納入、dash < 0.5.13 不支援。
  3. **Windows Git Bash 路徑轉換**：`origin/main:.github/…` 的冒號被 MSYS 轉成
     `origin\main;.github\…`。**加引號無效**（轉換發生在 msys2 runtime 組 win32 argv 時，
     shell 引號早已消化）。依據＝msys2-runtime `msys2_path_conv.cc`：只有**冒號開頭**的參數
     有豁免（`/* Prevent Git's :file.txt and :/message syntax… */`）。

**採用的修法**（研究建議＋本機實測驗證）：改用
`git grep -c -F -e <PAT> <ref> -- ':/<path>'`——ref 與 pathspec 是**兩個獨立 argv、參數無冒號**
（Windows 免逃生變數），且 ref 不存在時 **exit 128 大聲失敗**（實測：`fatal: unable to resolve
revision`／exit 128，stdout 空）。`:/` ＝ `:(top)`，順帶解掉「pathspec 預設相對 cwd、
從子目錄跑會假性回 0」。六處全部替換，研究依據寫成一份共用註記放 `CLAUDE.md` 17.4。

**明確不採用的做法**（各有依據，記下來免得後人再走一次）：`set -o pipefail`（零鑑別力）／
加引號（無效）／`MSYS_NO_PATHCONV=1`（只修 Windows 那一層，ref 缺失的 fail-open 原封不動，
且對 Linux 讀者是無意義噪音）／雙斜線 `//origin/main:`（ref 名變成 `//origin/main`，換一種失敗）。
