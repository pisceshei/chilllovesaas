# 工作記錄：金額值物件 R1／R4／Display（M1 PR-1 第 6 步，2026-08-15）

## 已完成的工作 (Done)

`app/models/money.rb`：`Money::Storage`（R1）、`Money::Decimal`（R4）、
`Money::Display`（R3 骨架）＋ 三個例外類別。

### 🔴 L2「唯一建構路徑」在 `Data` 上有**三條**後門，不是一條

規格 §C L2 說「`.new` 設 `private_class_method`」，但 `Data.define` 另外給了：

| 後門 | 實測（Ruby 3.4.10） | 危險在哪 |
|---|---|---|
| `Klass[cents: 1, currency: "HKD"]` | 建得出完整實例 | 與 `.new` 等價 |
| `instance.with(currency: "JPY")` | 建得出完整實例 | **「換幣別、保留同一個數字」變成一行**——那正是跨幣別事故的形狀 |
| `Klass.allocate` | 建得出 `cents=nil` 的實例，**而 `is_a?` 為 true** | 🔴 **L3 的 adapter 斷言只看 `is_a?`** ⇒ 一個全 nil 的假金額可以直接穿過型別防線 |

三條全部關掉（`private :[]`、`private :allocate`、`undef_method :with`），
spec 三條都斷言。**只斷言 `.new` 的測試會全綠交付，而 L2 是假的。**

### 🔴 `format("%.2f", big_decimal)` 內部會轉 Float——BIGINT max 上失真

第一版 `to_decimal` 用 `format`，往返測試在 **BIGINT max** 上紅：

```
cents = 9223372036854775807
舊寫法 → "92233720368547760.00"   ← 差 2 分錢
新寫法 → "92233720368547758.07"   ← 往返一致
```

⚠️ 這個 bug **只在極大值現形**，一般金額測試全綠——與 65 §0.2 描述的
「exponent=2 幣別下測試全綠」是**同一種病**：**測試選的樣本決定了看不看得到**。
T10（USD 邊界值 `0` / `1` / BIGINT max）就是為此存在的，而它抓到了。

修法：`Money.fixed_string(BigDecimal, digits)` 全程整數／BigDecimal 運算，不經 Float。

### 其他判斷

- 🔴 **型別層不驗正負**（65 §A.7，本輪考掘後新增的那一節）：
  在 `Money::Storage` 上驗非負會讓退款差額與撤銷整條卡死。
  正負的業務規則驗在**寫入端與 PSP adapter**。spec 有一條 `-500` 的正面斷言。
- **跨幣別比較 raise 而不是回 false**：「兩筆金額不同」與「兩筆金額不可比」是兩件事，
  靜默回 false 會把後者偽裝成前者。
- **`Display` 只做兩位小數骨架，不帶幣別符號**：符號與千分位由**市場的 locale**
  決定（鐵律 10），而 markets 是 M5——在這裡硬編 `HK$` 就是把一個 per-market
  的決定寫死成全域常數。spec 有一條「不得含 `HK$`、不得含 `,`」的斷言釘住。

### 鐵律 6 的驗法：stub 比 grep 強

除了「原始碼不得含 `to_f`」的 grep 式斷言，另加一條：
**把 `storage_scale_multiplier` stub 成 1000，`to_decimal` 的輸出必須跟著變**。
grep 只能證明「原始碼裡沒有那個字面量」，stub 能證明「換了設定值，行為真的跟著換」。

## 尚未完成或需注意的風險 (Pending / TODO)

- 🔴 **R5／R6 與 PSP registry 不在本步**（S7）。在它們落地之前，
  `Money::Storage` **沒有任何對 PSP 的出向路徑**——這是刻意的：
  `to_psp_amount` 必須依 pack 宣告的 `amount_format` 分流，而 registry 是 S7 的東西。
- 🔴 **算術行為完全未定義**（65 §F.3 只講 SQL rollup，值物件層是空白）：
  `Money::Storage` 目前**不能相加相減**。業務層（訂單小計、折扣）需要大量加減，
  現在猜一個實作，第一個使用者就會繞過它寫 `a.cents + b.cents`。
  ⇒ 留給第一個需要小計／折扣的 PR 定義，那時才有真實需求可對照。
- ⚠️ **`Money::Decimal#to_storage` 的位數檢查靠字串長度**，而 `from_string` 已經用
  `decimal_string_regex` 擋過一次 ⇒ 正常路徑下第二次檢查恆真。
  它存在的意義是「regex 被放寬時仍然擋得住」（spec 用 stub regex 證明了這一點）。
- ⚠️ **`fixed_string` 的 rounding 語義是 `BigDecimal#round` 的預設（half-up）**。
  目前 `storage_scale`（100）與 `decimal_digits`（2）相容 ⇒ **永遠不會真的 round**。
  若日後兩者脫鉤（例如 scale 改 1000），rounding 就會真的發生，
  而**「金額該怎麼 round」規格沒寫** ⇒ 屆時要先裁定，不得沿用預設。
- **`Money::Display` 沒有 locale 概念**：M5 接上 markets 時，它的簽名要加 market／locale 參數。
  現在的 `call(storage)` 是過渡形態。
- **`app/` 仍然沒有任何生產呼叫端**（`Money::` 零命中，`ProductType` 連價格欄位都沒有）。
  本步的正確性靠三件事保證：規格逐行寫死的欄位形狀、spec 的 22 條斷言、
  以及 S7／S8 的矩陣與 CI 執法。**這一點必須寫進 PR 描述**，不得假裝已經被使用。
