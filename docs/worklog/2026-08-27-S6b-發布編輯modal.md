### 2. 🔴 抓包解掉了 §13.2 當時只能寫成「推測」的那一半

`82` §13.2 記過「本尊把兩個方向放在同一個 GraphQL document 裡（**推測**，document 內容不可觀測）」。
本輪錄到 request body，拿到**逐字證據**：

```
ProductSaveUpdate 的 variables：
  "publicationsToPublish": [{"publicationId":"…"}], "publicationsToUnpublish": [],
  "shouldPublish": false, "shouldUnpublish": false
ProductSavePublishablePublishUnpublish 的 variables：
  "shouldPublish": true, "shouldUnpublish": false
```

⇒ **兩支 document 共用同一組變數，靠 GraphQL `@include` 逐向開關**，不重複寫入。
媒體也是同一套（`shouldUpdateMedia`／`shouldReorderMedia`）⇒ 這是本尊 admin 的通用形態。
我方照做：變數名與開關名全對齊。

### 4. 關卡④拿到一條決定性的第一方規範

🔴 `role="switch"` **不支援** `aria-checked="mixed"`——MDN 逐字
"assigning a value of `mixed` to a `switch` instead sets the value to `false`"。
⇒ 群組總開關若照各列的樣子寫成 switch，**半選態會被螢幕閱讀器讀成「關」**，
而畫面完全正常、任何視覺測試都不會紅。改用 `role="checkbox"`。

另拿到一條**規格出處**：Microsoft Win32 UX Guide 的 owned property window 條文與我方形態
逐字一致，其中 "make sure users can cancel changes made in an owned property window by
clicking Cancel" 直接對應「頁面捨棄要能撤銷 modal 內的變更」——而那一條我**原本沒驗**，
補測後發現是把 delta 放進 `values` 的自動收益。

### 7. 🔴 前端 GraphQL document 對真實 schema 的驗證（測試抓不到的那一層）

前端測試用的是 **mock fetch** ⇒ **結構上驗不到 document 與後端 schema 是否相容**。
`@include` 這種 directive、top-level field 位置寫錯，測試會全綠、上線才炸。
本包因此另外跑了一次靜態驗證（只讀，不寫入）：

```

  puts ChillloveSchema.validate(q).map(&:message).inspect'
```

三份 document 皆通過：`PUBLISHING_MUTATION`（`@include` 被 schema 接受）、
`PRODUCT_QUERY`（top-level `publications` 合法）、`PUBLICATIONS_QUERY`。

### 8. 🔴 對抗性審查（初始候選 `12d3c28` 推出後）——23 條通過，9 個真問題本輪全修

五維度 fan-out（正確性／對齊本尊／無障礙／測試充分性／跨模組影響），每條 finding 再由
兩個獨立 lens 嘗試推翻（一個實際讀碼推演、一個查是否已登記過）。32 條 → **23 條通過雙 lens**。

**兩條 🔴 都是我自己的測試結構上抓不到的**：

1. **`changed` 判準錯**（三個維度獨立發現）。判準寫成「draft 兩邊皆空」而不是
   「draft ≠ 開場暫存」。差別只在**開場就已有暫存**的 session 顯現：
   關掉線上商店→完成→重開→撥回開 ⇒ `toggleChannel` 把 id 從兩邊移除 ⇒ draft 變空
   ⇒ **完成鍵 disabled，按不下去**；而取消依 §14.4d 保留先前暫存。此時 modal 內的三個
   出口逐一檢查：完成（disabled）／取消（保留先前暫存）／Escape 與 scrim（等同取消）
   ——三者都撤不掉它；剩下的只有 modal 外的頁面層「捨棄」，而那會連標題／價格／變體
   一起丟。沒察覺就儲存 ⇒ 商品真的被下架，**而畫面上那個開關當時顯示為「開」**。審查附實跑：`DONE disabled = true`、
   `SENT = {...unpublish:[Publication/1], shouldUnpublish:true}`。
   ⚠️ 我原本引 §12「還原後 Done 全程 disabled」當依據——那次量測**開場 delta 為空**，
   兩種判準在該情境重合、分不出來，射程不涵蓋此情境。

2. **`reloadPublications` 完全不可觀測**。重讀路由回的是**與初始相同**的那份 fixture，
   且全檔沒有一個 `callsTo(..., "query productPublications")` 斷言 ⇒ 刪掉呼叫那一行，
   55 格全綠。**與 M5 同型的相等陷阱**——我在同一個包裡犯了兩次同型錯誤。

**七個 🟡**：發布 mutation 拋例外時 `lockVersion` 沒吸收（此後每次儲存都撞 `STALE_OBJECT`，
實跑 `LOCKV = 3,3`）／`variantOverflow` 連坐（實跑 `PUBCALLS = 0`，**直接推翻我 dev doc 裡
「無正確性問題」那句登記**）／`Query.publications` 含 catalog publication 會混進「銷售管道」節／
`.cl-switch--mixed` 只覆寫 width 未覆寫 height ⇒ 渲染成**直立短棒**／齒輪沒有 `disabled={saving}`
⇒ 儲存中可重開 modal、之後的 toast 落在 inert 樹內對 AT 靜默／搜尋結果無 status message
＋群組 accname 不含可見文字（WCAG 4.1.3 與 2.5.3）／搜尋框把三個**未量測**屬性寫成「本尊形態」。

🔴 **CSS 那條特別值得記**：我上一輪「驗算」過 translate，但只算了水平位置、**沒檢查形狀**——
`width: 4px` 而 height 沒覆寫 ⇒ 4×14 的直立短棒。而我第一版寫的 `translate: 7px` 其實是對的
（對 14px 寬的橫線而言），我的「修正」把一處錯誤變成兩處。正解是
`width:14 height:4 top:7 translate:7px`。
