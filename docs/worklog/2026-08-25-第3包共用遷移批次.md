### 遷移（一支）

`products` +3（variants／media／publications 的 `*_updated_at`）、
`collections.products_updated_at`（14 §F1）、`shops.catalog_version`、
`files.alt_source`、`orders.locale_snapshot`。

- 🔴 stamp 欄**刻意 nullable**：`null: false` 會要求每個 `Product.create!` 呼叫點都帶值
  （炸掉全部 factory）；null＝「立欄前未變動過」，快取 key 端當 epoch。
  backfill 仍做（`updated_at` 是三者的上界——全樹鎖下任何儲存都 bump 它）。
- 🔴 `alt_source` **nullable、不 backfill**：存量 alt 的來源是未知的，猜成 human
  就是把未取證假設寫進資料（鐵律 19）。
- 遷移做成**冪等**（`if_not_exists`）：第一次跑就撞到「MySQL DDL 不進交易」——
  backfill 被 strong_migrations 擋下時，欄已加、版本未記，重跑撞 Duplicate column。

### 🔴 寫入接線：欄位在、沒人 bump＝永久舊快取

stamp 的失敗形態是**靜默的**（顯示舊圖舊價、零錯誤），所以接線與建欄同一包：

| 欄 | 寫入者（本包接上）|
|---|---|
| `variants_updated_at` | `SaveProduct`（宣告式全量恆重寫變體樹 ⇒ 恆 bump，不精算）＋`DeleteVariant` |
| `media_updated_at` | `MediaSync` 六個口（create／update alt／delete／reorder／append／卸圖）＋`ProcessFile`（ready 與 failed 都是呈現變化）＋`FileWrite.update`（alt）＋`FileWrite.delete` |
| `collections.products_updated_at` | `SaveCollection#sync_members!` |
| `publications_updated_at` | **無寫入者**（發布 mutation 屬第 12 包）——欄先立，接線隨那包 |
| `catalog_version` | **無寫入者**（市場屬第 32 包）——同上 |

複驗接線全集＝`git grep -n "CacheStamps\." app/`。

🔴 **檔案層寫入 bump 的是「所有用到這個檔的商品」**：D48 之後一張圖一份 alt，
從檔案庫改一次＝所有掛著它的商品頁都變了。只 bump 一個商品＝其他商品留在舊快取
顯示舊 alt——`bump_media_for_file!` 就是為這條存在，並有跨商品 spec 釘住。

### 🔴 本包最重要的一個發現：Rails 8.1 的 `update_all` 會動樂觀鎖

`CacheStamps` 檔頭②明文要求「不得 bump lock_version」（否則改一張共用圖的 alt
會讓所有正在編輯相關商品的人存檔撞 STALE_OBJECT）。**而 Rails 8.1 的 `update_all`
對有樂觀鎖的 model 會自動 +1 `lock_version`**——hash 形式的
`update_all(media_updated_at: Time.current)` 實測讓 0 → 1，首輪就被既有 C6 spec
的 `product.destroy!` 撞 StaleObjectError 抓到。
修法＝官方 opt-out：把 locking column 顯式列進更新
（`… , lock_version = lock_version` 字串形式），並有專門 spec＋突變驗證釘住
「改回 hash 形式要轉紅」。
