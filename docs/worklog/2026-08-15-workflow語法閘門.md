### 1. 問題：一個保護真空

### 2. `scripts/check-workflow-syntax.rb`

兩條規則：

1. `.github/workflows/*.yml` 每份必須是**合法 YAML**
2. 每個 step 的 `run:` 區塊必須過 **`bash -n`**（只檢查語法，不執行）

三個實作決定：

- **GitHub 表達式先換成佔位符**。`${{ ... }}` 直接送 bash 會是 bad substitution ⇒ 誤報。
  目前倉庫的 run 區塊裡**一個表達式都沒有**（實測 25 個 run 區塊、0 個），
  但第一個用它的人不該撞到假警報。
- **只送 bash 系的 shell**（未宣告＝預設 bash）。宣告 `shell: pwsh`／`python` 的跳過。
- **掃到 0 份 workflow 就 fail**，不是印 OK ——同 `check-exec-bits.sh` 的 canary，
  防「空值長得像資料」。

🔴 檔頭有**誠實聲明**：**這不是 actionlint**。不驗 action inputs 是否存在、
不驗 `${{ }}` 內的表達式語義、不驗執行期行為。
（前例就在同一份 workflow 的註釋裡：`with: model:` 在 action v1 是**未知 input，
GitHub 靜默忽略**——那一類本腳本抓不到，要靠 actionlint 或讀 action.yml。）

### 3. `scripts/test-workflow-syntax-rules.rb`（四條）

| fixture | 期望 | 守什麼 |
|---|---|---|
| `wf_clean` | exit 0 | 🔴 反向斷言，且**刻意含 `${{ }}` 與 heredoc**——兩者都是最容易誤報的形態 |

## 驗收後修正（PR #42 第 1 輪 Codex review，六條，逐條複驗）

### 🔴 P1：`bash -n` 對未閉合 heredoc **exit 0**

實測：

```
$ printf 'cat <<EOF\nnever terminated\n' > hd.sh && bash -n hd.sh; echo "exit=$?"
hd.sh: line 2: warning: here-document at line 1 delimited by end-of-file (wanted `EOF')
exit=0                     ← 🔴 只在 stderr 印警告，退出碼是 0
```

⇒ 只判 `status.success?` 的話，這一類**完全放行**。
🔴 而 `claude-review.yml` 記載的兩次語法事故，**其中一次正是 heredoc**
——**這道閘門原本擋不住它宣稱要守的兩件事之一**。

**修法**：`stderr` 有任何輸出就算違規。
實測本倉庫 **27 個 run 區塊 stderr 全空** ⇒ 不會製造誤報；
且它的失效方向是「吵」不是「靜默」，那是對的方向。
新增 `wf_bad_heredoc` fixture 守住。

### 🔴 P2：裸日期讓腳本崩掉

`YAML.load_file` 預設不許 `Date` ⇒ 含 `SINCE: 2026-08-15` 的 workflow 會丟
`Psych::DisallowedClass`。本腳本原本只 rescue `Psych::SyntaxError`
⇒ **帶著 Ruby backtrace 崩掉**，CI 上只看得到 backtrace，讀的人不知道是哪份 workflow。

**修法**：`permitted_classes: [Date, Time, Symbol]` ＋ 加 rescue `Psych::Exception`
（仍報成違規，**不讓腳本崩掉**）。

### 🔴 P2：自訂 shell 模板被靜默跳過

GitHub 的 `shell:` 可以是模板，例如 `bash -e {0}`、
`bash --noprofile --norc -eo pipefail {0}`（**後者正是 `run:` 的預設**）。
原本用 `[nil, "bash", "sh"].include?(shell)` 判斷 ⇒ 這些寫法**一個都不匹配**
⇒ 那些 run 區塊被**靜默跳過不檢查**——又是「檢查沒驗到目標」。

**修法**：`interpreter_for(shell)` 取第一個 token 的 basename 判斷；
順帶採納另一條 P2——**宣告 `sh` 就用 `sh -n` 檢查**，不要用 bash 的寬鬆語法放行。

### 未採納 / 未處理

- **`${{ }}` 內含 `}}` 字面**（例如 `fromJSON('{"a":{}}')`）會讓非貪婪 regex 截錯。
  目前倉庫 **0 個表達式**，且真出現時是 `bash -n` **誤報**（吵而不是靜默）
  ⇒ 可接受的失效方向，**本輪不處理**，已寫進腳本註釋。
- **重複 YAML 鍵**：Psych 預設不報錯，GitHub Actions 會。這需要自己走 AST 比對，
  **本輪沒做**，登記在下面 Pending。

### 補測後的回歸測試（3 條 → **6 條**）

新增 `wf_bad_heredoc`（exit 1）與 `wf_date_scalar`（exit 0）。
後者是**第二條反向斷言**，且刻意「合法但最容易被誤判」——
它同時覆蓋裸日期與自訂 shell 模板兩個坑。

自測：6 條全過；真實倉庫 exit 0（27 個 run 區塊，比修前多 2 個——
**那 2 個正是原本被靜默跳過的**）；rubocop no offenses。
