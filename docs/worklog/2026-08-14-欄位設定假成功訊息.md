# `lcolumns` 欄位設定：17 個清單頁的假成功訊息（89 §2 #4）

> 承接 `docs/specs/89` §2 的死控件清單第 4 條——我在上一份 worklog 標為
> 「嚴重度不低於本次四條 P0，下輪優先」的那一條。

## 已完成的工作 (Done)

### 一、問題

`lcolumns()` 的 checkbox **一律 `checked`、沒有 onchange、`c.cols` 不回寫**，
按「套用」卻 toast「Demo：欄位設定已存回目前檢視」。

- **爆炸半徑 17 個清單頁**（drafts／cols／cust／seg／disc／gift／mobj／blog／mkt／cat／
  rep／xfer／pages／aband／slab／camp／camp0），因為它們共用同一支通用清單引擎。
- 🔴 **假成功訊息比「沒反應」更糟**：沒反應時使用者知道要回報；
  回報成功時使用者以為設定生效了，**之後看到的每一張表都在騙他**。

### 二、修法

- `lstate()` 加 `hidden`（Set）——🔴 **存 `cfg.cols` 的原始索引，不存欄名**，
  因為 `s.sort` 也是原始索引，兩者必須指向同一套座標。
- thead（`listPage`）／tbody（`lbody`）／空態 colspan 三處同步跳過隱藏欄。
- `lcolumnsApply()` 真的回寫 `s.hidden` 並 `lrender()`，toast 回報**實際欄數**。
- 全部取消勾選時擋下並顯示警告（不能有零欄的表）。
- 隱藏「正在排序的那一欄」時自動取消排序。

### 三、兩個容易寫錯的點（都實測驗過）

| 點 | 為什麼會錯 | 實測結果 |
|---|---|---|
| 用 `map`→空字串而**不是 `filter`** | `filter` 會重排索引，而 `lsort(key,i)` 傳的必須是原始索引 ⇒ 隱藏一欄後排序會錯位到別欄 | 隱藏索引 1、2 後其餘表頭 onclick 仍是 `0/3/4/5`；排序箭頭仍在「消費金額」 |
| 隱藏「正在排序的欄」要取消排序 | 否則「看不到的欄在決定順序」 | `s.sort` → `-1`、`th.sorted` 數 → 0 |

### 四、驗證（顧客清單頁 `cust`，實跑瀏覽器）

| 項 | 結果 |
|---|---|
| 隱藏 2 欄 | 表頭 6→4；首列 td 7→5；**表頭數＋bulk 欄 ＝ td 數** ✅ |
| toast | 「已套用欄位設定（顯示 4 欄、隱藏 2 欄）」——回報實際值 |
| 重開設定 modal | 勾選狀態記住（`[true,false,false,true,true,true]`） |
| 全部取消 | 被擋，警告可見，modal 不關 |
| 復原 | 表頭與 td 數都回到 6／7 |

## 追加：回應 PR #27 的 Codex review

**「隱藏欄是逐檢視的，不是逐清單」**——屬實，而且是**與畫面上自己寫的說明相反**。

`41` §1.3 逐字「欄位設定存在檢視上、不影響其他檢視」，modal 的說明文字也這樣寫，
但我第一版存成 `s.hidden`（掛在 `LS[k]` 上）。`lsetView()` 只改 `s.view`，
所以在「全部」檢視隱藏兩欄，切到「已訂閱」檢視那兩欄也不見了。

修法：`s.hidden` → `s.hiddenByView[view]`，加 `lHidden(s)` helper 統一取值；
toast 補上「——僅影響目前檢視」，讓回饋與說明一致。

實測（顧客清單，4 個檢視）：

| 步驟 | 結果 |
|---|---|
| 檢視 0 隱藏索引 1、2 | 表頭 6→4 |
| 切到檢視 1 | **完整 6 欄**（不受影響）✅ |
| 檢視 1 隱藏索引 5 | 表頭 6→5 |
| 切回檢視 0 | **仍隱藏 1、2** ✅ |
| 內部狀態 | `{"0":[1,2],"1":[5]}` |

🔴 **教訓**：我在同一個 modal 裡把「欄位設定儲存在目前檢視上」這句說明**照抄下來**，
卻沒有讓實作滿足它。**畫面上的說明文字就是規格**——抄了就要做到，
否則它跟假成功訊息是同一種東西（本 PR 修的正是假成功訊息）。
