# 2026-08-25 第 28 包後修：刪檔留下衍生空目錄

## 已完成的工作 (Done)

**線上驗收抓到的洩漏**（第 28 包合併部署後，於 bt3 量測）：`fileDelete` 正確刪掉了
衍生檔本身，但**留下空目錄**。實測數字（bt3，2026-08-25，複驗指令見下）：

```
files 列數=14   files/ 底下 blob 數=14        ← 原圖對得上
derivatives/{file_id} 目錄數=31               ← 但衍生樹有 31 棵
derivatives 樹的空目錄數=17                   ← 差額＝本輪刪掉的檔數
derivatives 樹的檔案數=56                     ← 14 × 4 個尺寸，衍生檔本身刪對了
```

根因：`Storage::LocalDisk.delete` 用 `FileUtils.rm_f`，只拿掉檔案、不動目錄。
對 `shops/{id}/files/` 沒差（全部 blob 共用一層），但衍生 key 是
`shops/{id}/derivatives/{file_id}/{checksum}/{variant}.webp`——**每個檔案自己一棵樹**，
刪一個檔就永久留下兩層空目錄，而且沒有任何東西會來收。累積的是 inode 不是位元組，
但一樣是單向成長，性質與 staged 孤兒同類。

**修法**：新增 `Storage::LocalDisk.delete_with_empty_parents(key, stop_at: root)`
——刪檔後往上收空目錄，`Dir.rmdir` 對非空目錄丟 `ENOTEMPTY` 就是天然的停止條件
（不必自己判斷「還有沒有別人在用」，也就沒有「以為空的其實不空」的競態），
收到 root 就停、絕不刪 root。

**射程＝同一個孤兒目錄產生者的完整集合**（鐵律 20.5）：
- `Storage::FileWrite.delete` 的衍生刪除（本次線上抓到的那條）
- `MediaPipeline::ProcessFile` 的**兩處**失敗補償刪除（`write_derivatives!` 的 rescue、
  以及 checksum 在本輪期間被 replace 換掉時丟棄本輪結果）——同樣寫在
  `derivatives/{file_id}/{checksum}/` 底下，同樣會留空目錄
原圖 blob 的刪除**刻意不改**（共用一層，收了下次上傳還要重建）。

**反向複驗**：`spec/services/storage/local_disk_spec.rb`（6 例）——正面（兩層都收）、
反面（同層還有別的尺寸就留著）、**不得往上收進共用層**（`files/` 還有別的 blob）、
收到 root 就停、檔案不存在不報錯、**舊 `delete` 保持原行為**（兩支語義不得混淆）。
另在 `spec/requests/files_library_spec.rb` 的刪除例加一條整合斷言。

- 測試：rspec **587/587**（複驗＝`bundle exec rspec`）。

## 尚未完成或需注意的風險 (Pending / TODO)

- **既有的 17 個空目錄不會被本修法追溯清掉**：修的是產生端，不是清掃端。
  它們無害（空目錄、無資料），下一次該 file_id 重新產衍生時會被重用。
  🔴 **刻意不寫一次性清理腳本**：一支只跑一次的刪目錄腳本，風險（路徑打錯刪到別的）
  高於它解決的問題（17 個空目錄）。複驗現況：
  `find storage/chilllove/shops/*/derivatives -type d -empty | wc -l`
- **本修法只涵蓋本地磁碟後端**：`storage_backend` 換成物件儲存時「空目錄」這個概念
  不存在（S3 沒有真目錄），屆時本支會變成 no-op，不需要移植。
