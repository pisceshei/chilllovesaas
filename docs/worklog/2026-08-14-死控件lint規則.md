# 死控件機制化：`r_dead_control` lint 規則（89 §7）

> 承接 89 §2 那 25 條——**全部是 lint 綠燈但實際壞的**。
> 用它們當測試案例：正面不得誤報、負面必須抓到。

## 已完成的工作 (Done)

### 一、規則本體

判準**不是**「必須有 onclick」，而是「**有沒有一個真的被選擇器用到的把手**」。
理由：89 §2 修好的控件多數沒有 inline handler（`querySelectorAll('.mkt-country')`、
`getElementById('rfOverOK')`、`input[name="expfmt"]:checked`、`data-set` 事件委派）。
🔴 **天真規則會把本輪修好的東西全部誤報，然後被人關掉——比沒有規則更糟。**

放行條件：inline handler／`data-f`／`data-val`／`disabled`／
把手出現在真正的選擇器上下文／`data-read="<讀它的函式名>"`。

### 二、三個非做不可的收斂（每一條都是實測踩出來的）

1. **剝掉註釋**——本檔的防回退註釋逐字引用壞掉的 markup，不剝的話規則會抓到自己的說明文字。
2. **不跨行 ＋ `${...}` 內的 `>` 不算結束**——`[^>]*` 會讓 `<button` 吃到很多行後的 `>`，
   回報行號完全對不上；`>=` 會提前截斷屬性、使 onclick 落在範圍外。
   🔴 **交替順序要緊**：`${...}` 必須排在 `[^>\n]` 前面，否則 `[^>\n]` 會先逐字吞掉 `$`、`{`…，
   等走到 `>=` 才失敗，`${...}` 分支永遠輪不到。
3. 🔴 **把手只認 DOM API 上下文**——本原型的 markup **寫在 `<script>` 的模板字面量裡**，
   任何屬性值本來就出現在 script 字串中 ⇒「有沒有出現過」是**自我滿足**的，永遠成立。
   （負面測試實證：Cookie 橫幅 radio 退回舊寫法，寬鬆版照樣放行。）

另補一層：選擇器帶 `[attr]` 條件時，控件必須也有那些屬性才算被命中——
`querySelectorAll('.tgl[role="switch"]')` 用到了 `tgl`，但只有 `class="tgl"`、
沒有 `role` 的開關**不會被它選中**。

### 三、逃生口刻意「會自我說明」

`data-read="<函式名>"`，**且那個函式必須存在**。實測指向不存在的函式 → 照樣報。
純靜音的逃生口會被拿來搪塞。

### 四、存量基準線——讓規則咬得住「新增」

規則一上線抓到 **73 條存量**，全報 WARN 的話 lint 會從 13 個警告暴增到 86 個。
🔴 **沒有人會讀 86 個警告，規則就等於白做**——這正是「加了規則卻被忽略」的典型死法。
⇒ 存量報 WARN，**超過基準線一律 ERROR**（admin 14／platform 12／storefront **47**）。

## 尚未完成或需注意的風險 (Pending / TODO)

- 🔴 **73 條存量未修**，其中 **storefront 47 條——那個檔從未被稽核過**。
  這是本輪最大的新發現：規則抓到的比人工稽核多，而且多在沒人看過的檔案裡。
- 🔴 **基準線會腐化**：清掉存量後**必須順手調降數字**，否則它會變成新的容忍額度。
  規則的錯誤訊息已寫明這件事，但**沒有機制強制**——這是本規則自己的紀律缺口。
- **class 把手仍是啟發式**：只能判斷「有選擇器提到這個 class 且屬性條件相符」，
  無法真的做 CSS selector matching。同名 class 被別處選擇器用到時仍可能放行。
- **`data-read` 只檢查函式存在，不檢查它真的讀了那個控件**——同 `r_dangling_onclick` 的限度。
- **規則掃三個原型檔**（admin／platform-admin／storefront）。
  本輪只逐條看過 admin 的 14 條，另外兩檔的 59 條**沒有人工複核過**。
