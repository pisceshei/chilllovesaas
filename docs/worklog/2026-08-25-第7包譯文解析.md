## 已完成的工作 (Done)

### 新功能

1. **`Locales::FallbackChain`**——BCP-47 截尾鏈（67 §C.4(a)）。純函式。
   截到 `i18n.forbidden_locale_tags` 就**停止整條鏈**（不是跳過該階繼續截）；
   `never_fallback_pairs` 的雙向過濾；`fallback_chain_mode` 非 `bcp47_truncation` 一律 raise。
2. **`Translations::BlankValue`**——「等於沒有翻譯」的判準，讀寫共用**同一支**
   （消費者導出＝`git grep -n "BlankValue.blank?" -- app/`）。
   `kind: :text | :html`；HTML 走 `Loofah.fragment`（＝與 sanitizer 同一支 parser）。
3. **`Translations::Fields`**——可翻欄位的中繼資料（kind／missing／base 屬性／上限與**單位**）。
4. **`Translations::Resolve`**——67 §C.4 的四步演算法，批載形態，附 `i18n.fallback_hit` 遙測。
5. **`Translations::Audit` ＋ `lib/tasks/translations.rake`**——既有譯文稽核，四條規則
   ＋一條**明文棄權**；`translations:fix` 只修其中兩條。
6. **`Locales::Registry.published_tags`**——前台解析範圍（`published` ≠ `enabled`）。

### 修復的缺口（三個，兩個是線上實測到的）

| # | 缺口 | 實證 | 影響 |
|---|---|---|---|
| 1 | 🔴 譯文 `body_html` **完全不 sanitize** | bt3 正式環境 rev `1a75ceb`，`rails runner` 實跑：同一段 payload 走 base 落庫 `<p>ok</p>alert(1)<img>`，走譯文**原樣落庫**含 `<script>` 與 `onerror` | 第 30／34 包渲染的那一刻＝儲存型 XSS |
| 2 | 🔴 `CsvImport` **完全不重算 `translation_status`** | 同上實跑；`csv_import.rb` 內零個 `recompute_status` 呼叫 | 後台進度徽章不動；`translation_status.updated_at`（67 §G.3 建議的 cache stamp 載體）不推進 ⇒ 第 3 包會在已知破的不變式上建快取失效 |
| 3 | 舊 `blank_value?` 有 **8 格誤判**（全部同一方向） | 本機 `bundle exec ruby` 實跑 24 格對照 | `<p>&#160;</p>`／`<p>　</p>`／`<p>​</p>`／`<p class="x"></p>` 等被判成「有翻譯」⇒ fallback 永不觸發 ⇒ 商家看到空白區塊而不是原文 |

另修：`CsvImport#write_row` 每列各查一次 `source_tag` 的 N+1；譯文 `body_html`
的長度上限**量錯單位**（base 用 `bytesize`、譯文用 `length` ⇒ 中文譯文拿三倍額度）。

### 一個既有測試的行為被刻意改掉

`spec/requests/product_translations_spec.rb` 原有一格用 **`title`** 送 `<p><br></p>` 並期待被刪。
67 §C.4(b) 原文把 HTML 那一條明文限定在**富文本欄位**（「NULL、空字串、只含空白字元的字串
三者等價視為『無譯文』。🔴 富文本欄位**另加一條**：`<p></p>`／`<p><br></p>` 這類語義空的
HTML 也算空」）。舊實作不看欄位型別 ⇒ 把富文本規則套到純文字欄上 ⇒ 商家在標題欄真的打了
`<p><br></p>`（標題欄不是 RTE）會被靜默刪成「未翻譯」。
⇒ 改成 `body_html` 送空 HTML、`title` 送空字串，並**新增**一格反向斷言純文字欄不判空。

### 一個裁定（研究建議被否決）

研究階段建議 `read_path_blank_check: text_only`（讀取熱路徑只跑快篩 ~1.1µs、完整判準 ~85µs
留寫入端）。**否決**：四個可翻欄位只有 `body_html` 是 `:html`，商品詳情頁 ≈1 次、
50 筆列表頁全解析也只有 ~4ms，而代價是「同一個值讀寫兩種答案」的漂移——正是本包要消掉的東西。
limits 改記 `single_implementation_for_read_and_write: true`。

- `app/services/translations/csv_import.rb` — `__CLEAR__` 在 sanitize **之前**判；補 `sanitize`；
  判空改 `BlankValue`；收集 `touched` 並在收尾 `recompute_status`（`dry_run` 不做）；
  `source_locale` 由呼叫端帶下去（修 N+1）；`source_text_for` 改用 `Fields.base_value`
- `config/limits.yml` — 新增 `i18n.resolve.*`（7 鍵）與 `i18n.blank_value.*`（5 鍵）；
  `truncation_stops_at_forbidden` 補 CLDR 出處與 RFC 偏離登記；
  `mark_fallback_with_lang_attribute_on` 補「值是 resolved_locale 不是請求語言」
- `spec/requests/product_translations_spec.rb` — 見上「一個既有測試的行為被刻意改掉」

**核心不變量**

1. 前台不得靜默空白：required 缺翻 ⇒ 回 base；optional 缺翻且原文也空 ⇒ **整個欄位不輸出**。
2. `translations.value` 的**每一條寫入路徑**都經同一套 sanitize 與同一套判空。
3. 後台 GraphQL 的 `translations` **永遠是精確比對**，不接 Resolve。
4. 遙測只在 `depth >= 1` 發，payload 不含 `resource_id`。
