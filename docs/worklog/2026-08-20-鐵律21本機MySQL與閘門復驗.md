  找到 `docs/worklog/2026-08-13-本機環境部署與M0全套實測.md` 記載的手動啟動入口
  `C:\Users\pisce\chilllove-mysql\start-mysql.cmd`；讀取檔案確認它使用既有 datadir、MySQL 8.4，
  並只綁定本機回環位址。
- 以隱藏背景程序啟動既有 launcher；`mysqladmin ping -h 127.0.0.1 -P 3306 -u root --silent`
  輸出 `mysqld is alive`，TCP 查詢輸出 `LISTEN=127.0.0.1:3306 PID=7308`。
- 第一次 Windows production runner 使用不存在的 `bundle.cmd`；PowerShell 的非終止錯誤沿用了
  前一個成功命令的退出碼，錯把 Rails 測試標成 exit 0。該結果已明確作廢，沒有用於完成性聲明。
- 改用 `Get-Command bundle` 實際取得的 `bundle.bat`，並把 runner 改成命令錯誤立即停止。
  Windows 下 `bin/setup` 直接呼叫 extensionless `bin/rails` 會回 `Errno::ENOEXEC`，因此依其
  檔內順序逐項執行等價命令：`bundle check`、`pnpm install --frozen-lockfile`、
  `ruby bin/rails db:prepare`、`ruby bin/rails log:clear tmp:clear`，退出碼均為 0。
- 以 `bundle.bat exec rspec` 重跑 Rails specs，實跑輸出為 `284 examples, 0 failures`；style、
  gem audit、frontend audit、Brakeman、frontend test／typecheck／build 與純文檔 scripts 閘門在
  本步取得的各自輸出均為 exit 0。原型 lint 快照為 `ERROR 0 / WARN 136`。
