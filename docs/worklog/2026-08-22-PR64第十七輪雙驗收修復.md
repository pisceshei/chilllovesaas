- 🔴 **窗口掃描：本輪重跑一次，只留這一份輸出**（Codex `3835660390` 指出第十六輪同一段裡
  放了兩個不同時間點的輸出）。完整指令：

  ```sh
  # 命中集合＝docs 全樹 ＋ 本輪新檔 ＋ PR 描述
  { git -c core.quotepath=false grep -nE '\bth=[0-9]' -- docs
    grep -nE '\bth=[0-9]' <本檔>      | sed 's|^|<本檔>:|'
    grep -nE '\bth=[0-9]' <PR描述落檔> | sed 's|^|<PR描述落檔>:|'
  } | while IFS= read -r line; do
      f=${line%%:*}; n=$(printf '%s' "$line" | cut -d: -f2)
      ctx=$(sed -n "$((n>W?n-W:1)),$((n+W))p" "$f")
      fm=$(printf '%s' "$ctx" | grep -c '<th.b')                       # 有沒有計數式
      an=$(printf '%s' "$ctx" | grep -cE '82e2fa8|53d346b|終態樹')      # 有沒有錨定
      # 兩者皆 ≥1 ⇒ PASS；第三輪 worklog（歷史層、本輪未被點名）⇒ EXEMPT
    done
  ```

  一次跑完的四個窗口（**同一份資料、同一個樹**）：

  ```
  窗口 ±5    PASS= 9  FAIL=4  EXEMPT=2   總計 15
  窗口 ±8    PASS=12  FAIL=1  EXEMPT=2   總計 15
  窗口 ±12   PASS=13  FAIL=0  EXEMPT=2   總計 15
  窗口 ±16   PASS=13  FAIL=0  EXEMPT=2   總計 15
  ```

  ⇒ **±12 是「零誤判」的最小窗口**（±16 沒有再多救到任何一處，撐大它沒有收益）。
  兩條 EXEMPT 都在 `2026-08-21-PR64第三輪雙驗收修復.md`：歷史層、無錨定 commit、
  依 19.5 不得就地補，且本輪無人點名 ⇒ 依「只修點名的」不動（已入 Pending）。
