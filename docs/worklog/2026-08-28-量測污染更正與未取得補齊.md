# 2026-08-28 · 量測環境污染更正與「未取得」補齊

## 已完成的工作 (Done)

### 1. 🔴 發現並更正一個污染了全部字重量測的環境問題

使用者 Chrome 的一個擴充功能在 `<style id="font-bolder-style">`（`parentNode` 是 `HTML`）
注入 `body, body :not(svg):not(svg *):not(img):not(video):not(canvas) { font-weight: 500 !important }`。

- **雙向改寫**：固定值 500 加 `!important` ⇒ 把 450 **拉高**、把 550 **壓低**
  ⇒ **看到 500 無法回推真值，只能重量**。
- 🔴 **shadow DOM 不是無條件免疫**（發布前複核抓到的二次更正）：選擇器確實停在 shadow 邊界，
  **但 `font-weight` 是可繼承屬性** ⇒ shadow 內**未自宣告**它的繪製盒會沿 flattened tree
  繼承宿主被打成 500 的值。判準是「**該元素自己有沒有宣告 `font-weight`**」。
  反例：`s-internal-button` 的 `.button.variant-plain`（乾淨 450／污染 500）、
  `s-button` 的「Remove schedule」`SPAN.text-wrapper`（同）——**兩者都在 shadow 內**。
  ⇒ **任何「在 shadow 內所以不用重量」的判斷都不成立**。
- **只影響 font-weight**：font-size／line-height／color／letter-spacing／font-family
  在兩種環境下逐項相同（已逐項複驗）。

**逐項更正 118 條**，分落五個檔的更正節：
`21` §5.6（22）／`77` §7.6（31）／`81` §8.6（29）／`82` §16.6（7）／`113` §1.6（29）。
方法論主文＝`docs/design/111` §20。

### 2. 撤回一個由污染造出來的結論

`111` §7 原本宣稱「token 值域沒有 500，但實際 computed 有 483 個 500 ⇒ token 值 ≠ computed 值」。
**那個落差是污染造成的。** 乾淨直方圖（商品詳情頁 1335 個葉節點）：
`450×981 / 550×187 / 600×4 / 400×13`，**一個 500 都沒有**，完全落在 token 值域內。
⇒ 結論撤回，原文依鐵律 19.5 保留並加更正註。

同批修正 `111` §16（`body` 500→450、導航項改記繪製層）與 §17.1（兩層對照表的「500」欄）。

### 3. 發現第二類與污染獨立的錯誤：量錯層

記到的是**不繪製文字的包裹元素**，而非實際繪製文字的元素：

| 例 | 包裹層（原記載） | 實際繪製文字的元素 |
|---|---|---|
| 側欄導航項 | `<a>` 13px/450（純繼承） | `<span>` 13px/**550**；作用中 **600** |
| 側欄分組標題 | host `s-internal-text` 13.3333px/400（`display: contents`，**不產生繪製盒**） | shadow 內 `<strong>` 12px/**550** |
| 側欄徽章數字 | host `s-internal-badge` 13px/500 | shadow 內 `<span.number>` 12px/**600** |

🔴 原記載那個單一的「500」**同時掩蓋了包裹層與繪製層兩個不同的值**。

### 4. 解掉 `112` 的一個換值阻塞

我方 `--fw-xs`／`--fw-md`／`--fw-xl`／`--fw-control` 四個 `500` 原本標「待裁定」，
現依乾淨量測定案：**450／450／600／550**。

### 6. 1280 桌機寬：改走樣式表窮舉

🔴 **先前登記的原因是錯的**。原記「量測機實體螢幕 1024×768」——實測 `screen` 是 **2560×1440**。
真正的原因是瀏覽器視窗被放在 `screenX ≈ -32000` **離屏**、渲染面**凍結**：

| 請求寬度 | 實得 `innerWidth` |
|---|---|
| 700 | 945 |
| 1280 | 945 |
| 1500 | 945 |
| 2400 | 945 |

`resize_window` **每次都回報 "Successfully resized"**——工具層的假成功。

⇒ 改用**樣式表窮舉**（90–162 份全部同源可讀、0 份被擋）：
**72 個帶寬度的 `@media` 條件**、33 個門檻。≥1024 者＝
`65em`(1040) **58 條**／`75em`(1200) **16 條**／`90em`(1440) **43 條**／`100.5em`(1608) 1 條。

🔴 **另有一條寬度軸先前完全漏掉**：全站 **90 條 `@container` 規則、33 個相異條件**，
幾乎全用 px。視口變寬時它們會**跟著容器寬另外翻一批**，與 media query 無關。
