## 已完成的工作 (Done)

### 1. 🔴 A6b：`decimal_places < 2` 的 pack 不得 enable

**缺口**：A6 原本只擋位數**上限**（`> 2` ＝ 精度謊報）。宣告 `0` 或 `1` **是合法 pack**，
而 `to_psp_decimal` 走 `Money.fixed_string(major, pack.decimal_places)`，
內部 `value.round(digits)` **靜默四捨五入**。

**實跑驗證**（不是推理）：

| pack 宣告 | 帳上（儲存 cents） | 送出 | 差額 |
|---|---|---|---|
| `decimal_places: 1` | HKD 14.85（`1485`） | `"14.9"` | **0.05，沒有任何一張表記得住** |
| `decimal_places: 0` | HKD 1480.00（`148000`） | `"1480.0"` | 格式連自己宣告的 0 位都不符 |

🔴 **三件事讓它特別難發現**：
1. **與 `minor_units` 側不對稱**——那側有 A3 的餘數 `raise` 順手擋住，`decimal_string` 側**沒有等價物**；
2. **在 HKD 這個基準法域上就會發生**，不像 A1／A2 只在 zero-decimal 幣別現形；
3. **§H 矩陣證明不了它**——矩陣裡每個 pack 都宣告 2 位，那條路從沒被走過。

**修法**：`limits.yml` 增 `psp_decimal_min_places: 2`；`validate_decimal_string!` 一併 reject `< min`。

**為什麼不補齊 sub-2 位語義**：要「支援」就得先發明湊整規則
（誰決定進位方向？差額記到哪張表？）——65 §D.4 四家實證表裡沒有一家這樣要求，
本規格全篇無出處可依 ⇒ 憑空造規則，而且很可能第一次接真 PSP 就是錯的。
fail-closed 的代價是「真出現時第一次呼叫就 raise」＝**看得見**的失敗。

### 2. 🔴 配套：`Money.fixed_string` 的 `digits = 0` 格式 bug

`"0".rjust(0, "0")` 回 `"0"`，而小數點是無條件接上去的 ⇒ `fixed_string(1480, 0)` 輸出 `"1480.0"`。
**連它自己 `@return` 的「定位數」契約都不符。**

🔴 **分層刻意如此**：格式化器管「怎麼 render」（對任意 `digits` 都要正確），
政策層（A6／A6b）管「准不准 render」。把政策塞進格式化器會讓
`Money::Decimal`（恆 2 位、與 PSP 無關）也被 PSP 規則綁住。
另加 `digits` 為負 ⇒ `ArgumentError`。

### 3. 🟡（採納）`Money::Storage#<=>` 落在 private，且對非 `Storage` 會 raise

驗收只說「`a <=> b` 會 NoMethodError」，**實測發現更嚴重的那一半**：

```
a <=> b   => 🔴 NoMethodError: private method '<=>'
a == nil  => 🔴 TypeError: 只能與 Money::Storage 比較，實得 NilClass
a == 100  => 🔴 TypeError
```

🔴 `==` 回 false 是 Ruby **全域約定**——`Array#include?`／`uniq`／`-`／`Hash` 查找全靠它。
一個會拋例外的 `==` 會在**完全無關的地方**炸開，堆疊還指向 `money.rb`。

**修法**：型別不同 ⇒ `<=>` 回 `nil`（Ruby 慣例，`1 <=> "a"` 就是 `nil`）
⇒ `==` 回 `false`、`<` 得到 `ArgumentError`；**幣別不同仍然 raise `CurrencyMismatch`**
（那是本專案刻意加嚴的那條，不是型別問題）。並 `public :<=>`。

⚠️ **為什麼既有測試抓不到**：它們只用 `a < b`——而 `Comparable#<` 是**內部**呼叫 `<=>`，
**不受 private 限制** ⇒ 測試全綠，但直接呼叫 `<=>` 是壞的。

## 這次掃描學到的（比逐條修更有價值）

🔴 **四種形態，每一種本專案都真的發生過**：
1. `@raise` 寫了 A，實際拋 B 或根本不拋；
2. 註釋描述了一個代碼沒有的分支（`1480.0` 與 `1480` 同指紋）；
3. 方法被 `private` 遮住，註釋卻當它是 public 在描述；
4. 引用的規格章節／行號／檔名與實際不符（本輪**我自己就寫錯兩處**）。

⚠️ **第 3 種最難靠測試發現**：`Comparable`／`Enumerable` 這類 mixin 的**內部**呼叫
**不受 private 限制** ⇒ 測試用 `a < b` 會綠，而使用者呼叫 `a <=> b` 會炸。
**「測試綠」證明不了「public 可用」。**

🔴 **第 4 種的根因是「寫註釋時憑印象引用」**。本輪我在同一個 commit 裡
新增了 `65` §D.5 卻在兩個地方引成 §D.4——**因為我寫註釋時 §D.5 還沒寫完**。
⇒ **引用要在該章節定稿後回頭核一次**，或者乾脆引章節標題而不是編號。
