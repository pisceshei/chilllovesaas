# 2026-08-27 — S6a-2：`purchasable`／`discoverable` 出到 GraphQL，前端不再硬算

> 承接 S6a（PR #156，main `6c54f3d`）；補的是 S6 盤點列出的 GraphQL 缺口第一條。

## 已完成的工作 (Done)

### 1. 為什麼要補這個欄位

S6a 把 publication 資料送進前端之後，`ProductDetailPage.tsx` 那張硬編的
`STATUS_DIMENSIONS`（只看 status 算兩維）的**禁令從「沒得違反」變成「活的」**——
它的註釋逐字寫著「前端沒有 publication 資料，硬算出來的第二個答案遲早與伺服器分岔，
而分岔的症狀是後台說可購買、前台買不到」。⇒ 改由伺服器欄位提供判準
（複驗：`grep -n "STATUS_DIMENSIONS" app/frontend/admin/pages/ProductDetailPage.tsx`
——應只剩 fallback 用途的定義與一處引用）。

### 2. 🔴 判準完全復用 scope，不新增第三份實作

`Types::ProductType#purchasable` / `#discoverable` 只做兩件事：解析 publication、
把 `Product.purchasable` / `.discoverable` 這兩個既有 scope 套到這一列上
（`scope_method.call(publication:).where(id: object.id).exists?`）。

**沒有任何 Ruby 版的狀態比較。** 理由：`docs/specs/91` 已登記過同型事故
（「同一條『已發布』規則有兩份實作：`ResourcePublication#published?` 與
`Product.published_on`」），本欄位若自己算就是**第三份**；而
`discoverable ⊆ purchasable` 在 model 層是**由 purchasable 導出的定理**，
繞過 scope 會讓它退化成「要靠測試盯著別漂移」的性質。

GID 解析復用 `Publications::Lookup`——理由是**不再新增第四份 GID parser**
（倉庫沒有共用 parser，各線各寫一份 regex，該檔檔頭已登記此事）。

### 3. 🔴 突變抓到我自己的一句過度宣稱

我原本在註釋寫「復用 `Publications::Lookup`（它同時做**租戶隔離**）」。
M4 突變（把該行換成裸 `Publication.find_by`）**跨租戶那格 spec 仍然綠**
⇒ 本路徑的租戶保護實際上來自 `acts_as_tenant` 的預設 scope（請求期
`Current.shop` 已設），不是 `Lookup`。`Lookup` 的顯式 `with_tenant` 是**第二層**，
只在 `without_tenant` 情境下才是該路徑上僅存的那一道，而本路徑不在那種情境裡。
⇒ 註釋已改寫成精確版本，並註明現有 spec **未涵蓋**那一層。

### 4. 前端：伺服器答案優先，三種情形退回狀態層

`STATUS_DIMENSIONS` **不刪**，但角色降級為 fallback，只剩兩個用途：
①建立態（伺服器上還不存在，問不到）②編輯態下使用者剛改了狀態下拉**尚未儲存**
（伺服器答的是**已儲存**的狀態，此時顯示它會與畫面上的下拉矛盾）。

### 6. 🔴 全套 rspec 抓到一條結構性規則違反（本包引入）

`spec/graphql/mutation_context_shop_spec.rb` 有兩道守衛：靜態掃描
（`app/graphql` 下不得出現 `Current.shop`）＋直呼冒煙。**本包第一版踩到了它。**

字面上是我在**註釋**裡寫了 `Current.shop` 四個字（掃描是純文字比對），
但它暴露的是一個**真問題**：第一版的 `Publication.online_store`（無參數）
靠 `acts_as_tenant` 的**隱式租戶** ⇒ request spec 全綠，而直呼
`ChillloveSchema.execute` 時查不到管道、兩維**靜默回 false**。
那正是第 25 包線上驗收抓到的形態。

⇒ 改為 `shop = context.fetch(:current_shop)`，`online_store` 包在
`ActsAsTenant.with_tenant(shop)` 內；`Lookup` 也改傳這個 shop。

### 7. M7：一個**預期內**沒轉紅的突變

新增「直呼 schema」冒煙格後，我先在測試註釋裡自我界定：
「這一格證明本欄位在無 controller 情境可執行，**不**證明租戶取自 context
——`with_tenant` 兩者都滿足；後者由靜態掃描那一格負責」。

M7（把租戶改回隱式 `ActsAsTenant.current_tenant`）**果然沒轉紅** ⇒
**突變證實了那句自我界定是準確的**，不是漏測。

⚠️ 但由此登記一個**既有守衛的射程缺口**：靜態掃描只抓字面 `Current.shop`，
**抓不到「靠 `acts_as_tenant` 隱式租戶」這種寫法**。擴張該守衛屬 `scripts/`／
既有 spec 的範圍（鐵律 20.5 不在本包擴修），登記待裁定。
