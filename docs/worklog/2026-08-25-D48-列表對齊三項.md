### ① 檔案庫排序

本尊 Files 頁可依 **Date added／File name／Size** 排序，各可升降
（help 逐字 "By default, files are listed from newest to oldest based on the date
that they were uploaded."，取證 2026-08-25）。

- `Types::FileSortKeysEnum`（CREATED_AT／FILENAME／ORIGINAL_UPLOAD_SIZE）。
  🔴 **成員名是 ours**：官方 `FileSortKeys` 的完整值域**未取得**（query reference
  只回了預設值 `ID`）⇒ 三個名字取自官方 `files` query 的**篩選識別字**
  （`created_at`／`filename`／`original_upload_size`，同一份文檔明列），
  至少不是憑空造字。查到官方值域後回頭對齊，不得寫成「照抄本尊」。
- `files(sortKey:, reverse:)`；`KeysetCursor::ORDER_KEYS` 新增兩個 codec。
  🔴 **字串鍵的 load 必須自己驗型別**：`Integer(raw)` 遇到 `"abc"` 會 raise
  ⇒ position／byte_size 天然 fail-closed；字串沒有這個保護，
  `JSON.parse('[123, 5]')` 會給你一個 Integer 當 filename，
  而 `WHERE filename > 123` 在 MySQL 是**隱式轉型不是錯誤**——那是一整頁錯資料
  而不是一個錯誤訊息。已加 `raise ArgumentError unless raw.is_a?(String)`，
  並做突變驗證（拿掉守衛 ⇒ 該例從 BAD_USER_INPUT 變 nil 轉紅）。
- 🔴 **預設方向依鍵而異**，不是一律 desc：日期預設新到舊（本尊逐字），
  但檔名與大小預設由小到大才符合直覺——檔名 desc 開頭是 z，沒有人期待那個。
  `reverse` 反轉的是「該鍵的預設方向」。
- migration `ix_files_byte_size`。🔴 只有 `byte_size` 需要加索引，`filename` 不用：
  keyset 條件是 `(排序鍵, id)` 的字典序，`ix_files_filename (shop_id, filename)`
  的 InnoDB 二級索引**隱含帶主鍵**，等效 `(shop_id, filename, id)`，剛好夠用。

### 🔴 critical：`PRODUCTS_QUERY` 少了 `$after`（載入更多永遠重取第一頁）

我改 `fetchProducts` 時把 `after` 放進 variables，卻**沒改查詢文件**——
那次字串取代的錨點寫錯（文件叫 `ProductsIndex` 不是 `productsList`），
而我沒加 assert，所以它**靜默沒命中**。GraphQL 規格只認 operation 宣告過的變數，
未宣告的一律丟掉 ⇒ 每次「載入更多」都送 `after: null`、把第一頁再接一次。

回歸測試連**查詢文件**一起驗（只驗 variables 抓不到它），並做突變驗證：
把文件改回沒有 `$after` ⇒ 該例轉紅。

🔴 **教訓**：字串取代一律加 `assert s.count(old) == 1`。本輪其他十幾處都加了，
漏的這一處正好是出事的那一處（本輪取代點複驗：`git show --stat HEAD`）。

### `useCursorPagination` 的旗標：我先修出一個新缺陷，再被審查抓回來

- 第一版：`loadingMore` 的清除**帶世代守衛** ⇒ loadMore 途中改篩選會讓旗標卡在 true，
  按鈕永遠 disabled。發現後改成**無條件清**。
- 審查抓到：無條件清會讓**過期世代**那筆（它的 controller 沒人 abort，一定跑完）
  清掉**現行世代**的 in-flight 旗標 ⇒ 防重入失效 ⇒ 同一個 endCursor 送兩次 ⇒
  同一頁 append 兩次。
- 終版：**守衛恢復 ∧ 第一頁 effect 一併重置**。兩件事各有各的機制——
  守衛擋跨世代污染，effect 重置解卡住。合成一個就會壞掉一邊。
