# A-1：撤銷款項 vs 實體退貨的概念邊界（84 §1 A-1／R11-V14 結案）

## 已完成的工作 (Done)

- **🔴 釐清了一個容易讀反的事實**：官方 2026-03-05 把指標欄 `returns` 改名為 `sales_reversals`，
  直覺是「returns 沒了」——**錯**。真相是**拆概念**：舊的 `returns` **指標**改名，
  而 `returns` 這個**詞**被重新指派給**實體退貨資源**，並同批新增 `returned_quantity`、
  `return_line_item_reason` 等專屬欄位。官方 changelog 的理由逐字寫著：新欄名是為了釐清
  「broad order adjustments (sales reversals)」與「physical returns」的差別。
- **`docs/specs/86` 落檔**：概念邊界（§1）、官方 11 組欄名對照（§2）、
  我方命名規則與聚合定義（§3）、對既有規格的修訂（§4）、M1/M3/M4/M5 各該做什麼（§5）。
- **🔴 發現並修正 19 號主公式的兩個錯**：
  - `Total sales = Σ(訂單總計) − Σ(退款) −（取消單全額）` **漏了訂單編輯**——
    19 §F1.1 自己補了這一項，但**主公式沒同步**，只讀主公式的人會漏掉；
    且用「退款」當被減項名稱，但退款只是撤銷款項**四個來源之一**。
  - `AOV = Total sales / Orders` **是錯的**——本尊的 AOV 分子刻意排除 post-order adjustments
    （§A G25 已裁定照抄此例外），`AOV ≠ net_sales / orders`。
- **🔴 定義了官方沒給的東西並明說是我方定義**：`sales_reversals` 的**加總公式官方文檔未載**
  （只給列舉式定義）。86 §3.2 寫出我方定義，並標明這是我方定義而非照抄。
  其中最關鍵的一條：**實體退貨不獨立計入金額**——伴隨退款者已由退款計入，
  換貨（無退款）金額淨影響為零。**把退貨也加進金額聚合會雙重扣除。**
- **`reversed_quantity` vs `returned_quantity` 是兩個數**：前者是任何原因移除的件數，
  後者是實際被寄回的件數。換貨情境下 `returned_quantity=1` 但 `sales_reversals=0`。
- **CI 新增 `check-reversal-naming.rb`**（與 G24 的做法一致——把契約變成機制）：
  規則 1 擋官方已移除的 11 個舊指標欄名；規則 2 擋以聚合指標命名的資源表。
  正反皆測（塞 `net_returns` 欄 → exit 1；把表命名為 `sales_reversals` → exit 1）。
- **驗證**：rspec 52/52；quality 八個步驟本機全過（rubocop／brakeman／bundler-audit／
  pnpm audit／prototype lint／tenant isolation／reversal naming 皆 exit 0）。
