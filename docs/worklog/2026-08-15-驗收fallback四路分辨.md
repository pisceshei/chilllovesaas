# 2026-08-15 — 驗收失敗訊息：把「取不到」拆成四種原因，並擋住缺欄位的 null 垃圾

> 來源：多代理驗收的 **Y7／Y8**，兩條複驗成立。

---

## 已完成的工作 (Done)

### 1. 🔴 Y7：四條路徑被收斂成一句假歸因

`REVIEW_OUTCOME != success` 分支在撈不到診斷時，一律印
「（取不到 execution_file，請用下方指令自行撈 result payload）」。

實測（jq 1.8.2，逐一構造輸入）證實**四條完全不同的路徑印同一句**：

| 情境 | 檔案在不在 | 舊訊息 |
|---|---|---|
| env 空 | — | 「取不到 execution_file」 |
| 檔不存在 | ✗ | 同上 |
| **檔在、可解析，但沒有 `type=="result"` 物件** | ✓ | 同上 ← **假歸因** |
| **檔在但 JSON 截斷** | ✓ | 同上 ← **假歸因** |

🔴 後兩者**檔案明明在**，訊息卻說「取不到 execution_file」。
更糟的是：那句話就印在一段**承認第三種路徑存在**的註釋下面幾行
（「`select(. != null)` 讓『找不到 result』落空成空字串，才會走下面的 fallback」）
——**註釋與它自己產生的訊息互相矛盾**。

🔴 這正是本分支上一輪（PR #36）才修掉的錯誤形態（寫死的猜測當診斷），換個位置又犯一次。

**對照組**：姊妹分支（「成功但沒貼留言」的回收品）有 `tail -c 20000` 的 fallback，
所以**它**那句「execution_file 為空或不存在」是可信的。失敗分支缺的就是這道分辨。

**修法**：四種各報各的，jq 的 stderr 收進訊息而不是 `2>/dev/null` 丟掉，並附檔案大小。

### 2. 🔴 Y8：欄位被改名時輸出「看起來像資料的 null 垃圾」

`select(. != null)` 只擋**整個 result 物件不存在**，擋不住**欄位被上游改名**
⇒ 會印出 `is_error=true num_turns=null total_cost_usd=null duration_ms=null`。
那一行**對不上判準表的任何一列**，而讀的人會拿它去對號入座。

**修法**：jq 內定義 `def g(k): if has(k) then (.[k] | tostring) else "缺欄位" end;`。

🔴 **不能用 `// "缺欄位"`**：jq 的 `//` 對 **`false`** 也會取右邊，
而 `is_error: false` 是**完全正常的值** ⇒ 會被誤報成缺欄位。
（這個坑在寫的時候差點踩進去，是靠 `is_error_false` 那條測試案例擋下來的。）

### 3. 自測：七種輸入形態

| 輸入 | 輸出 |
|---|---|
| 正常 JSONL | `is_error=true num_turns=1 total_cost_usd=0 duration_ms=654` |
| **`is_error: false`** | `is_error=false ...` ✅ 沒被誤報成缺欄位 |
| 欄位被改名 | `is_error=true num_turns=缺欄位 ...` ✅ 不是 null |
| 檔在但無 result | 「檔在（35 bytes）且可解析，但裡面**沒有 result 物件**」 |
| JSON 截斷 | 「檔在（28 bytes）但 **jq 解析失敗**：jq: parse error: Unfinished JSON term...」 |
| 檔不存在 | 「execution_file 指向 <路徑>，但該檔不存在」 |
| env 空 | 「action 沒有輸出 execution_file——步驟可能在產生它之前就失敗了」 |

另：`YAML.load_file` 通過；抽出 run 腳本 `bash -n` 通過。

## 尚未完成或需注意的風險 (Pending / TODO)

   驗證機會是**合併後開的第一個 PR**，而且要那次驗收剛好失敗才看得到這段訊息。
   ⇒ 本輪的七種輸入實測是**離線**跑的（抽出 shell 片段 ＋ stub `gh`），
   那是目前唯一可行的驗證方式。

2. ⚠️ **這段 shell 沒有 fixture 回歸測試**。本輪的七種輸入是手動構造的，
   沒有固化成 CI 會重跑的東西 ⇒ 日後改壞不會有人知道。
   （PR #42 的 `check-workflow-syntax.rb` 只驗語法，抓不到這類邏輯退化。）
   要補的話正解是把這段抽成 `scripts/` 下的腳本 ＋ fixture——
   **與 PR #41 對執行位元閘門做的事同型**，但那要動更大的結構，本輪沒做。

3. ⚠️ **`mktemp` 與 `wc -c` 的可用性**沒有特別防護。GitHub runner 上都在，
   但若 `mktemp` 失敗，`JQ_ERR` 會是空字串 ⇒ `2>""` 會出錯。
   實務上不會發生，但這是本輪已知未處理的邊界。

4. ⚠️ **判準表本身仍是斷言**（`num_turns`／`total_cost_usd` 的語義若被 action 改掉就要重驗）。
