## 🔴 本輪最重要的四個發現

### A. 本尊有兩套設計系統世代並存於同一畫面

新的 `s-*` web component 層與舊的 Polaris React 層同時在跑，**同名元件在兩層值不同**：
heading 13/600 vs 14/500、按鈕標籤 12/550 vs 13/500、modal 遮罩 `#000000b5` vs
`rgba(0,0,0,.5)`、按鈕 transition `none` vs `all`。

⇒ **這解釋了為什麼 `47` 與 `64` 本來就互相矛盾**（47 §6.5 記按鈕 12/16/550、
64 §3 記 13/20/500）——**兩邊都對，量的是不同層**。我方只取新層。

### B. token 值 ≠ 實際 computed 值

`--p-font-weight-*` 的值域是 450/550/600/650（**沒有 500**），
但全站 deep 掃描的 computed 直方圖有 **483 個元素是 500**，`body` 自身就是 500。
⇒ **不能只照 token 表填**；500 的來源規則未查明，已登記。

### C. 🔴 `47` §A 的「封閉 Shadow DOM 是一道硬牆」是錯的

`47` §A 記載 `s-internal-*` 宿主的 `shadowRoot` 為 `null`（closed mode）、
「按鈕與徽章的內部樣式**無法由 JS 讀取**」，並據此把 §D 整節改用**高倍率截圖目視判讀**。

**實測全部是 open**——`s-internal-button`／`-badge`／`-text-field`／`-tooltip`／`s-banner`
的 `shadowRoot` 皆可直接 `querySelector` 後 `getComputedStyle`。宿主的
`getBoundingClientRect()` 是 0×0 沒錯，但那是因為**繪製盒在 shadow 內**，不是讀不到。

⇒ **`47` §D 全部數值都是在錯誤前提下目視得到的**，逐項待複核。
其中「次級按鈕配方」已證實有誤：47 §6.5 記「白底＋底緣內陰影＋外投影」，
直接量測是 **`#e3e3e3`、`box-shadow: none`、`border: 0`**（三個獨立樣本一致）。
🔴 **錯誤來源已定位**：47 記的兩層陰影**逐項等於 `--p-shadow-button` 這個 token 的值**
（`0 -1px 0 0 #b5b5b5 inset` 完全吻合；第二層的 `rgba(0,0,0,.1)` 就是 `#0000001a`），
只是 47 把 inset 記成了 drop ⇒ **當時讀到的是 token 表的值，而該 token 並未套用在
`variant=secondary` 的繪製盒上**。同檔 §D 的表（「淺灰實心」）反而是對的。

### D. 本尊自身有不一致，不能照抄

- 同一個 popover 裡日期欄用 inset shadow 當邊框、時間欄用真 border
- 焦點環**不是全域一致**：設定區導覽項是瀏覽器預設 `outline auto 1px`，只有表單控件才有 `#005bd3`
- 設定區導覽的 **hover 比 selected 深**，且 token 名與用途對調
  （`-selected` token 用在 hover、`-active` token 用在 selected）——照 token 名直覺實作會做反
