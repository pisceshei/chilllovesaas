> ⚠️ **本檔為第一版基準，數字凍結不再更新。** 修完幾輪後的重跑結果在 **`docs/specs/53-ui-gap-recheck.md`**（同一套 grep／python 方法 ＋ Chromium 實跑）。摘要：缺口 205 → 162；P0 22 條中已解決 8／部分 4／未解決 10；另發現 7 項回歸風險與 11 條新缺口。本檔已知的兩處量測誤差見 53 號 §8 的 X-08、X-09。
>
> **目的**：把「實測看到了、但原型或契約沒有」與「契約寫了、但原型沒實作」的每一個缺口列成可勾銷的清單。**寧可多報，不可漏報。**
>
> **比對來源**
> | 代號 | 檔案 | 行數 |
> |---|---|---|
> | **44** | `docs/research/44-live-shopify-teardown-2026-08.md` | 909 |

>
> **方法**：以 `grep` / `python re` 對三份原型做機械掃描——抽出 44 的全部 `##`/`###` 標題與內文行為描述當清單；抽出原型的 CSS 選擇器表、`data-doc` 註釋鍵、路由表（`MODULES` / `DETAILS` / `SET_PAGES` / `ROUTES`）、九態選擇器與 ARIA 屬性計數，逐一交叉核對。
>
> **證據格式**：`檔案:行號` 或 CSS 選擇器。查無命中一律寫「**grep 無命中**」，不寫「應該有」。
>
> **狀態定義**
> - **已實作** = 有可點擊的真實視圖，內容與 44 記錄大致對得上
> - **佔位** = 視圖存在，但只是靜態摘要列 / `toast()` 存根 / 缺關鍵結構
> - **完全缺** = 三份原型都沒有任何對應錨點
>
> **重要前提（影響全表判讀）**：三份原型**完全不使用 48 的 `cl-` 前綴命名**（`grep "cl-btn\|cl-input\|cl-badge\|cl-card\|cl-modal"` → A/P/S 皆 0 命中）。48 是原型**之後**寫的目標契約，因此表 2 的比對一律以「功能等價的既有選擇器」為準（`.btn`↔`cl-btn`、`.badge`↔`cl-badge`…），命名差異本身另列為 P1（見 §5 彙總 F-01）。
