🔴 **#13 追出一個比原始發現更深的根因**：原始發現只說「Cookie 橫幅的 radio 沒有 `data-f`」。
補上 `data-f` 之後 save bar **仍然不跳**——因為 `formRead()` 對非 checkbox 一律讀 `.value`，
而 **radio 的 `.value` 是固定的，變的是 `.checked`**。
⇒ **任何帶 `data-f` 的 radio 在髒狀態追蹤裡都是隱形的**，這不是某一頁的問題，
是機制本身漏接這個型別。已修 `formRead()` 與 `formDiscard()` 同時支援 radio。

實測完整循環：進入無 save bar → 改顏色 → save bar 跳出 → 捨棄 → **收起且還原為「淺色」**
→ 改位置 → 跳出 → 捨棄 → 還原為「底部置中」。

### §6.2 `lcolumns` 修復（17 個清單頁共用）

原本：checkbox 一律 `checked`、**無 onchange**、`c.cols` 不回寫，按「套用」卻 toast
「Demo：欄位設定已存回目前檢視」。🔴 **假成功訊息比「沒反應」更糟**——沒反應時使用者知道要回報，
回報成功時使用者以為設定生效了，之後看到的每一張表都在騙他。

修法：`lstate()` 加 `hidden`（Set，存 **`cfg.cols` 的原始索引**）；thead／tbody／colspan 三處同步跳過；
`lcolumnsApply()` 真的回寫並 `lrender()`，toast 回報實際欄數。

🔴 **兩個容易寫錯的點，實測都驗過**：

| 點 | 為什麼會錯 | 實測 |
|---|---|---|
| 用 `map`→空字串而**不是 `filter`** | `filter` 會重排索引，但 `lsort(key,i)` 與 `s.sort` 用的是**原始索引** ⇒ 隱藏一欄後排序會錯位到別欄 | 隱藏索引 1、2 後，其餘表頭 onclick 仍是 `0/3/4/5`，排序箭頭仍在「消費金額」 |
| 隱藏「正在排序的那一欄」要取消排序 | 否則會出現「看不到的欄在決定順序」 | 隱藏索引 4 後 `s.sort` → `-1`，`th.sorted` 數 → 0 |

🔴 **第三個點（PR #27 的 Codex review 補抓）：隱藏欄是逐檢視的，不是逐清單**。
`41` §1.3 逐字「欄位設定存在檢視上、不影響其他檢視」，modal 的說明文字也這樣寫，
但第一版存成 `s.hidden`（掛在 `LS[k]` 上）⇒ 在「全部」檢視隱藏兩欄，切到「已訂閱」
那兩欄也不見了——**與畫面上自己寫的說明相反**。改為 `s.hiddenByView[view]`。
實測：檢視 0 隱藏 `[1,2]`、檢視 1 隱藏 `[5]`，互切互不影響，狀態為 `{"0":[1,2],"1":[5]}`。

另：全部取消勾選被擋（不能有零欄的表）＋警告可見；重開設定 modal 記住勾選狀態；
表頭數 ＋ bulk 欄 ＝ 每列 td 數（7→5→7）。

🔴 **驗證時踩到的坑**：瀏覽器會拿**快取的舊版**——渲染出來的還是沒有新 class 的舊碼，
看起來像「改了沒效」。必須 `location.reload(true)` 後再測。
